# [2026-09-25] 移除环境变量修改密码机制，残留变量仅警告

> 本文件为独立变更日志，记录移除「环境变量重置 Dashboard 密码」机制（`LDMBOT_RESET_DASHBOARD_PASSWORD` / `LDMBOT_DASHBOARD_INITIAL_PASSWORD`）的背景、范围与新行为。

---

## 问题现象

原机制：启动时若检测到 `LDMBOT_RESET_DASHBOARD_PASSWORD=1`，就把 Dashboard 密码重置为 `LDMBOT_DASHBOARD_INITIAL_PASSWORD`（未设则默认 `ldm`）。实际使用暴露两个问题：

1. **写进 .env 后每次启动都生效**：该变量不像启动参数那样「用一次就完」，.env 每次启动都会把它加载进环境，密码被反复重置回默认，用户设的密码永远保不住。
2. **语义混乱**：`INITIAL_PASSWORD` 除了配合 RESET 标志，还会影响启动期的另外两条密码自愈再生分支；环境变量、启动再生分支、CLI 参数三套入口交织，行为难以推理。

## 移除内容

- `astrbot/core/config/astrbot_config.py`：删除 RESET 标志消费逻辑（`_consume_reset_dashboard_password_flag`）与 `INITIAL_PASSWORD` 解析（`_resolve_initial_dashboard_password`），启动分支链中对应分支移除；`_reset_generated_dashboard_password` 改为直接使用 `generate_dashboard_password()`（固定默认 `ldm`）。
- `astrbot/cli/commands/cmd_init.py`：删除 `astrbot init` 时读取 `INITIAL_PASSWORD` 预生成 `cmd_config.json` 的钩子，`init` 回归「只建目录、首次 run 时标准自愈」。
- `astrbot/utils/env_file.py` 模板与 `main.py --help`：删除两个变量的条目。
- 根目录 `.env` / `.env.example`：清理残留的注释行。

## 新行为

两个变量完全失效。启动时若检测到残留的非空值，打警告日志，**分两个阶段各提示一次**：配置加载期一次、WebUI 就绪横幅（✨ 显示框）打出后一次——第一次容易被启动过程的大量日志刷屏淹没，第二次保证用户能看到。同一阶段只提示一次，配置对象多次实例化（如各插件配置）不重复。文案以「例如」给出修改命令示意（解释器 + 脚本 + `--reset-password`，按当前进程的启动方式拼装，与 `about_info._startup_command` 口径一致；受 venv 激活方式、cwd、脚本类型影响，未必可直接照抄执行）：

```
检测到已废弃的环境变量 LDMBOT_RESET_DASHBOARD_PASSWORD：为避免混乱，已禁止通过环境变量修改密码，请通过启动参数修改，例如：D:\ldmbot\.venv\Scripts\python.exe main.py --reset-password
```

密码修改从此只有 `--reset-password` / `--reset-passwd` / `--重置密码` 一个入口（见同日「密码重置命令增强」一篇）。

## 部署注意

- .env 里若还留着这两行，建议删除；不删也无害，只会在每次启动日志里看到一条废弃警告。
- 依赖「INITIAL_PASSWORD + init」做自动化部署的场景，改为：init → 启动一次生成配置 → 停机 → `--reset-password` 设置密码 → 启动。
