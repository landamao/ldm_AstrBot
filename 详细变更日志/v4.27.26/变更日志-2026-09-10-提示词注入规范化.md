# 提示词注入规范化：system_reminder 包裹 + 去除行为引导

- 日期：2026-09-10

## 背景

审查发现两类问题：

1. **注入不可区分**：大量「非用户内容」直接以 user 文本或 `[SYSTEM NOTICE]` 形式混进上下文，模型无法区分「用户说的」和「系统补的」，人格扮演容易被带偏。最典型的是空 @ 唤醒：一整段中文直接当作 user prompt，且写满了行为引导。
2. **引导污染人格**：注入文案里大量操作/输出/思考引导（「友好地询问」「符合人设」「只输出回复内容」「Prioritize…」「Continue the conversation…」「Stop calling tools…」等），与用户配置的人格 prompt 冲突，导致角色扮演机械化、口吻被框架劫持。

## 设计原则（与用户确认）

1. **非用户内容一律用 `<system_reminder>` 包裹**，与用户发言可区分；
2. **只陈述事实，不引导操作 / 输出 / 思考 / 语气**——系统只告知「发生了什么」，怎么回由人格与主 system prompt 决定。

### 设计定式

| 类型 | 处理 |
| --- | --- |
| 对话内注入（extra_user_content_parts / tool 结果 / 追加 user 消息） | 必须 `<system_reminder>` 包裹 + 纯事实 |
| 系统级能力说明（沙箱/本地/工作区路径） | `<system_reminder>` 包裹 + 只写可用性与环境事实 |
| 独立小模型调用（标题生成、图片转述、KB 修复、PONG） | 指令即任务本身，保持原样 |
| 人格定义（ChatUI 默认人格、Live Mode） | 本身就是人格，不动 |
| 安全模式 | 内容安全规则，不是风格引导，不动 |

## 实现

### 1. 空 @ 唤醒（核心修复）

**文件**：`astrbot/builtin_stars/astrbot/main.py`

**改前**（整段中文作为 user prompt，强引导）：

```
注意，你正在社交媒体上中与用户进行聊天，用户只是通过@来唤醒你，但并未在这条消息中输入内容，他可能会在接下来一条发送他想发送的内容。你友好地询问用户想要聊些什么或者需要什么帮助，回复要符合人设，不要太过机械化。请注意，你仅需要输出要回复用户的内容，不要输出其他任何东西
```

**改后**：

```
@{自己的昵称（At.name，无则 event.get_self_id()）}
<system_reminder>用户艾特了你，但并未输入任何内容</system_reminder>
```

昵称优先取 At 组件的 `name`，缺失时回退 `get_self_id()`。

### 2. 打断 / 停止提示去引导

**文件**：`astrbot/core/pipeline/process_stage/method/agent_sub_stages/internal.py`

去掉固定的 `Continue the conversation based on the content already sent above.`：

- 打断兜底 `context_text`（超时未写入历史时临时注入）
- `force_stopped` 手动停止 note
- 新消息打断 note

改后只保留事实句，且全部在 `<system_reminder>` 内。

### 3. Agent 循环注入统一（tool_loop_agent_runner.py）

| 常量 | 改后要点 |
| --- | --- |
| `USER_INTERRUPTION_MESSAGE` | `[SYSTEM: ...]` → `<system_reminder>...</system_reminder>`，去掉引导 |
| `FOLLOW_UP_NOTICE_TEMPLATE` | 去掉 Prioritize / acknowledge 引导，只保留「消息已合并 + [Message N]」 |
| `MAX_STEPS_REACHED_PROMPT` | 只保留 `Maximum tool call limit reached.`，去掉 Stop calling / summarize |
| `REPEATED_TOOL_NOTICE_L1/L2/L3` | 三级统一为同一句事实「同一工具同参连续 N 次」，去掉 Double-check / stop repeating / change strategy |
| `TOOL_RESULT_OVERFLOW_NOTICE_TEMPLATE` | 只保留预览截断 + 完整输出路径，去掉「用读文件工具查看」「用更窄窗口」 |
| `SKILLS_LIKE_REQUERY_*` | 只说明「已选工具 / schema 两阶段下发」，去掉 You must / Do not return empty |
| 未使用方法 | 删除 `_read_tool_hint()`（格式化参数已去掉，方法成死代码） |

### 4. Cron / 后台任务唤醒

**文件**：`astr_main_agent_resources.py`、`cron/manager.py`、`astr_agent_tool_exec.py`

- `PROACTIVE_AGENT_CRON_WOKE_SYSTEM_PROMPT` / `BACKGROUND_TASK_RESULT_WOKE_SYSTEM_PROMPT`：删掉整段 `# IMPORTANT RULES`（Do NOT greet、Explain WHY、MUST use send_message_to_user 等），改为 `<system_reminder>` + 唤醒来源 + 任务 JSON；
- 对应 user prompt：去掉 Proceed according to / summarize 等引导，改为 system_reminder 事实说明；
- 历史对话 dump：拼进 `<system_reminder>Previous conversation history: ...</system_reminder>`。

### 5. 对话内内容块包裹

**文件**：`astr_main_agent.py`

| 项 | 改后 |
| --- | --- |
| KB 检索结果 | `[Related Knowledge Base Results]:` → system_reminder |
| WebChat 侧栏选段 | 包进 system_reminder |
| 引用消息 | `<Quoted Message>` → `<system_reminder>Quoted message: ...</system_reminder>` |
| 图片转述 | `<image_caption>` → `<system_reminder>Image caption: ...</system_reminder>` |
| 转述失败 / 超限跳过 | `[Image Captioning Failed]` 等 → system_reminder |
| 图/音/视频附件路径 | `[Xxx Attachment: path ...]` → system_reminder |
| 工作区路径 | 去掉「Unless the user explicitly specifies…」，改为 system_reminder 路径事实 |
| Computer Use 未启用 | 去掉「ask the user to enable…」，改为能力不可用事实 |

### 6. 系统级能力说明

- `SANDBOX_MODE_PROMPT`：改为 system_reminder，只写沙箱可用；
- `_build_local_mode_prompt()`：去掉「Use POSIX… / do not assume Unix…」等语法引导，只写 OS + Shell 类型事实；
- `WEB_SEARCH_CITATION_PROMPT`：去掉 Always cite / Do not invent，只描述 `<ref>index</ref>` 格式；
- `TOOL_CALL_PROMPT`：只保留「严格按 schema，不编造参数」；
- `TOOL_CALL_PROMPT_SKILLS_LIKE_MODE`：只保留 schema 两阶段机制说明。

### 7. Skills 加载说明去引导

**文件**：`astrbot/core/skills/skill_manager.py`

去掉「When to trigger / Never silently skip / Announce which skill / Failure handling」等行为规则，只保留：技能清单 + SKILL.md 绝对路径 + 读取示例命令 + 只加载直接引用内容。

## 刻意未改

- 安全模式 `LLM_SAFETY_MODE_SYSTEM_PROMPT`：内容安全，非风格引导；
- `CHATUI_SPECIAL_DEFAULT_PERSONA_PROMPT` / `LIVE_MODE_SYSTEM_PROMPT`：本身是人格定义；
- 标题生成、图片转述默认词、KB 修复 `TEXT_REPAIR_SYSTEM_PROMPT`、PONG：独立小模型调用，指令即任务；
- 防抖合并、工具被中断：原本已是 system_reminder + 纯事实。

## 兼容性

- 测试断言的是事实片段（`sent 3 messages`、tool interrupted 文案、`<system_reminder>` 标签），不依赖被删的引导语；
- 人格/自定义规则/压缩指令等用户可配置项未改；
- 工具协议仍保留「严格按 schema」「两阶段下发」等运行必需信息，避免 Agent 循环失效。
