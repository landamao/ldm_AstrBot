# [2026-09-09] plugin 指令回复与插件管理日志文案统一

## 改动内容

聊天侧 `/plugin` 指令组的回复文案与 WebUI 插件管理后端日志中，插件名引用格式统一：插件名一律用「」括住，不再出现「插件 xxx 已启用」这类空格式写法。同时 `/plugin get` 与 `/plugin update` 的成功回复新增版本信息。

### 聊天指令（builtin_stars/builtin_commands/commands/plugin.py）

- 「」统一（原先空格与「」混用）：
  - 启用成功：插件「xxx」已启用。
  - 禁用成功：插件「xxx」已禁用。
  - 重启成功：插件「xxx」已重启。
  - 重启失败：重启插件「xxx」失败: {错误}
  - 后台日志「准备重启/更新插件」同步改为「」格式
  - 「插件不存在」提示原本就是「」格式，未动
- 版本显示：
  - `/plugin get` 安装成功：安装插件「xxx」成功，版本 1.2.3。版本从安装后注册表读取；插件元数据缺失名字时显示「未知」，缺失版本时省略版本段（缺失的数据不伪装）。
  - `/plugin update` 更新成功：插件「xxx」更新成功，版本 1.2.3 → 1.3.0。旧版本在更新前捕获，新版本在 reload 完成后从重新注册的元数据读取；任一缺失显示「未知」。
  - 「正在更新「xxx」插件…」进行中提示保持不变。

### WebUI 插件管理后端（dashboard/services/plugin_service.py）

共 19 处日志/返回消息的插件名（或仓库地址、上传文件名）统一加「」：

- 返回消息：插件「{dir_name}」重载成功。
- 安装：正在安装插件「{repo_url}」、安装插件「{repo_url}」成功。、GitHub 加速跳过 CDN 日志、用户上传插件安装 2 处
- 卸载：正在卸载插件「{plugin_name}」、失败插件卸载 3 处
- 更新：正在更新插件「{plugin_name}」、批量更新插件「{name}」、更新失败插件 4 处、update-all 错误日志 3 处、GitHub 加速日志 2 处
- 附带：获取插件 Skills 失败「{plugin.name}」

## 修改文件

- astrbot/dashboard/services/plugin_service.py

## 验证

- 两个文件均通过 py_compile / ast 语法校验。
- 正则扫描确认无「插件 {xxx}」空格式残留（剩余命中均为「插件 Logo」「插件 Skills」等名词短语，非插件名引用）。
- 版本读取顺序核对过 star_manager 实现：reload 会销毁并重建插件元数据对象（star_manager.py star_map[path] = metadata），旧版本必须提前捕获、新版本事后重新 get_registered_star，当前实现正是该顺序。

## 部署/测试注意

- 纯 Python 改动，无需前端构建；源码同步后手动重启生效。
- 聊天侧可实测：/plugin on|off|restart <插件名> 看回复是否为「」格式；/plugin get <仓库>、/plugin update <插件名> 看版本显示。
- update 版本显示依赖插件 metadata 的 version 字段，个别插件未声明 version 时按「未知」显示，属预期。
