# 工具中断上下文提示修复

## 问题

1. WebUI ChatUI 工具调用被手动停止时，上下文里英文系统提示重复：tool 结果里已有一条「The tool 'test' was interrupted...」，后面又多了一条 assistant 的「The user manually stopped this response.」
2. 上一轮修复（工具结果统一重写为中断提示）引入新问题：两次工具调用、第一个执行成功、第二个才被中断时，第一个工具的真实结果也被重写成了中断提示
3. 再上一轮修复（has_tool_results 整体原样返回）引入新问题：工具执行成功后进入文本生成阶段才被中断时，文本末尾的停止标记丢了（实测：调用工具 → 工具返回 → assistant 输出赤壁赋 → 用户停止，上下文里文本后没有停止提示）

## 最终语义（按中断发生阶段区分）

- 工具执行阶段被中断：重写工具的返回结果为英文中断提示词；串行执行下已完成的工具保留真实结果，未执行的工具写「was not executed」未执行提示；不追加 assistant 停止标记
- 文本输出阶段被中断（含工具成功之后的文本生成）：在文本末尾追加英文停止标记；工具调用与结果原样保留

## 根因

- `_apply_interrupt_to_messages` 的 `has_tool_results` 分支在 tool 结果之外还会追加一条 assistant 停止标记（与 tool 结果里的中断提示重复）
- 工具是串行执行（for 循环逐个跑）。中断时已完成的工具结果只存在局部变量 `tool_call_result_blocks` 里，`_ToolExecutionInterrupted` 异常直接抛出去，这些真实结果全部丢失；`_finalize_aborted_step` 拿不到已完成结果，只能给所有 tool_call 一律写中断提示

## 改动

### `astrbot/core/agent/runners/tool_loop_agent_runner.py`

- `_ToolExecutionInterrupted` 异常新增两个字段：`completed_blocks`（中断前已完成工具的真实结果）和 `interrupted_tool_call_id`(真正被中断的工具调用 ID)
- `_iter_tool_executor_results`：签名新增 `completed_blocks`、`current_tool_call_id` 两个参数（由 `_handle_function_tools` 调用时传入当前上下文），两个中断抛出点把已完成结果和被中断工具 ID 带进异常
- `_finalize_aborted_step`：签名新增 `completed_blocks`、`interrupted_tool_call_id` 参数，按工具逐个写 tool 角色消息：
  - 已完成的工具 → 保留真实结果（不再误标为中断）
  - 真正被中断的工具 → 写英文中断提示「The tool 'xxx' was interrupted because the user actively requested to stop. The execution was incomplete.」
  - 未执行到的工具 → 写英文未执行提示「The tool 'xxx' was not executed because the user actively requested to stop.」（每个 tool_call 必须有对应 tool 消息，否则历史不完整）
- `step()` 的 `except _ToolExecutionInterrupted` 分支：把异常携带的已完成结果和被中断工具 ID 传给 `_finalize_aborted_step`

### `astrbot/core/pipeline/process_stage/method/agent_sub_stages/internal.py`

- `_apply_interrupt_to_messages` 的 `has_tool_results` 分支：区分中断发生阶段——
  - 最后一条 user 消息之后存在无 tool_calls 的非空文本 assistant（文本阶段被中断）→ 不提前返回，继续走通用逻辑在文本末尾追加停止标记，tool 调用与结果原样保留
  - 否则（工具阶段被中断，中断提示已由 runner 写在 tool 结果里）→ 原样保留直接返回
  - 用「最后一条 user 之后」判定本轮文本回复，避免多轮场景误伤上一轮旧回复
- 删除上一轮叠的两个辅助函数 `_tool_messages_already_note_interrupt`、`_extract_message_plain_static`（本次方案不再需要）

## 修复后上下文形态

两个工具（test、file_read）、中断在第二个时：

```
assistant: tool_calls [test, file_read]
tool(call_1): test 的真实结果
tool(call_2): <system_reminder>The tool 'file_read' was interrupted ...</system_reminder>
```

工具成功后文本生成被中断时（实测赤壁赋场景）：

```
assistant: tool_calls [test]
tool: 测试调用（真实结果）
assistant: # 前赤壁赋…（已生成部分）+ <system_reminder>The user manually stopped this response. …</system_reminder>
```

纯文本（无工具调用）被停止的行为不变：assistant 末尾仍追加英文停止标记。
