# [2026-08-31] 指令组星号兜底子指令（未匹配时处理）与「子指令名不存在」提示

> 本文件为独立变更日志，记录 2026-08-31 一次聊天指令框架改造：子指令名填 `*` 表示「未匹配时处理」的兜底子指令；没有注册 `*` 时，子指令不匹配不再唤醒 LLM，而是发送「子指令名不存在」提示（含指令树），并把原「参数不足」文案统一为「子指令名不存在」。

---

## 问题现象

- 指令组 `@filter.command_group("test")` 下，子指令不匹配时（如 `/test uuu`）没有任何 handler 接管，事件继续落入 LLM 对话，模型会对不存在的子指令随意作答。
- 子指令注册时漏填指令名（`@test.command()`）只是打一条 WARNING，handler 无任何过滤器，成为永不触发的「幽灵」handler（waking_check 对空 event_filters 直接 continue），用户容易误以为它会兜底。
- 仅输入组名（`/test`）时提示文案为「参数不足」，与「子指令名不存在」语义不符。

## 背景原因

- waking_check 阶段按 handler 逐个过滤：指令组 handler 只负责前缀匹配（startswith），具体子指令由各自 CommandFilter 匹配；组前缀命中但子指令全部不匹配时，没有任何拦截点，事件带着 is_wake 状态继续，ProcessStage 见无 handler 接管且未发消息即唤醒 LLM。
- `CommandGroupFilter.startswith` 使用 `message_str.startswith(tuple(完整指令名列表))` 的宽松前缀匹配，`"test2 off".startswith("test")` 为 True——组名互为前缀时（test / test2）会误判归属，新拦截逻辑下会错误地抢先报「子指令名不存在」。

## 改动内容

### 新增：`*` 兜底子指令

- `@test.command("*")` 注册兜底子指令：组前缀命中、非纯组名、且组内其他子指令（含子指令组）都没有匹配时触发。
- 参数解析：剥离组名后剩余部分按空格分词，按普通子指令规则转换（`/test uuu xxx` → 首个参数 `cmd="uuu"`）。
- 优先级：具体子指令 > `*` 兜底；纯组名 `/test` 不触发 `*`（走「子指令名不存在」提示）。
- 帮助树中显示为 `├── * (未匹配时处理)`。
- 实现：
  - `astrbot/core/star/filter/command.py`
    - `CommandFilter.__init__` 新增 `parent_group` 反向引用（由指令组挂载时设置）
    - 新增 `matches(message_str)` 判断指令命中（指令名 + 参数形式）
    - 新增 `is_fallback` 属性（`command_name == "*"`）
    - `filter()` 新增 `*` 分支：非纯组名 + 组前缀命中 + 其他子指令（含子指令组）不匹配才生效，随后剥离组名做参数解析
  - `astrbot/core/star/filter/command_group.py`
    - `add_sub_command_filter()` 对 `command_name == "*"` 的 CommandFilter 设置 `parent_group = self`

### 新增：子指令名不存在 → 不唤醒 LLM，发送提示

- `CommandGroupFilter.filter()`：组前缀命中后，若无 `*` 兜底且所有子指令（含子指令组前缀）都不匹配，抛 `ValueError("子指令名不存在。…指令组下有如下指令，请参考：\n" + 指令树)`。
- waking_check 既有异常捕获链路处理：发送 `插件 xxx: 子指令名不存在。…` 提示 → `stop_event()` → `event.send` 置 `_has_send_oper=True` → ProcessStage 不再唤醒 LLM。
- 仅输入组名（`/test`）的提示文案由「参数不足」统一改为「子指令名不存在」。
- `astrbot/core/pipeline/waking_check/stage.py`：plugin 组美化帮助特判 `err_text.startswith("参数不足。")` 同步改为 `startswith("子指令名不存在。")`，`/plugin` 组的行为（纯组名/乱输子指令均发美化帮助）保持一致。

### 修复：指令组前缀重叠误判

- `CommandGroupFilter.startswith()` 由宽松 tuple 前缀匹配改为边界敏感：指令名后需为空格或结尾（`message_str == full_cmd or message_str.startswith(f"{full_cmd} ")`），避免 `test` / `test2` 这类互为前缀的组名误判归属。

## 使用方式

```python
@filter.command_group("test")
def test(self, event):
    yield event.plain_result("111")

@test.command("off")
async def meme_off(self, event):
    yield event.plain_result("off")

@test.command("*")
async def fallback(self, event, cmd: str = None):
    yield event.plain_result(f"未匹配的指令名: {cmd or '无'}")
```

行为一览：

| 消息 | 无 `*` 兜底 | 有 `*` 兜底 |
|------|------------|------------|
| `/test off` | 触发 meme_off | 触发 meme_off（兜底不抢） |
| `/test uuu` | 发「子指令名不存在」提示，不唤醒 LLM | 触发 fallback（cmd=uuu） |
| `/test` | 发「子指令名不存在」提示 | 同左（`*` 不接纯组名） |

## 补充改动：注册指令不填参数一律报错，插件加载失败

紧随其上（同一天）：`astrbot/core/star/register/star_handler.py` 把原来「打 WARNING + 注册成永不触发的幽灵 handler」改为直接抛异常，插件加载直接失败，不再静默产生幽灵指令。

四种空参场景统一：

| 场景 | 报错信息 |
|------|---------|
| `@test.command()` 子指令不填指令名 | `指令组「test」注册子指令时未提供 sub_command 参数，插件加载失败。` |
| `@filter.command()` 裸指令不填指令名 | `注册裸指令时未提供 command_name 参数，插件加载失败。` |
| `@filter.command_group()` 指令组不填指令名 | `注册指令组时未提供 command_group_name 参数，插件加载失败。` |
| `@test.group()` 子指令组不填指令名 | `指令组「test」注册子指令组时未提供 sub_command 参数，插件加载失败。` |

- 装饰器在 import 阶段执行，异常会中断类定义 → 整个插件模块加载失败，启动日志可见 traceback。
- 原「warning + 幽灵 handler」行为删除（waking_check 对空 event_filters 的跳过逻辑保留，但正常注册流程已不可能产生空 filters 的 handler）。
- 删除了 `star_handler.py` 中不再使用的 `logger` import。
- 测试：`tests/test_register_no_args.py`（新增，4 空参场景全 raise + 正常注册不受影响）；`tests/test_cmdgroup_integration.py` 删除原幽灵用例 `@test.command()`（现为非法用法）。
