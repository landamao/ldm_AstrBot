# 工具调用期间防打断

## 需求

平台里用户发新消息，可以打断文本回复，但**不能打断正在执行的工具调用**，防止误操作（如工具执行到一半被取消产生副作用）：

- 开了「输出函数调用状态」→ 发送提示「⚠️ 我正在使用工具，你的消息我将稍稍后回复，如需停止，请发送「/stop」」（stop 前带用户配置的第一个唤醒词，唤醒词为空则不带前缀）
- 没开 → 不发送内容，静默放入队列（follow-up），工具间隙注入 LLM

在「打断回复」配置里新增开关「工具调用期间防打断」，默认开启。同时调整打断回复各配置默认值。

## 改动

### 新增配置项 `platform_settings.interrupt_reply.tool_interrupt_protect`（默认 True）

四处齐全（漏一处 WebUI 就显示裸键名）：

- `astrbot/core/config/default.py` DEFAULT_CONFIG 默认值（~L137）
- `astrbot/core/config/default.py` schema 模板（~L1131）
- `astrbot/core/config/default.py` CONFIG_METADATA_2 metadata（~L4776，description/hint，condition 跟随「启用打断回复」）
- `dashboard/src/i18n/locales/zh-CN/features/config-metadata.json`（description/hint）

hint：「开启后，当前任务正在执行工具调用时不打断，防止误操作。开启「输出函数调用状态」时会提示用户稍后回复，否则静默放入队列。」

### 打断回复默认值调整（default.py）

| 配置项 | 旧默认 | 新默认 |
|--------|--------|--------|
| 启用打断回复 enable | False | **True** |
| 私聊中启用 enable_private | True | True（不变） |
| 群聊中启用 enable_group | True | **False** |
| 向用户发送打断提示 notify_user | True | **False** |
| 打断提示文案 notify_text | 不变 | 不变 |
| 等待旧任务结束超时（秒）wait_timeout | 8.0 | **3.0** |

老配置文件缺新字段时按 default 补齐（即防打断默认开启）。

### `astrbot/core/agent/runners/tool_loop_agent_runner.py`

- 新增 `_tool_executing` 字段（None = 无工具在执行）：`_handle_function_tools` 循环里每个工具开始执行前置位为当前 tool_call_id，该工具结果 yield 完后清位（只清 `== func_tool_id`，串行执行安全）
- 新增 `is_tool_executing()` 查询方法
- `_resolve_unconsumed_follow_ups`：**只有显式 /stop（`agent_force_stop` extra）才丢弃队列中未消费的 follow-up 消息**；软打断（仅 `agent_stop_requested`，新消息打断文本回复）不丢弃，释放后排队消息按到达顺序作为新请求正常处理
- `_format_follow_up_line`：follow-up 注入列表格式由 `1. xxx` 数字编号改为全英文 `Message 1: xxx`（与 [SYSTEM NOTICE] 模板语言一致）

### `astrbot/core/pipeline/process_stage/method/agent_sub_stages/internal.py`

`_maybe_interrupt_active_reply` 开头（在 request_agent_stop_all 之前）新增防打断分支：

- `tool_interrupt_protect` 开启 + 存在活跃 runner + `is_tool_executing()` → 不打断，直接返回 False
- `self.show_tool_use`（输出函数调用状态）开启时发送 ⚠️ 提示（只看此配置，与 notify_user/notify_text 无关）；提示中的停止指令 = 配置的第一个唤醒词 + stop（唤醒词为空则只有 stop）
- 未开状态输出则静默，消息已入 follow-up 队列，下个工具结果间隙以 [SYSTEM NOTICE] 块注入 LLM

## 行为说明（实测确认）

- 工具窗口内连发多条消息：每条各自入队（每条收到一次 ⚠️ 提示），下个工具结果出来时全部按序注入（Message 1: / Message 2: …），模型先简短确认收到再继续
- 文本生成阶段的新消息：走正常软打断路径（防打断只保护工具窗口）
- /stop：连排队中未消费的消息一起取消，等待中的消息事件直接结束处理，不唤醒 LLM；stop 后新消息不再入队
- 软打断：队列消息照常处理，不丢
