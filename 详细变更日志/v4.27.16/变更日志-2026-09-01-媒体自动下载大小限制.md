# [2026-09-01] 媒体自动下载大小限制：按类型配置上限，超限把链接传给 LLM

> 本文件为独立变更日志，记录 2026-09-01 媒体自动下载大小限制功能：
> 下载不再无上限，按媒体类型分别限制大小；超过上限的文件不再下载，
> 改为把下载链接以文本形式传给模型，保证 LLM 始终有可用信息。

---

## 背景

- 此前 `download_file` 没有任何大小上限，唯一约束是超时（1800 秒）；
  媒体消息自动下载可能拉取任意大的文件，磁盘和流量不可控。
- 下载时机：平台 adapter 收到消息只保存 URL 引用，唤醒 LLM 后才真正下载；
  未唤醒的消息不下载，因此限制放在下载发生层即可，无需在 adapter 拦截。

## 功能设计

- 新增配置 `platform_settings.auto_download_limits`（WebUI：配置文件 →
  平台配置 → 新逻辑块「文件下载限制」，位于「速率限制」之后）：
  - `enable`：总开关，默认开启
  - `max_file_mb`：文件/视频上限，默认 20.0
  - `max_image_mb`：图片上限，默认 10.0
  - `max_audio_mb`：语音上限，默认 10.0
  - `max_other_mb`：其他类型（兜底）上限，默认 10.0
  - 全部为 float，滑块 0-100 步进 0.1（保留一位小数），超过 100 可在
    输入框手动输入；0 表示不限制
- 新增配置 `provider_ltm_settings.image_caption_max_size_mb`
  （WebUI：AI 配置 → 群聊上下文感知 →「图片下载大小上限 (MB)」，默认 10.0）：
  群聊自动理解图片时下载图片的上限，超限跳过该图转述
- 超限行为：抛 `DownloadFileSizeLimitError`，删除半成品文件，
  由上层把 URL 以文本形式传给模型（如 `[File Attachment: name xxx, url ...]`），
  不中断对话

## 改动内容

### 后端 `astrbot/core/utils/io.py`

- `download_file` 新增 `max_bytes` 参数：
  - 下载前检查 `content-length`，超限直接拒绝（不发起下载）
  - 下载中逐块累计，超限立即中止（防服务器谎报长度）
  - 两条下载路径（主路径 + SSL 降级重试路径）都接入
  - 异常时调用新增的 `_remove_partial_download` 清理半成品文件
- 新增 `DownloadFileSizeLimitError` 异常类（携带 url/size/max_bytes）

### 后端 `astrbot/core/utils/media_utils.py`

- 新增 `get_auto_download_max_bytes(media_type)`：读取平台配置对应类型的
  上限（MB→字节），未启用/无效/0 返回 None（不限制）；
  类型映射：image→max_image_mb，audio→max_audio_mb，
  video/file→max_file_mb，其他→max_other_mb
- `_materialize_media_ref` 新增 `max_bytes` 参数（None 时自动读配置），
  HTTP 下载接入限制
- `MediaResolver.to_path` / `as_path` 新增 `max_bytes` 透传参数

### 后端 `astrbot/core/message/components.py`

- `File._download_file` 接入 file 类型上限

### 后端 `astrbot/core/astr_main_agent.py`（LLM 附件组装）

- 图片/语音/文件/视频（主消息 + 引用链）的下载超限统一捕获
  `DownloadFileSizeLimitError`：记 INFO 日志，把 URL 以附件说明文本传给模型
- 图片转述路径 `_ensure_img_caption`：压缩时遇到超限图片，跳过转述，
  以 URL 文本兜底
- 视频 `_append_video_attachment`：超限单独分支，传 URL 文本

### 后端 `astrbot/core/pipeline/preprocess_stage/stage.py`

- 语音（含引用链）：下载超限跳过处理，记 WARNING
- 图片（含引用链）：下载超限单独捕获记 INFO（「图片超过下载上限，跳过
  本地化处理，保留原始链接」），不再落入通用 except 的
  「Image processing failed」WARN 误报；组件保留原始 URL

### 后端 `astrbot/builtin_stars/astrbot/group_chat_context.py`

- `_calc_image_md5` 新增 cfg 参数：有下载上限时走 MediaResolver 带限制下载，
  超限记 INFO「超过下载上限 | 跳过转述」，返回 None（该图显示为 [Image]）
- `_image_caption_max_bytes(cfg)` 从 cfg 读 `image_caption_max_size_mb`
- 两处调用方（MD5 缓存计算、延迟转述预统计）传入 cfg
- 注意：群聊上下文感知的图片转述用自己的上限配置，不走平台下载限制

### 配置 `astrbot/core/config/default.py`

- `DEFAULT_CONFIG`：`platform_settings.auto_download_limits` 默认值 +
  `provider_ltm_settings.image_caption_max_size_mb: 10.0`
- `CONFIG_METADATA_2`：两处 schema items（float 类型）
- `CONFIG_METADATA_3`：platform_group 新增「文件下载限制」逻辑块
  （enable + 四项上限，含 condition 联动与 slider）；
  ltm 群聊上下文感知块新增「图片下载大小上限 (MB)」

### 前端 `dashboard/src/components/shared/ConfigItemRenderer.vue`

- 滑块数值按 step 保留小数位（新增 `formatSliderValue`：step 0.1 →
  保留一位小数，step ≥1 取整，最多两位）；原来 step 0.1 会产生
  0.30000000000000004 这类浮点尾巴

### 前端 i18n `dashboard/src/i18n/locales/zh-CN/features/config-metadata.json`

- 「文件下载限制」块 + 群聊上下文感知新项的中文文案

### 测试 `tests/test_image_command.py`（顺手修复）

- FakeEvent 补 `message_obj`（图生图 v4.27.14 加 `_load_reference_images`
  后测试没跟上，5 个用例 AttributeError），14 个用例全过

## 已知边界（按设计）

- WebUI 聊天（WebChat）发送的附件：上传时已直接落在
  `data/attachments/` 本地路径，不走 HTTP 下载，大小限制不适用，
  LLM 拿到的始终是本地路径——这是 WebChat 附件的固有行为
- 本地路径 / base64 / data URI 的媒体组件不经过 HTTP 下载，不受限制
- Misskey 平台有自己的 `misskey_max_download_bytes`，互不影响
