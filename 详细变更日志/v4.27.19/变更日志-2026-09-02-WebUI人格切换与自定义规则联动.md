# [2026-09-02] WebUI ChatUI 人格切换与自定义规则联动

> 本文件为独立变更日志，记录 2026-09-02 一次修复：WebUI 聊天界面（ChatUI）
> 输入框加号菜单的「人格情景」切换，在该对话有自定义规则强制人格时
> 切换不生效、显示也不跟随的问题。

---

## 问题现象

1. 会话被自定义规则（会话管理页 → session_service_config.persona_id）强制
   人格时，在 ChatUI 加号菜单里切换人格，无论选什么都不生效——下一条消息
   仍用规则里的人格。
2. 反过来，在聊天侧用 `/persona` 指令切换（指令联动会直接改规则值，见
   「persona远程换人格」日志）之后，ChatUI 菜单里显示的当前人格仍是旧值，
   不跟随规则变化。

## 根因

- ChatUI 人格切换走 `POST /chat/sessions/{id}/persona` →
  `chat_service.set_session_persona`，原逻辑**只写对话级 persona_id**
  （conversations 表字段）。
- 而运行时人格解析 `persona_mgr.resolve_selected_persona` 中，自定义规则
  的 persona_id **无条件压制**对话级设置 → 有规则时怎么切换都被规则盖住。
- `get_session_persona` 同理只读对话值 → 指令改了规则后菜单显示不跟随。

## 修复方案

与 `/persona` 指令的规则联动逻辑（2026-09-02 已落地）完全同构：

### 后端（astrbot/dashboard/services/chat_service.py）

- `set_session_persona`：先读该会话 UMO 的 session_service_config——
  - 有规则 persona_id → 直接改规则值并写回 preference，不写对话；
    实时生效（运行时现读 preference）。新增中文日志
    `WebChat 人格: 会话 {umo} 的自定义规则人格已设为「{id}」，立即生效`。
  - 选「不使用人格」（[%None]）→ 从规则 pop persona_id，其余规则字段保留，
    回落按对话/默认人格生效。
  - 无规则 → 原逻辑不变：写当前对话 persona_id；无对话自动创建。
- `get_session_persona`：规则优先返回（与运行时解析顺序一致）；
  响应新增 `from_rule` 布尔标记标识当前人格是否来自规则强制。
- 两条 transport 路由（v1 + legacy）都汇入这两个方法，改一处全生效。

### 前端（dashboard/src）

- `PersonaMenuItem.vue`：
  - 从 `getSessionPersona` 响应读取 `from_rule`；有规则时弹窗顶部显示
    v-alert 提示「当前会话被自定义规则强制人格，切换将直接修改规则值并
    立即生效。」（i18n `persona.ruleForced`）。
  - 有规则时选「不使用人格」→ 本地同步 fromRule=false（对应后端从规则
    移除）。
- `Chat.vue` / `StandaloneChat.vue` 的 `handlePersonaSelect`：按响应
  `from_rule` 分流 toast——规则路径弹「已修改自定义规则的人格，立即生效」
  （i18n `persona.ruleSetSuccess`），普通路径弹「人格情景已设置」。
  StandaloneChat 此前切人格成功/失败均无任何反馈，一并补上成功+失败 toast。
- i18n 只加 zh-CN（ldm 不保留 en-US/ru-RU）。

### 测试（tests/test_webchat_persona_rule.py，新增 8 例）

风格对齐 test_webchat_empty_bot_flush.py（asyncio.run + __new__ 桩模式）：

- set 有规则 → 改规则值、其余字段保留、不写对话、from_rule=True
- set 有规则 + [%None] → 从规则移除 persona_id，其余字段保留
- set 无规则 → 原逻辑写对话、不写规则
- set 无规则无对话 → 自动创建带人格
- get 有规则 → 返回规则值 + from_rule=True
- get 规则移除后 → 回落对话 persona_id
- get 无对话 → persona_id=None
- 会话不存在 → 抛 ChatServiceError

运行：`pytest tests/test_webchat_persona_rule.py -q` → 8 passed。

## 效果

- 有规则会话：ChatUI 切人格 = 直接改规则值，立即生效，与指令行为一致；
  弹窗明示「切换将直接修改规则值」，不再出现「选了没反应」的假象。
- 指令与 WebUI 两条路径改的是同一份数据（规则值），互相可见、显示跟随。
- 无规则会话行为完全不变（写对话/自动创建）。

## 部署

- 前端已构建部署（构建部署.sh 完成，dist 已同步运行目录）。
- 后端为 py 改动，需 `bash ~/同步源码.sh` + 手动重启 ldm 生效。

## mock 坑备忘

- conv_mgr.get_conversation 返回带 .persona_id 属性的对象（非 dict）。
- build_webchat_unified_msg_origin 需要 session 带 platform_id/creator/
  session_id/is_group 四属性。
- 打桩 sp 必须 `patch(f"{MODULE}.sp", fake)`；不能用
  `patch(MODULE, {...}, create=True)` 字典形式——它把模块名按最后一个点
  拆成「包.属性」，改的是包属性而非模块全局 sp，规则分支读不到桩。
