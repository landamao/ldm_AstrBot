# [2026-09-03] 消息防抖：私聊连发消息合并为一次 LLM 请求

> 本文件为独立变更日志，记录新增「消息防抖」功能：
> 私聊用户连发多条消息时，防抖窗口内只保留最后一条的静默期，期满后
> 合并全部内容请求一次 LLM，替代此前「每条都请求、丢弃 N-1 次结果」的浪费。

---

## 一、需求与问题现象

### 问题现象

打断回复开启时，用户连续发三条「1」：

- 三条消息各自走完整 pipeline，**三次都请求 LLM**；
- 前两次请求的结果被打断丢弃，只有第三次的回复真正发出；
- 用户刷屏十几条 = 十几次 LLM 请求 + 丢弃 n-1 次结果，浪费严重。

### 需求语义（与用户确认的过程）

1. 用户发新消息 → 先防抖，再由打断回复接管；
2. 防抖只做防抖，**不改变消息处理方式**：图片开转述就转述、
   语音/文件/引用照原链路处理——在 LLM 请求前拿原生处理的结果；
3. 先做私聊，群聊暂不做；
4. 配置区域放 WebUI 配置文件 → 扩展配置 → 分段回复下面（打断回复上方）。

### 设计讨论中敲定的取舍

- **合并方式**：不是每条消息各自跑一遍原生处理再拼结果，而是把被吸收
  消息的原始组件（文本 + Image/Record/File/Reply/Video）并入赢家 event，
  统一走一遍原生链路（下载/压缩/转述一次完成，临时文件全部 track 在
  赢家 event 上，生命周期干净）；
- **落库与请求一致**：合并提示 `<system_reminder>` 直接拼进合并后的
  message_str 末尾，随 req.prompt 一条路走到本次请求与历史落库——
  不做「请求时临时注入、落库不带」的双层机制（用户拍板砍掉）；
- 被吸收消息**不写对话历史**（内容已并入赢家那条 user 消息）；
- 默认关闭，不影响现行为。

## 二、实现

### 插入点

`astrbot/core/pipeline/process_stage/method/agent_sub_stages/internal.py`
`InternalAgentSubStage.process()`：

- 空消息检查（无文本/媒体/Reply 直接 return）**之后**；
- 打断判定（`_should_interrupt_reply`）**之前**；
- `has_provider_request`（插件构造的 LLM 请求）跳过防抖，不受影响；
- send_typing 在防抖之后：被吸收消息不触发 typing；
- 防抖等待不持 session lock（lock 在后面才 acquire），不饿死旧任务收尾。

### 防抖状态机（模块级 per-UMO）

```
消息 A（首条）→ 开窗：deadline = now+window，hard_deadline = now+max_wait
             → 循环 sleep 到 deadline；醒来发现状态不是自己 → 放行（边界竞态）
消息 B/C（窗口内）→ 吸收：文本/outline/媒体组件进缓冲，
             deadline = min(now+window, hard_deadline)（滑动重置）
静默期满（A 仍是赢家）→ 合并：message_str 按 [Message N] 拼接 +
             <system_reminder> 提示；媒体组件 extend 进赢家消息链
             → 走原有打断判定 → 原生处理 → 单次 LLM 请求
```

- 被吸收消息直接 `return`，**不触发打断、不请求、不回复**；
- 连发 10 条 = 1 次打断 + 1 次请求；
- max_wait 到期强制放行；放行后仍在连发的消息开新窗口（分多批）；
- finally 里 `is entry` 判定后清理状态项，防误删新窗口、防泄漏。

### 合并格式（请求与落库同一条内容）

```
[Message 1] 2
[Message 2] 3
[Message 3] 5
<system_reminder>The user sent 3 messages in rapid succession within a short time. They have been merged into this single message in chronological order, each prefixed with [Message N].</system_reminder>
```

- 无文本的纯媒体消息用 `get_message_outline()` 占位（如 `[图片]`）；
- 后续会话回看历史，AI 也能理解这条 user 消息是连发合并的。

### 配置（platform_settings.message_debounce）

| 配置项 | 默认 | 范围 | 说明 |
| --- | --- | --- | --- |
| enable | False | - | 启用开关，默认关 |
| window | 2.0 | 0~60 | 防抖静默窗口（秒），窗口内新消息重置计时；0 等同关闭 |
| max_wait | 60.0 | 1~600 | 累计等待上限（秒），持续刷屏超时强制放行；正常聊天不受影响；设得比 window 还小等效于缩短窗口 |

- 配置实时现读（仿 `_get_interrupt_reply_config`，禁缓存），WebUI 改完立即生效；
- 仅私聊生效（`is_private_chat()` 判定）；群聊与插件 provider_request 不防抖。
