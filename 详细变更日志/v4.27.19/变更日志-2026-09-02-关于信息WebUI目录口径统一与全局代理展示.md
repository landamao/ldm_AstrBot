## 一、WebUI 目录口径不一致（修复）

### 问题现象

- WebUI「关于ldm」弹窗显示 `WebUI目录: /home/ldm/ldmbot_run/dashboard/dist`；
- /about 指令显示 `WebUI目录: /home/ldm/ldmbot_run/data/dist`；
- 两边明明共用同一个信息收集函数，值却不一样。

### 根因

两边共用 `astrbot/core/utils/about_info.py:get_about_info()`，但传参不同：

- WebUI 端点（`astrbot/dashboard/api/stats.py` `/stats/about`）传入
  `app.state.dashboard_static_folder`，即 server.py 启动时用统一解析器
  `resolve_dashboard_dist()` 解析出的**实际生效目录**（dashboard/dist）；
- /about 指令（`builtin_commands/commands/about.py`）不传参，落进
  `get_about_info()` 里写死的旧回退 `data/dist`——2026-09-01 WebUI 目录
  迁移到 dashboard/dist 后，这个回退没有跟着改。

### 修复内容

1. `astrbot/core/utils/about_info.py`
   - 回退从写死 `os.path.join(get_astrbot_data_path(), "dist")` 改为委托
     统一解析器 `resolve_dashboard_dist()`，与 WebUI 端点同一口径；
   - 解析不到可用 dist 时返回 None（缺失就是缺失，不再拼路径假装能用）。
2. `astrbot/builtin_stars/builtin_commands/commands/about.py`
   - WebUI 目录为空时显示「未知」。

## 二、新增「全局代理」使用情况（功能）

### 需求

「关于」信息的 ldm 信息段，「已运行时长」下方新增全局代理使用情况，
区分几种情况：启动前环境变量设了代理、是否清除环境变量代理、
配置文件设置了代理。

### 设计要点（关键：事实源是当前进程环境变量）

代理规则**仅在启动时应用一次**（`astrbot/core/core_lifecycle.py` `__init__`）：

1. 配置了 `http_proxy` → 写入环境变量；
2. 未配置且开启「未配置代理时清除系统代理」→ 清除环境变量，
   并设 `no_proxy=localhost,127.0.0.1,::1`；
3. 否则保留启动前 shell 导出的代理变量。

WebUI 改代理配置只落盘（`AstrBotConfig.save_config` 会同步更新内存单例，
但**不会**重新应用代理规则到进程环境变量），重启才重新应用。
因此展示逻辑**以当前进程环境变量为事实源**，配置与进程不一致时
如实标注「重启后生效」——显示的第一段永远是当前真实生效的代理，
括号里才是配置文件的待生效状态。

### 展示格式（7 种场景）

| 场景 | 输出示例 |
| --- | --- |
| 配置代理已生效（进程环境=配置值） | `http://127.0.0.1:7897（来自配置文件）` |
| 进程有代理 + 配置改过未重启 | `http://127.0.0.1:7897（来自启动环境变量；配置文件为 http://127.0.0.1:9999，重启后生效）` |
| 仅启动前 shell 导出的代理 | `http://10.0.0.1:7890（来自启动环境变量）` |
| 进程有代理 + 已开清除开关未重启 | `…（来自启动环境变量；重启后将清除）` |
| 配置填了代理但进程环境无（未重启） | `未使用代理，直连（配置文件为 http://127.0.0.1:7897，重启后生效）` |
| 开了清除开关且已生效 | `已清除系统代理，localhost 直连`（以启动时清除行为留下的 `no_proxy=localhost,127.0.0.1,::1` 特征值判定） |
| 两处均无 | `未使用代理，直连` |

环境变量读取顺序：`https_proxy` → `HTTPS_PROXY` → `http_proxy` → `HTTP_PROXY`，
与 core_lifecycle 的判定习惯一致（优先 https）。
