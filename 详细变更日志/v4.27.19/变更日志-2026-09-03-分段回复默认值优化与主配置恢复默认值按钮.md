# [2026-09-03] 分段回复默认值优化与主配置「恢复默认值」按钮

> 本文件为独立变更日志，记录三类改动：
> ① 分段回复/消息防抖默认值优化（换行分段可见、超长阈值 400、默认开启）；
> ② WebUI 专业模式分段配置聚合与条件显示修复；
> ③ 主配置文件新增「恢复默认值」按钮（仅填空类/数值类），并修复
>    默认值注入函数误伤 list 配置项（管理员 ID / 唤醒词）。

---

## 一、分段回复与相关功能默认值优化

### 问题现象

1. **换行分段默认值不可见**：`split_words` 默认列表里存的是真实换行符
   `\n`（单个字符），WebUI 配置列表渲染成空白行，看起来像「没有换行分段」；
2. **超长不分段阈值太小**：默认 0（不限制），长文回复会拆成过多段；
3. **分段回复 / 消息防抖默认关闭**：新装用户需要手动开启才享受内置
   分段与连发合并能力。

### 改动

| 配置项 | 旧默认 | 新默认 | 说明 |
| --- | --- | --- | --- |
| segmented_reply.enable | False | True | 分段回复默认开启 |
| split_words 中的换行 | 真实 `\n` | 字面量 `\\n` | WebUI 列表可见；splitter 已有 `\\n`→换行转换，行为不变 |
| words_count_threshold | 0（不限） | 400 | 超过 400 字整段发送，避免长文拆太多段 |

- 分段回复默认开启需**三处同步**：DEFAULT_CONFIG、
  `_segmented_reply_template()` 兜底模板、`resolve_segmented_reply_config()`
  的 `pick("enable", default=True)`——原 `default=False` 会在 raw 缺键时
  压过模板值，只改模板不生效；
- 用户已显式保存过的配置不受影响（raw 有值用 raw），仅新配置/缺键生效。

### 消息防抖 / 打断回复默认开启

- `message_debounce.enable`：False → True（打断回复本就默认 True，未动）；
- 防抖静默窗口 2s、累计上限 60s 保持默认。

## 二、WebUI 专业模式分段配置聚合与条件显示

### 问题现象

专业模式下「分段模式（符号列表/正则）」位于配置列表很前部，而
「从哪些符号后断开」等分段项在后面，相关配置被割裂；且「从哪些符号后断开」
在正则模式下仍显示（不匹配当前分段模式），缺少条件联动。

### 改动（astrbot/core/config/default.py CONFIG_METADATA_3）

- 把 `split_mode`（分段模式）、`regex`（分段正则）两项移到
  `split_words`（从哪些符号后断开）之前，三项紧邻；
- `split_words` 增加条件：仅 `split_mode ∈ [chars, words]`（符号列表/
  分段词列表）时显示；
- `regex` 保持仅 `split_mode == regex` 时显示。

## 三、主配置「恢复默认值」按钮（新功能）

### 需求确认

插件配置页本就有逐项恢复默认按钮，主配置文件页没有。用户确认：
**只需要填空类（string/text/list/dict 手填）与数值类（int/float）显示
恢复按钮**，开关、下拉、特殊选择器一律不显示，避免到处是按钮。

### 实现

**后端（astrbot/dashboard/services/config_service.py）**

- `ConfigProfileService` 新增 `_inject_metadata_defaults(metadata, defaults)`：
  递归为 metadata 叶子项注入 `default`（按点路径从 DEFAULT_CONFIG 取值）；
  取不到（动态项/特殊项）不注入，前端据此不显示按钮；
- `get_profile_schema()` / `get_system_schema()` / `get_profile()` 返回
  metadata 前统一注入；
- 补上 DEFAULT_CONFIG 缺失的 `provider_settings.fallback_max_context_tokens
  = 128000`（hint 本就写「默认 128000」，代码兜底也是 128000）。

**前端（dashboard/src/components/shared/AstrBotConfigV4.vue）**

- 引入 `ConfigDefaultReset` 组件（插件配置复用），包住输入控件；
- 新增 `shouldShowReset(itemMeta)`：仅对 string/text/list/dict/int/float
  且非 readonly/非 _special/非 options（下拉）的项启用；
- `@reset` 走 `setValueBySelector(iterable, itemKey, v)` 写回主配置对象；
- 值等于默认时按钮自动隐藏（ConfigDefaultReset 内部比较），仅改动过的项出现。

### 修复：list 配置项默认值注入失败

- **现象**：新配置目录登录后「管理员 ID」「唤醒词」出现恢复按钮，点击变空；
- **根因**：注入函数把 `admins_id`、`wake_prefix` 这类 list 项自带的
  `items: {type: string}`（元素描述）误当嵌套配置递归，lookup 失败不注入，
  前端拿不到 default 便用类型兜底值 `[]` 当「默认」；
- **修复**：仅 `type == 'object'` 的 items 才递归，list/dict 一律当叶子注入；
- **验证**：`admins_id` 默认 `["ldm"]`、`wake_prefix` 默认 `["/"]` 正常注入。
