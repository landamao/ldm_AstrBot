# [2026-09-03] 内置指令参数类型手动转换与友好错误提示

> 本文件为独立变更日志，记录 builtin_stars/builtin_commands 全量指令的
> 参数处理优化：不管框架传入 int 还是 str，指令内部手动尝试转换目标类型，
> 转换失败时返回友好清晰的中文提示（带参数名、实际输入值、用法说明）。

---

## 一、背景与设计

框架的参数类型转换只在带类型注解且解析成功时生效，实际传入值可能是
int、str 或 None，指令内部此前多处用 `isinstance(x, int)` 硬分支判断，
数字串 "3" 会被误判为非法，或直接落到「无效的参数」这类无信息量的提示。

本次改造思路（不依赖框架转换，指令内部自己兜）：

1. 新增共享工具模块 `commands/utils/param_utils.py`，三个函数全部返回
   `(值, 错误提示)` 二元组，错误提示为空字符串表示成功：

   - `转整数(raw, 名称, *, 最小值=, 最大值=)` — 兼容 int/str/bool/None，
     转换 + 范围校验一体；bool 显式拒绝（避免 True 被当成 1）；
   - `转整数或None(...)` — 可选数字参数版，raw 为 None 或空串时返回
     `(None, "")` 不报错（如 /switch 省略序号时引导输入）；
   - `校验非空(raw, 名称)` — strip 后判空。

2. 错误提示统一格式：`「名称」需要是数字，输入的是「实际值」。`、
   `「名称」不能小于 N。`、`请输入名称。`——参数名用「」括住、
   回显用户实际输入，用户能直接看出哪里错了。

3. 序号类参数转换成功后统一检查上界，超范围时提示总数
   （如「模型序号超出范围，共 N 个。」），替代笼统的「序号错误」。

## 二、各指令改动明细

### provider.py

| 位置 | 改动 |
| --- | --- |
| `provider()` 主分支 | 删除 `isinstance(idx, int)` 硬分支，统一走 `转整数(idx, "提供商序号", 最小值=1)`——框架传 str "3" 现在能正确切换；转换失败时给完整用法（切换/检测/tts/stt 四种用法一并列出）；超出数量提示总数 |
| `provider tts/stt` | idx2 缺失时提示具体用法（原来只有「请输入序号。」）；idx2 走 `转整数` 转换 + 上界检查 |
| `model_ls()` | 删除 `isinstance(idx_or_name, int)` 硬分支，先 `转整数` 试数字编号（成功则按序号切换+上界检查），失败再按模型名处理；空模型名有独立提示 |
| `key()` | index 走 `转整数` 转换 + 上界检查；帮助文案 `<idx>` 改 `<序号>` |

修复的实际 bug：`/provider 2`、`/model 2`、`/key 2` 这类数字序号用法，
在框架把参数传成字符串的场景下会落到「无效的参数」/「模型名查找」分支。

### conversation.py

| 位置 | 改动 |
| --- | --- |
| `his()` / `convs()` | page 走 `转整数(page, "页码", 最小值=1)`，非数字页码（如 `/history abc`）给「「页码」需要是数字，输入的是「abc」。」 |
| `switch_conv()` | 删除 `isinstance(index, int)` 硬判断（原实现里 str "3" 会直接被「类型错误」拒绝——但框架传的可能就是 str），改 `转整数或None`；省略参数引导输入，非数字带原因提示，超范围提示总数 |
| `groupnew_conv()` | sid strip + 缺参提示改为「使用方法：/groupnew <群聊ID>」 |
| `rename_conv()` | new_name strip + 缺参提示带用法 |

### alter_cmd.py

`reset scene` 的场景编号：手写的 `isdigit() + int() + 范围拼接` 替换为
`转整数(scene_num_raw, "场景编号", 最小值=1, 最大值=3)`，超范围时提示
「「场景编号」不能大于 3。」而不是笼统的「必须是 1-3 之间的数字」
（两种错误原因现在能区分开）。

### llm.py

`sid` / `操作` 入口统一 `str(x or "").strip()`——兼容框架传 int 的场景
（如 `/llm 123456 -q` 框架把 123456 传成 int），原实现直接用会导致
列表查找失效。

### image.py

`model()` 缺参提示拆分：只缺模型ID、只缺提示词、都缺三种情况分别提示
（原来合并成一条，用户不知道自己漏了哪个）。

### admin.py

`op` / `deop` / `wl` / `dwl` 的 admin_id / sid 入口统一
`str(x or "").strip()`，兼容框架传 int。顺手删除 `up_ldm()` 里未使用的
`import importlib`。

### plugin.py

`plugin_off/on/get/restart/update/help` 的 plugin_name / plugin_repo
入口统一 `str(x or "").strip()`。

### setunset.py

- `set_variable()`：key / value 加 str+strip，缺变量名、缺变量值分别提示
  带用法（`/set <变量名> <值>`）；
- `unset_variable()`：key 缺失时提示 `/unset <变量名>`（原来没有缺参拦截）。

### name.py

`alias` 用 `str(alias or "")` 包裹后再传 `normalize_umo_name`，兼容 None/int。

### persona.py

- `view` 缺参提示带用法（`/persona view <人格名>`）；
- 人格不存在提示：`人格「xxx」不存在。使用 /persona list 查看所有人格。`
  （原来是不带引导的「人格xxx不存在」/「不存在该人格情景」）。
