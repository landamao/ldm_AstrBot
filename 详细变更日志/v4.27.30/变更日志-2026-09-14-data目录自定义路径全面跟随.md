# [2026-09-14] data 目录自定义路径全面跟随：插件导入命名空间映射、CLI 与日志路径修正

> 本文件为独立变更日志，记录 2026-09-14 一次 data 目录硬编码全面审查与修复：
> 魔改支持 `LDMBOT_DATA_DIR` / `--data-dir` 后，插件仍固定按逻辑包名 `data.plugins.*`
> 去源码树 `data/` 导入；CLI 多处写死 `root/"data"`；插件日志标签字面量匹配
> `"data/plugins"`。本次注入命名空间包映射逻辑包名到实际 data 目录，CLI 统一走
> 路径 getter，日志改为 realpath 对照。

---

## 问题现象

1. 设置 `LDMBOT_DATA_DIR=D:/foo/data_xxx`（或启动参数 `--data-dir`）后，插件物理
   目录正确解析到 `data_xxx/plugins`，但加载插件时仍报 `ModuleNotFoundError`，
   或在源码树默认 `data/plugins` 里找同名插件；
2. 若默认 `data/` 与自定义目录两边都有同名插件，会**静默加载默认目录的插件**，
   自定义目录里的改动不生效；
3. `astrbot plug` / `conf` / `init` 等 CLI 命令仍读写 cwd 下的 `data/`，与主程序
   实际使用的 data 目录不同步；
4. 自定义 data 目录下插件打日志时标签为 `[Core]` 而非 `[Plug]`。

## 根因

### 问题 1 / 2：插件导入逻辑包名与物理路径脱节

- 插件模块历史上固定导入为 `data.plugins.<目录名>.<模块>`，该字符串写死在
  `star_manager.py` 多处（加载、卸载清理、LLM 工具归属判断）；
- `main.py check_env()` 只把 `get_astrbot_root()`（源码根）插入 `sys.path`，
  不会把自定义 data 目录的**父目录**插入；
- Python 按包名 `data` 在 `sys.path` 上查找 → 始终解析到 `<源码根>/data/plugins`，
  与 `get_astrbot_plugin_path()` 返回的物理路径无关；
- DB / `shared_preferences` 中已持久化 `data.plugins.xxx` 形式的 module_path，
  不能直接改逻辑包名，否则存量数据失效。

### 问题 3：CLI 写死 `root/"data"`

- `cli/utils/basic.py` 的 `get_astrbot_root()` 只返回 `Path.cwd()`，
  完全忽略 `LDMBOT_DATA_DIR` / `LDMBOT_ROOT`；
- `cmd_plug` / `cmd_conf` / `cmd_init` / `cmd_run` 均用 `root / "data"` 拼路径。

### 问题 4：日志路径字面量匹配

- `log.py _is_plugin_path` 判断 `"data/plugins" in norm_path`，
  自定义目录名（如 `data_xxx/plugins`）永远匹配不上。

## 修复内容

### P0：逻辑包名映射到实际 data 目录（`astrbot_path.py`）

- 新增 `ensure_plugin_module_importable()`：向 `sys.modules` 注入命名空间包
  - `data` → `get_astrbot_data_path()`
  - `data.plugins` → `get_astrbot_plugin_path()`
- 逻辑模块名仍为 `data.plugins.xxx`，不改 DB / shared_preferences 存量数据；
- 已存在且带 `__file__` 的真实包不会被覆盖；路径一致时幂等复用；
- 调用点：
  - `main.py check_env()`：启动即注入；
  - `star_manager.load()`：加载前兜底；
  - CLI `cmd_run`：CLI 启动路径同步注入。

### P1：CLI 统一解析 data 路径

- 新增 `cli/utils/basic.py resolve_cli_data_path()`：
  1. 从项目根 `bootstrap_env`（加载 `.env`）；
  2. 优先 `LDMBOT_DATA_DIR`，其次 `LDMBOT_ROOT/data`，最后 `<cwd>/data`；
  3. 未显式配置时默认 `LDMBOT_ROOT=<项目根>`，与 `main.py` 行为一致。
- 接入：
  - `cmd_plug.py`：`_get_data_path()` 改用 resolver；
  - `cmd_conf.py`：`cmd_config.json` 读写改用 resolver（并 `mkdir` 父目录）；
  - `cmd_init.py`：初始化目录按 resolver 结果创建；
  - `cmd_run.py`：不再无条件覆盖已有 `LDMBOT_DATA_DIR` / `LDMBOT_ROOT`；
    启动日志输出实际 data 目录。

### P2：日志插件标签跟随实际目录

- `log.py _is_plugin_path`：改为 `get_astrbot_plugin_path()` /
  builtin_stars 的 realpath 前缀对照（`normcase` 兼容 Windows）；
- 失败时退回宽松关键字匹配作兜底。

### 关联修复

- `io.py extract_dashboard`：默认 `extract_path` 从相对 cwd 的 `"data"` 改为
  `None` → `get_astrbot_data_path()`；
- `process_restart.py`：frozen 应用重启时除 `--webui-dir` 外一并保留
  `--data-dir`（环境变量子进程继承，CLI 参数原先会丢）。

## 部署/测试注意

- 需重启 ldm 生效（导入命名空间在启动期注入）；
- 默认 data 目录行为不变；仅 `LDMBOT_DATA_DIR` / `--data-dir` / `LDMBOT_ROOT`
  指向非源码树 `data/` 时路径解析发生变化；
- 无配置项变更、无存量数据迁移；已持久化的 `data.plugins.*` module_path 继续有效；
- CLI（`astrbot plug` / `conf` / `init`）在自定义 data 目录下需与主程序使用相同
  环境变量 / `.env`，否则仍按 cwd 下 `data` 解析。
