# [2026-09-14] plugin 指令显示名匹配：按显示名定位插件，模糊命中给候选不执行

> 本文件为独立变更日志，记录 2026-09-14 一次 `/plugin` 指令组增强：
> on / off / restart / update / help 五个子指令的插件名参数支持显示名精确匹配直接执行、
> 模糊命中不执行并返回候选提示、候选统一「显示名（插件名）」格式并附可复制指令。

---

## 问题现象

1. 插件的真实插件名（如 `astrbot_plugin_stealer`）与显示名（如 `表情包小偷`）不一致时，
   直接输显示名会报「插件名不存在」，必须先 `/plugin ls` 查到内部插件名再复制；
2. 插件名输错或只记得一部分时，也只有一句「插件名不存在」，不知道相近的候选有哪些、
   该用哪个名字继续操作。

## 方案设计

- 新增统一解析器 `_resolve_plugin`，五个带插件名参数的子指令（on / off / restart /
  update / help）全部走它，匹配优先级：
  1. 插件名精确命中 → 直接执行（原行为不变，优先级最高）；
  2. 显示名精确且唯一命中 → 直接执行；
  3. 显示名精确但命中多个 → 不执行，返回编号候选列表；
  4. 模糊匹配（插件名与显示名做不区分大小写的包含匹配）：
     - 唯一命中 → 不执行，返回「你可能要……的插件是」提示 + 完整可复制指令；
     - 多个命中 → 不执行，返回编号候选列表；
  5. 全无命中 → 原有「插件名不存在」提示。
- 候选展示格式统一「显示名（插件名）」，无显示名的插件用插件名补位
  （如 `astrbot_plugin_xxx（astrbot_plugin_xxx）`），括号内的值即需要复制的插件名。
- 修复顺带问题：原先直接拿用户输入调 `turn_off_plugin` / `reload` / `update_plugin`，
  现统一改用解析后的真实插件名，执行与回复、日志一致。

## 实现内容

### 后端（`builtin_commands/commands/plugin.py`）

- 新增 `_resolve_plugin(plugin_name, command, action, tail)`：返回 (插件元数据, 提示文案)，
  提示非空时由调用方直接发送、不执行操作；提示中的指令前缀实时取当前第一个唤醒词；
- 新增 `_plugin_label`（统一候选标签格式）与 `_multi_match_hint`（编号候选列表）；
- 五个子指令接入解析器；restart / update 的执行、回复与日志改用解析后的真实插件名；
  help 的多结果尾句为「即可查看插件帮助」（`tail` 参数区分动词搭配）；
- `/plugin` 指令组帮助末尾新增提示：`<插件名>` 也可填插件的显示名（需完全一致），
  模糊命中时会给出候选列表。

提示文案示例（唯一模糊命中 / 多命中，`help` 同结构）：

```text
你可能要重启的插件是
→ 表情包小偷（astrbot_plugin_stealer），
使用
→ /plugin restart astrbot_plugin_stealer
重启
```

```text
匹配到多个结果：
1.表情包小偷（astrbot_plugin_stealer）
2.表情包制作（astrbot_plugin_maker）
请确认后使用
→ /plugin restart <括号内的值>
即可重启插件
```
