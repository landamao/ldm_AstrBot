# [2026-10-11] 插件查询已注册指令 API（Context.get_all_commands）

> 本文件为独立变更日志，记录给插件暴露「获取所有已注册指令 / 已启用指令」方法的设计与用法。

---

## 动机

插件此前只能通过 `context.get_all_stars()` 看到插件列表，拿不到指令层面的信息：想知道某个指令名是否已被占用、哪些指令当前处于启用状态、某条指令被指令管理重命名成了什么，都没有正规入口。指令管理的原始数据其实一直存在（`command_management.py` 的描述符体系，面板 `/command/list` 在用），只是没有暴露给插件侧。

## 设计

- **复用指令管理描述符**：不新造数据结构，直接复用 `command_management.py` 的 `CommandDescriptor`（指令名、别名、描述、所属插件、权限、启停、指令组/子指令标记等字段齐全），并在 `astrbot.api.star` 导出该类供插件做类型标注。
- **同步、无 DB 访问**：指令管理中的启停/重命名/别名变更都会实时应用到运行时注册表（`_apply_config_to_runtime`），插件加载时也有 `sync_command_configs()` 兜底同步，因此纯读注册表即为权威状态，方法做成同步函数，插件在任何时机都能直接调用。
- **插件级禁用一律过滤**：已禁用插件注册的指令在两种模式下都不返回（沿用 `_collect_descriptors` 的既有语义）；「已启用」指指令本身在指令管理中处于启用状态。

## 用法

```python
class MyPlugin(Star):
    # 所有已注册指令
    cmds = self.context.get_all_commands()
    # 仅已启用的指令
    active = self.context.get_all_commands(only_enabled=True)

    for cmd in active:
        cmd.effective_command   # 生效名（重命名后）
        cmd.aliases             # 别名列表
        cmd.description         # 描述
        cmd.plugin_name         # 所属插件名
        cmd.permission          # everyone / admin
        cmd.enabled             # 是否启用
        cmd.is_group / cmd.is_sub_command
```

内部实现：`Context.get_all_commands()` → `command_management.collect_commands(only_enabled)`（懒导入防循环）。`CommandDescriptor` 同步导出至 `astrbot.core.star`、`astrbot.api.star`、`astrbot.api.all`。

## 测试

`tests/test_get_all_commands.py`：注册表造数据（启用/禁用指令、指令组+子指令、事件监听类、禁用插件），断言收集范围、enabled 过滤、子指令父组回链、`Context` 入口与导出一致性，finally 清理全局注册表。
