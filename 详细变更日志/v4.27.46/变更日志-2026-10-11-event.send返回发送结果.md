# [2026-10-11] event.send() 返回发送结果（MessageSendResult）

> 本文件为独立变更日志，记录 send() 返回值的设计取舍、透传链路与各平台覆盖范围。

---

## 动机

`await event.send(chain)` 此前返回 `None`，插件拿不到任何发送回执。而协议端其实是有响应的——OneBot 的 `send_group_msg` / `send_private_msg` 响应里本就带 `message_id`，只是适配器把它丢掉了。拿消息 ID 是高频需求（后续撤回、引用回复、表情回应等都依赖它），为此打通一条从协议端响应到插件手里的透传链路。

## 设计取舍：统一包装，不纯透传

返回值有两种做法：直接把平台原生响应透传给插件（OneBot 下是 dict），或者包一层统一结构。**定案为统一包装**，理由：

- 纯透传时拿 ID 的写法按平台分叉：OneBot 是 `result["message_id"]`，telegram/discord 是 `result.message_id` 属性，跨平台插件没法统一判断，且返回类型沦为 `Any`。
- 包装后 `result.message_id` 是唯一需要记住的字段（统一转字符串）；同时 `result.raw` 字段**原样保留平台原生响应**——纯透传的能力一点没丢，只是多了一个统一入口。

```python
result = await event.send(chain)
mid = result.message_id if result else None   # 拿消息 ID，跨平台写法一致
raw = result.raw if result else None          # OneBot 下即 {"message_id": 123}
```

## MessageSendResult（astrbot/core/platform/message_send_result.py）

dataclass，两个字段：

- `message_id: str | None` — 平台侧消息 ID，统一 `str()`；平台未提供时为 None。
- `raw: Any` — 平台原生返回值（OneBot 为响应 dict，WebChat 为入队负载），未提供时为 None。

导出两处：`astrbot/core/platform/__init__.py` 与 `astrbot/api/platform/__init__.py`，插件 `from astrbot.api.platform import MessageSendResult`。

## 透传链路实现

### 基类（astrbot/core/platform/astr_message_event.py）

`send()` 签名从 `-> None` 放行为 `-> MessageSendResult | None`。基类实现不做平台发送（只记日志与累计已发送文本），**始终返回 None**；是否透传取决于平台适配器重写。docstring 写明这一约定，未透传结果的平台返回 None。

### aiocqhttp（用户主平台，完整透传）

- `_dispatch_send` 三个分支（群聊 `send_group_msg` / 私聊 `send_private_msg` / event 兜底 `bot.send`）全部 `return` 协议端响应。
- `send_message` 返回协议端原生响应（Any）。消息链被拆分为多次发送时（Node/Nodes 合并转发、File 与普通消息混排），**返回最后一次发送的响应**；全空白链被过滤、未发送任何东西时返回 None。
- `send()` 经 `_to_send_result` 包装：dict 且含 `message_id` 则取值转字符串，其余情况 `message_id=None`、`raw` 原样；raw 为 None（未发送）整体返回 None。

### WebChat

返回本地生成的 `message_id`（前端侧 ID，非平台回执），`raw` 为入队负载。WebChat 无平台侧响应，这是能拿到的最大信息量。

### 其余 15 个平台适配器

本次未动，`send()` 返回 None，行为与之前完全一致。后续要支持的照 aiocqhttp 模式补：适配器拿响应 → 包 `MessageSendResult(message_id=…, raw=…)`。

## 兼容性

- **纯增量改动**：框架内全部 `send()` 调用点（`process_buffer`、`react`、各适配器 `send_streaming`、pipeline 的 respond/waking_check/context_utils 等）都忽略返回值，行为不变；老插件不受任何影响。
- 其他平台适配器的 `-> None` 注解覆写基类的新签名，Python 运行时不检查注解，无兼容问题。

## 测试（tests/test_send_result.py，7 用例全过）

aiocqhttp 群聊/私聊响应包装与 message_id 转字符串、空链未发送返回 None、合并转发经 `call_action` 的响应透传、转发与普通消息混排返回最后一次响应、WebChat 本地 message_id、基类返回 None。

全量回归 393 项通过；7 项失败（test_image_command 1、test_plugin_display_name_match 5、test_provider_health_check 1）经干净树（stash 改动后）复跑确认均为预存问题，与本次改动无关。

## 回归点

- 新平台适配器支持发送结果时，包 `MessageSendResult` 后返回，别直接返回原生响应。
- 混排拆分发送的「返回最后一次响应」语义是定案：插件拿到的 ID 对应消息链中最后一个成功发送的段。
- aiocqhttp 的 `_dispatch_send` / `send_message` 返回类型是协议端原生值（Any），包装只发生在 `send()` 这一层；直接调 `send_message` 的调用方（如 webhook 场景）拿到的是原生响应。
