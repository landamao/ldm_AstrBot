# 变更日志 — 2026-11-12 — 插件页面两种打开方式（新标签页 / 仪表盘内嵌）

## 背景

插件自带的 Web 页面（`pages/` 下的自定义页面）此前只能在**新标签页**打开，点进去就离开了仪表盘，侧边栏、顶部状态、其它插件页面全部断开；在手机上更麻烦，标签页来回切，回到仪表盘还得重新找位置。

同时旧实现里 `PluginPagePage.vue` 接近 700 行，页面本体、路由参数、标题/favicon 处理、返回逻辑全揉在一起，想加一种打开方式只能复制一份。

## 改动

### 1. 打开方式偏好（`src/views/extension/pluginPageOpenMode.mjs`）

- localStorage 键 `astrbot.pluginPageOpenMode`，取值 `tab`（新标签页）/ `embed`（仪表盘内嵌），**默认 `tab`**。
- `normalizePluginPageOpenMode`：未知取值（历史脏数据、手改过的值）一律回落到 `tab`，不会因为一个坏值打不开页面。
- `readPluginPageOpenMode` / `writePluginPageOpenMode`：存储不可用（隐私模式、`localStorage` 被禁用、`getItem` 抛异常）时静默降级为默认值，不抛错。
- `getPluginPageRouteName`：把打开方式映射到路由名（`tab` → 独立页面，`embed` → 内嵌页面）。

### 2. 全局共享的偏好与统一的打开入口（`usePluginPageOpenMode.js`）

- 模块级 `ref` 保存打开方式，**插件页面列表、插件卡片、插件详情页共用同一份偏好** —— 在任一入口切换，其它入口立即跟随，不必各自读一遍 localStorage。
- `resolvePluginPageTarget(router, pluginName, pageName, mode)`：统一解析目标路由。
- `openPluginPage(...)`：`embed` 走 `router.push`（当前标签页内路由跳转）；`tab` 走 `window.open(target.href, "_blank", "noopener,noreferrer")`（保留原来的新标签页行为，并保留 `noopener` 安全属性）。

### 3. 内嵌路由与页面拆分

- 新增 `PluginPageEmbedded` 路由，挂在 `FullLayout` 下 —— 内嵌打开时**侧边栏、顶部栏都在**，看上去就是仪表盘的一个普通页面；`PluginPageRoutes.ts`、`MainRoutes.ts`、`routeConstants.mjs` 同步新增路由常量。
- `PluginPagePage.vue` 由 698 行瘦身为薄包装，页面主体拆到 `src/views/plugin-page/PluginPageView.vue`（827 行），两种打开方式共用同一份渲染逻辑。
- 内嵌模式的差异处理：
  - **不接管** `document.title` 与 favicon（避免把整个仪表盘的标签页标题改成插件页面名）；
  - 顶部加一条工具栏：左侧「返回」回插件列表，右侧「在新标签页打开」一键切到独立页面；
  - 独立页面模式行为不变（接管标题、无内嵌工具栏）。

### 4. 交互细节

- 插件页面每张卡片：**右上角置顶**一个新标签页图标（快速以独立页面打开），卡片下方两个并列按钮「新标签页 / 页面内」；头部提供默认打开方式的分段开关，切换即持久化。
- tooltip 改为**受控显隐**：点击即收 —— 路由跳转后 `mouseleave` 可能丢失，旧实现会让提示框一直挂在屏幕上。
- 插件页面卡片 hover 上浮 + 粉影、默认方式分段按钮 `scale` 恢复全局 Q 弹动画（`_override.scss`）。

### 5. i18n 与单测

- `features/extension.json` 补充打开方式、内嵌工具栏、自定义仓库等文案。
- 新增 `tests/pluginPageOpenMode.test.mjs` 6 例：默认值、读取已保存的 `embed`、未知值回落、写入与受限存储、路由名映射、`embed` 判定。
