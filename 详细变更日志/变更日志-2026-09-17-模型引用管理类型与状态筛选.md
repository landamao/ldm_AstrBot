# [2026-09-17] 模型引用管理新增类型与状态筛选：快速定位某类模型或异常配置

> 本文件为独立变更日志，记录 2026-09-17 模型引用管理页筛选能力增强：
> 在原有「来源（主配置/插件）」筛选基础上，新增「模型类型」与「状态」
> 两个下拉筛选，可单独或叠加使用，异常/未配置项不再需要肉眼翻找。

---

## 背景与问题现象

1. 模型引用管理页此前只有一个搜索框和「全部来源 / 主配置 / 插件」的来源下拉；
   想看「所有 Agent 执行器类型的引用」或「所有已失效的配置」时，只能在扫描
   结果里逐条肉眼翻找，插件多、配置档案多时非常低效；
2. 页面顶部虽有「失效 N 处」统计芯片，但点不了、不能按它过滤，看到数字
   之后还是得自己找是哪几处。

## 改动内容

### 新增两个筛选下拉（`dashboard/src/views/ModelUsagePage.vue`）

- 筛选栏在原有「来源」下拉后新增：
  - **模型类型**：按扫描结果动态生成选项，实际出现了哪些类型才列哪些；
    「对话」「Agent 执行器」固定排最前，其余类型（生图、语音识别、
    语音合成、向量、重排等）跟在后面；
  - **状态**：正常 / 已失效 / 未配置 / 全部状态，文案直接复用表格
    状态列，与页面显示口径完全一致。
- 三个筛选（来源 / 类型 / 状态）与搜索框、批量模式可自由叠加；
- 类型筛选与批量模式的类型锁、表格「类型」列同一数据口径
  （`provider_type`，插件疑似引用兜底项按对话类型处理），不会出现
  筛出来的类型和列里显示的对不上；
- 实现：`filteredUsages` 过滤链新增类型与状态两段判断；原
  `usageTypeLabel` 拆出通用的 `providerTypeLabel(type)` 供筛选选项
  与行内类型芯片共用。

### 文案（`dashboard/src/i18n/locales/zh-CN/features/model-usage.json`）

- `page.filter` 新增 `typeAll`（全部类型）、`statusAll`（全部状态）；
- 状态筛选项文案复用已有的 `page.table.statusOk / statusInvalid / statusEmpty`。

## 修改文件清单

1. `dashboard/src/views/ModelUsagePage.vue`
2. `dashboard/src/i18n/locales/zh-CN/features/model-usage.json`

## 验证

- 前端 `bash ~/构建部署.sh` 构建部署通过；
- 打包产物确认包含新增文案（`grep 全部状态` 命中 dist 产物）。

## 部署注意

- 纯前端改动，dist 已部署，重启 ldm 后刷新页面即生效；
- 使用方式：打开模型引用管理页 → 点「开始扫描」→ 用筛选栏的组合下拉
  过滤，例如「状态=已失效」直接列出所有失效引用，「类型=Agent 执行器 +
  来源=插件」只看插件侧的执行器配置。
