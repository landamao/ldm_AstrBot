# [2026-09-26] 主模型失败回退开关：可单独锁定某个模型不回退；LLM 请求失败错误中文化

> 本文件为独立变更日志，记录「开启主模型失败回退」配置项与 LLM 请求失败错误文案中文化。另见同日「模型无正文时重新请求」一篇（本配置项同时作为其回退闸门）。

---

## 问题现象

回退模型链一旦配好就总是生效：想临时固定用某个模型完成任务（即使它出错也不切换），只能破坏已配好的回退链，回头还要重新配置。另外模型请求失败时用户可见的错误是英文框架文案（`Error occurred during AI execution. / Error Type: ... / Error Message: ...`、`All chat models failed: ...`）。

## 实现内容

### 配置项

**开启主模型失败回退**（`enable_main_model_fallback`，bool，默认开），位于 WebUI「配置-AI」的「对话模型链」正下方。hint：开启后，模型请求失败将依次请求回退模型。关闭后，主模型失败就抛出错误。

### 运行时行为（astr_main_agent.build_main_agent）

- 开关开启：维持现状——主模型失败按 `fallback_chat_models` 顺序依次尝试。
- 开关关闭：`fallback_providers` 清空，任何失败（请求异常、错误响应、无正文重试耗尽）都在主模型上终局并抛错；用户收到中文错误说明。
- 与 WebChat 消息级 `enable_fallback` extra 开关叠加：两者任一关闭即不回退。
- 主模型不支持图片输入时原本会借回退链找可用图像模型；开关关闭后不再借道，与「即使出错也不要回退」的意图一致。

### 错误文案中文化（用户可见面）

| 位置 | 原文 | 现文 |
| --- | --- | --- |
| runner 最终错误 | `All chat models failed: ...` | `所有对话模型均请求失败：...` |
| runner 无候选 | `All available chat models are unavailable.` | `所有可用的对话模型均请求失败。` |
| 通用执行错误（astr_agent_run_util） | `Error occurred during AI execution.\nError Type: ...\nError Message: ...` | `AI 执行过程中出现错误。\n错误类型: ...\n错误信息: ...` |
| 第三方执行器错误（third_party.py） | `Error occurred during AI execution.\n... (3rd party)` | `AI 执行过程中出现错误。\n错误类型: ... (第三方执行器)` |
| internal 管线兜底 | `Error occurred while processing agent request: ...` | `AI 执行请求时出现错误: ...` |
| DeerFlow 执行器 | `DeerFlow request failed: ...` | `DeerFlow 请求失败：...` |
| runner 切换/空输出日志 | 英文 warning | 中文化（排查日志更直观） |

错误详情格式化收敛到 `_format_llm_error_detail`：框架自有异常（AstrBotError 系，文案本身已中文）只展示消息，第三方 SDK 异常保留「异常类名: 原始信息」便于排查。SDK 原始错误消息本身（英文）作为技术细节保留。
