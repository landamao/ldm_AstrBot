# [2026-09-17] 火山引擎生图提供商接入：方舟 Seedream 原生协议适配

> 本文件为独立变更日志，记录 2026-09-17 新增火山引擎（火山方舟 Ark）Seedream 生图提供商：
> 文生图/图生图统一走方舟 JSON 接口（不走 OpenAI 的 /images/edits multipart），
> 不发送 `n` 参数而是映射为组图 `max_images`，并按 pro/lite/4.5/4.0 模型能力族
> 在请求前做本地校验，避免无效请求消耗额度。

---

## 背景

ldmbot 原有生图提供商只有「OpenAI 兼容生图」一个类型。火山方舟 Seedream 的
`/images/generations` 虽然路径相同，但协议差异明显：

1. 图生图不接受 multipart `/images/edits`，而是把参考图放进 JSON `image` 字段
   （URL 或 `data:image/...;base64,...`）；
2. 不支持 OpenAI 的 `n` 参数，多张生成要用 `sequential_image_generation=auto` +
   `sequential_image_generation_options.max_images`，且语义是「上限」而非「保证数量」；
3. 不同模型能力差异大：pro 不支持组图/流式/联网搜索，透明背景只有 pro 支持，
   output_format 仅 5.0 pro/lite 支持，各模型的尺寸档位与总像素范围都不同；
4. 响应里单张图可能失败（组图部分成功），URL 24 小时过期，编码格式可能是 JPEG。

用 OpenAI 兼容适配器硬套这些行为（比如发 `n`、无脑请求 edits、把 JPEG 标成 PNG）
都会产生无效请求或错误展示，因此单独做一个原生协议适配器。

## 新增内容

### 火山引擎生图适配器（`astrbot/core/provider/sources/volcengine_image_generation_source.py`，新增）

- 注册类型 `volcengine_image_generation`，显示名「火山引擎生图」，继承
  `ProviderOpenAIImageGeneration` 复用会话管理、代理、密钥管理和健康检查框架，
  因此 ChatUI 生图会话、`/image` 指令、LLM 生图工具的现有 isinstance 判断全部兼容，
  无需改动这些调用方；
- 请求协议独立实现：
  - 文生图、单图编辑、多参考图、组图统一 POST `{api_base}/images/generations`，
    Bearer 鉴权，JSON 请求体；
  - 参考图转 data URL，单张传字符串、多张传数组，不走 multipart；
  - 数量参数 `n` 映射为 `sequential_image_generation=auto` +
    `sequential_image_generation_options.max_images`（上限语义，prompt 中说明即可，
    不保证数量）；
  - 不发送 `n`、`seed`、`negative_prompt`、`steps` 等方舟不存在的字段。
- 模型能力族按每个模型实例独立配置，不由整个提供商共用：
  - 在单个模型的新增/编辑窗口选择「自动识别」或手动选择 pro/lite/4.5/4.0；
  - 手动选择优先，只有选择 auto 时才按当前模型 ID 的前缀自动识别；
  - 自动识别支持 `doubao-seedream-5-0-pro-*`、`*-5-0-lite-*`、`*-5-0-*`、
    `*-4-5-*`、`*-4-0-*`；Endpoint ID 或无法识别的 ID 需手动选择，否则报错；
  - 同一提供商下的模型互不影响；不继承源级残留能力族，模型未设置时按 auto 处理。
- 请求前本地校验（不发起网络请求即拦截，省额度）：
  - 参数白名单：只允许方舟文档列出的可选参数，不认识的参数直接拒绝；
  - 尺寸校验：pro 支持 1K/1.5K/2K，lite 支持 2K/3K/4K，4.5 支持 2K/4K，
    4.0 支持 1K/2K/4K，或传精确 `宽x高`（按各模型的总像素范围与宽高比 1/16～16
    校验，总像素是宽×高，不是单边长度）；
  - 参考图校验：格式白名单（jpeg/png/webp/bmp/tiff/gif/heic/heif）、每张 ≤30MB、
    宽高 >14px、总像素 196～36,000,000、宽高比 1/16～16，pro 最多 10 张、
    其他 14 张；Pillow 本地 verify，HEIC/HEIF 不强制本地解码（环境通常缺插件），
    交给服务端校验；
  - 组图校验：pro 不支持组图（发了就报错，不静默降级单图）；lite/4.5/4.0 的
    参考图数 + max_images 合计 ≤15；`max_images` 必须是 1～15 整数；
  - 特性专属校验：透明背景仅 pro（且需单张带透明通道的非 JPEG 输入、
    不能配 jpeg 输出），output_format 仅 5.0 pro/lite，联网搜索 tools 仅 lite
    （参数必须精确为 `[{"type": "web_search"}]`），optimize_prompt_options 仅
    支持 mode 且 lite/4.5 不支持 fast；watermark/stream/layer_decomposition
    必须是布尔值；尺寸可在 `ark_image_options.size` 中配置，也可由单次请求指定；
  - 流式（SSE）与图层拆分本轮未实现：`stream=true` 拒绝，pro 拒绝任何 stream
    参数；lite/4.5/4.0 允许 `stream=false`。出现 `layer_decomposition` 参数即拒绝，
    不静默降级。
- 配置读取方式：每次请求现读 `ark_image_options` 并深拷贝，不污染原配置；
  `custom_extra_body` 在该类型下禁用（防止绕过能力校验覆盖 model/prompt/image）。
- 响应处理：
  - 先查 HTTP 状态，再查顶层 `error`，再逐张查 `data[].error`，不只看 HTTP 成功；
  - 顶层错误保留错误码和说明，并限制展示长度，避免直接吞掉错误原因；
  - 组图部分失败（某张 error）时保留已成功图片并记 warning 日志，不整体作废；
  - 每张图实际探测格式（verify + load），JPEG 不再被误标为 PNG；
  - URL 结果下载不带方舟 Authorization（下载域名与 API 域不同，凭据不外带）；
  - 失败不自动重试（避免超时/断连时重复提交收费请求）。

### 配置入口（`astrbot/core/config/default.py`）

- 「服务提供商 → 生图」新增提供商源模板「火山引擎生图」：
  - `api_base` 预填 `https://ark.cn-beijing.volces.com/api/v3`；
  - 源级保留 `ark_image_options`（生图参数 dict，支持 size/watermark/
    response_format/output_format 快捷项，高级参数如 tools、optimize_prompt_options
    通过修改按钮编辑）；能力族 `ark_model_family` 已移到单个模型的新增/编辑窗口；
  - 模型实例的「模型」填方舟模型 ID（如 `doubao-seedream-5-0-pro-260628`）
    或 Endpoint ID。
- 同步补了前端翻译 `dashboard/src/i18n/locales/zh-CN/features/config-metadata.json`
  的 `ark_model_family` / `ark_image_options` 描述与提示（后端 schema 会转成
  i18n 键，缺翻译会显示空白，2026-09-17 已实踩并修复）。

### 尺寸留空与 PNG 编码预设

- 移除尺寸输入框的 `2K` 预填，不替用户固定生成尺寸；
- 未配置尺寸，或尺寸为空字符串、空白、null 时，请求不发送 `size`，交由方舟模型
  默认处理；主动填写时才发送指定尺寸，单次请求指定值优先于配置值；
- 「图片编码格式」的添加预设由 JPEG 改为 PNG（无损编码），仍可手动改为 JPEG
  （有损编码）；该预设只影响配置编辑，不会自动向每个请求注入 `output_format`；
- 未添加 `output_format` 时仍由方舟决定编码，不能将 UI 的 PNG 预设理解为所有
  输出已强制变成 PNG。该参数仅 5.0 pro/lite 支持；
- 不擅自覆盖已保存的尺寸或 JPEG 设置，需要用户在配置中主动清空或修改。

### 适配器注册（`astrbot/core/provider/manager.py`）

- `dynamic_import_provider` 新增 `case "volcengine_image_generation"`；
- 实例化走现有 `ProviderType.IMAGE_GENERATION` 分支，复用默认生图提供商选择、
  健康检查及模型列表调用机制；
- 合并提供商源与模型配置时，能力族只读取模型自己的设置，忽略旧源中的同名字段。

## 使用方式

1. WebUI「服务提供商 → 生图」新增提供商源，模板选「火山引擎生图」，
   填入方舟 API Key（key 列表，支持多 Key）；
2. 在该源下添加模型实例，「模型」填官方模型 ID 或 Endpoint ID；在该模型的
   新增/编辑窗口配置「火山模型能力族」，可自动识别或手动选择，手动选择优先。
   Endpoint ID 或无法识别的模型需手动选择实际能力族，不影响同源其他模型；
3. 「火山生图参数」里按需配置尺寸、水印、响应格式等。尺寸留空不发送，
   主动填写才限制尺寸；添加「图片编码格式」时预设 PNG，可改 JPEG，
   不添加则不发送该参数。已保存的旧值需要手动调整；
4. 聊天会话切到该生图模型即可正常生图；WebUI「测试」按钮会真实生成
   「请生成一只猫。」（产生真实生图费用），成功时日志打印图片绝对路径。

## 部署/测试注意

- 后端 + 前端均已通过一键脚本部署，需手动重启 ldm 生效；
- 「火山生图参数」为空时显示「暂无项目」是 dict 编辑器的通用空态
  （与「自定义请求体参数」一致），点「修改」即可添加键值对，不是渲染故障；
- 生图测试与实际使用都会产生真实费用；组图数量是上限，实际张数以返回为准，
  未成功输出的图片不计费；
- 未接 SSE 流式与图层拆分：`stream=true` 拒绝，pro 不允许配置 stream；其他
  支持非流式的模型允许 `stream=false`。`layer_decomposition` 参数当前不接受；
- 模型能力族调整后，旧源级能力族不再生效；使用 Endpoint ID 的旧模型需到该模型
  的编辑窗口重新选择能力族。已保存的尺寸或编码格式不会被自动改写。
