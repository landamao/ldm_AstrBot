# 变更日志 — 2026-10-30 — WebUI 对话模型链编辑体验重构

## 背景

配置页的「对话模型链」编辑器（`ChatModelChainSelector.vue`，v4.27.56 后新增的自研组件，非上游 AstrBot 自带）上线后暴露一串交互问题：

1. **拖拽兼容性差**：拖拽排序走浏览器原生 HTML5 DnD（`draggable` + `dragstart/dragover/drop`），在部分浏览器（Safari、内嵌 webview）与触屏上不触发或拖拽影像异常。
2. **整条可拖导致按钮点不到**：`draggable="true"` 挂在整个 `v-list-item` 上，按住行内任意位置都进入拖拽状态，右侧上移/下移/× 按钮的 click 在 mousedown 阶段就被拖拽吞掉（`@click.stop` 与 `z-index` 都救不了，事件根本走不到 click）。
3. **点击有"回弹"**：全局主题 `_override.scss` 给所有 `.v-list-item:active` 加了 `transform: scale(0.96)` 的 Q 弹按压动效，按下缩小、松开弹回；且 CSS `:active` 会波及祖先链——按 × 按钮时条目本体也在缩放晃动。叠加 Vuetify 默认的 hover/focus 蒙层（`.v-list-item__overlay`，0.2s 淡入淡出），条目看起来一直在"闪"。
4. **弹窗功能缺失**：「添加模型」弹窗里的已选链条目只有 × 删除，没有上移/下移，调序必须退出弹窗回主列表操作。

## 改动

全部改动集中在 `ldmbot-dashboard/src/components/shared/ChatModelChainSelector.vue`（前端独立仓库），主仓库只收构建产物 `dashboard/dist/`。

### 1. 拖拽整体换成 Sortable.js

- 用项目已有的 `sortablejs@1.15.7`（插件排序同款），**不新增依赖**。
- 关键配置：
  - `forceFallback: true` — 不走原生 DnD，用鼠标/触摸事件模拟克隆体跟随指针，全平台一致；
  - `handle: '.drag-handle'` — 只有 `#prepend` 里的手柄 `span` 能发起拖拽，`dragstart/dragend` 挂在手柄上，`dragover/drop` 仍留在条目上（这两个事件不依赖 `draggable`，整行作为落点）；
  - `fallbackOnBody: true` — 克隆体挂 body，避免被弹窗内 `max-height + overflow-y:auto` 的滚动容器裁剪；
  - `fallbackTolerance: 3` — 移动超过 3px 才算起拖，压住手抖误触；
  - `animation: 180` + `ghostClass/chosenClass/dragClass` — 原位虚线占位框、按下高亮、拖起阴影。
- 删除了全部原生拖拽代码（`draggingIndex/dragOverIndex/dragInsertBefore` 状态、`resolveInsertIndex/updateDragIndicator/onDragStart/onDragOver/onListDragOver/onDrop/onListDrop/onDragEnd`）。

### 2. Sortable 直接改 DOM 与 Vue 的冲突处理

Sortable 的 `onEnd` 时真实 DOM 已被挪到新位置，虚拟 DOM 顺序仍是对的旧顺序。处理方式：

```js
onEnd(evt) {
  const { oldIndex, newIndex } = evt
  revertDom(evt)                     // 把 item 按 oldIndex 插回原位（from.children[oldIndex]）
  if (oldIndex == null || newIndex == null || oldIndex === newIndex) return
  applyReorder(oldIndex, newIndex)   // 再改数据，交给 Vue 重排
}
```

`revertDom` 先撤销 Sortable 的 DOM 变动、让虚拟 DOM 与真实 DOM 重新对齐，再更新数据由 Vue patch 到新顺序——顺序没变时 Vue 不动，正好停在撤回后的样子。这是 vuedraggable 内部的同款思路。

配套把 `v-for` 的 key 从 `chain-{id}-{index}` 改成 `chain-{id}`（链条 computed 已去重，id 唯一）：索引参与 key 时重排会整列卸载重建，稳定 key 才有平滑的位移动画。

### 3. Sortable 实例生命周期

两个列表（页面内主列表 + 添加模型弹窗内列表）各一个实例：

- `v-list` 是 `v-if` 渲染（链条为空时不存在）、v-dialog 内容懒加载，所以用 `watch([mainListEl, dialogListEl])` 在元素出现/消失时同步；
- 同步时比对「实例绑定的元素 !== 当前元素」，元素被替换或卸载就销毁重建，避免对话框关掉再打开后实例还绑在已销毁 DOM 上、拖不动；
- `onBeforeUnmount` 兜底销毁。

### 4. 条目点击反馈全部关闭

- `_override.scss` 的全局 Q 弹按压：组件内加 `.v-list-item.chain-item:active { transform: none !important }`，特异性 (0,4,0) 压过全局 `.v-list-item:not(.v-list-item--disabled):active` 的 (0,3,0)。条目与按钮祖先链都豁免，其他列表不动。
- Vuetify hover/focus 蒙层：`.chain-item :deep(.v-list-item__overlay) { display: none }`（蒙层是 Vuetify 内部渲染的元素，scoped 下必须 `:deep()`）。
- 涟漪：`:ripple="false"`。
- 刻意**不加**空的 `@click.stop`：`onClick` 进 attrs 会让 Vuetify 的 `link.isClickable` 判定为可点击，给条目挂上 `--link` 类、pointer 光标并把涟漪启用回来，等于把要关的效果请回来。
- `.chain-item` 自身的 transition 里去掉 `transform`（Sortable 用 transform 做位移动画，CSS transition 会叠加拖慢半拍）。

### 5. 弹窗补齐上移/下移按钮

弹窗内链条目的 `#append` 从单个 × 扩成与主列表一致的三按钮容器（↑ ↓ ×），复用 `move(index, ±1)` / `removeAt(index)` 与已有 i18n 键 `moveUp/moveDown/remove`；首项禁用 ↑、末项禁用 ↓。

## 边界与兼容

- 纯前端变更，核心 Python 代码零改动；无新增/移除配置项。
- WebUI 静态资源响应头为 `Cache-Control: immutable, max-age=1y`，更新后浏览器需强制刷新才能看到新版。
- 拖拽行为变化：只有手柄能拖是**有意为之**（防止整条误拖），条目本体点击无任何效果。
- 其他使用 `v-list-item` 的界面（会话列表、插件排序卡片、文件夹树等）的按压/悬停动效不受影响。
- `dashboard/dist/version` 与 `dist/assets/version` 均为无 `v` 前缀的裸版本号（与 4.27.56 之后的 `preserveDistVersion` 插件行为一致，两文件写同一值）。

## 回归点

下次动这个组件或相关全局样式时注意：

1. **不要给这两个列表的 `v-list-item` 加任何 click 监听（包括空的 `@click.stop`）**——会激活 Vuetify 的 clickable 判定，涟漪/pointer 光标全部回来。
2. **不要给 `.chain-item` 的 transition 加回 `transform`**——会和 Sortable 的位移动画叠加。
3. **key 必须保持稳定（纯 providerId）**——加回 index 会让重排时整列重建、拖拽动画丢失。
4. 若上游合并时 `ChatModelChainSelector.vue` 有冲突，以本仓库版为准（上游无此组件）。
5. `_override.scss` 的 Q 弹按压是全站风格，将来若要给别的不可点击列表关按压，复制本组件的特异性写法即可，别去改全局。
