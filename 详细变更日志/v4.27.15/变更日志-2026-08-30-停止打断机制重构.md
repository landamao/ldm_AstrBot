# 停止/打断机制重构

## 问题

1. WebUI ChatUI 未完成的会话离开重进后，发送按钮没有变成停止按钮
2. 手动停止的消息没有"已停止"提示显示
3. 停止不写入对话数据导致重试不了
4. stop 和打断的提示文案可配置且中文，应改成不可配置的英文系统提示
5. WebUI 配置页仍显示 interrupt_reply 配置项
6. 停止不写入用户主动停止的提示到上下文
7. 工具调用期间停止，上下文不记录工具调用，LLM 不知道工具被停止过
8. 工具有结果后停止仍继续请求 LLM
9. 侧边栏多选删除会话没有全选按钮

## 改动

### 后端

**`astrbot/core/agent/runners/tool_loop_agent_runner.py`**
- `_finalize_aborted_step`：当 `llm_resp.role != "assistant"` 时（流式模式下 LLM 响应 role 为 "tool"），重建 LLMResponse 时保留 tools_call_name/tools_call_ids/tools_call_args 等所有工具调用字段
- `_finalize_aborted_step`：当有 tool_calls 时，写入 assistant 消息（含 tool_calls）+ 为每个工具调用生成一条 tool 角色消息，内容为英文 system_reminder 提示工具被中断
- `step()` 开头：工具执行完毕后如果用户已停止，直接 yield aborted + return，不再发起新 LLM 请求

**`astrbot/core/pipeline/process_stage/method/agent_sub_stages/internal.py`**
- `_save_to_history`：不再因 agent_force_stop 跳过落库，保存已发送内容 + 停止标记
- `_apply_interrupt_to_messages`：
  - 新增 `llm_response` 参数，WebChat 流式路径 delivered 为空时从 llm_response.completion_text 取已产出文本
  - `has_tool_results` 检查：消息序列中有 role="tool" 时完整保存上下文（不裁剪 tool_calls 和 tool 结果），只在最终回复后追加停止标记
  - 没有 tool 结果但有 tool_calls 的 assistant：按正常裁剪逻辑（不保留未执行的 tool_calls）
  - `_is_llm_reply_fully_delivered`：不再在 runner_aborted=True 时直接返回 False，正常比较 delivered 和 original
- `_get_interrupt_reply_config`：打断功能仍可配置（enable/enable_private/enable_group/notify_user/notify_text/wait_timeout），但 context_text 固定英文不可配置
- `_maybe_interrupt_active_reply`：notify_user 仍可配置
- `_apply_interrupt_to_messages` 和 `_maybe_interrupt_active_reply`：停止/打断提示文案固定英文，用 `<system_reminder>` 包裹

**`astrbot/core/astr_agent_run_util.py`**
- abort 路径不再因 force_stop 丢弃缓冲内容

**`astrbot/core/pipeline/respond/stage.py`**
- `_should_stop_sending`：agent_force_stop 不再跳过发送，已生成内容仍投递给用户

**`astrbot/core/platform/sources/aiocqhttp/aiocqhttp_message_event.py`**
- `_should_stop_sending`：同上

**`astrbot/core/platform/astr_message_event.py`**
- process_buffer 循环：同上

**`astrbot/core/config/default.py`**
- 删除 interrupt_reply 中的 add_to_context 和 context_text 配置项（提示文案不可配置）
- metadata 对应删除

**`astrbot/dashboard/services/chat_service.py`**
- `stop_session`：cancel `_consume_chat_run` 的 task 并 await 完成
- `_consume_chat_run` CancelledError 分支：追加 stopped part + 立即 flush
- `BotMessageAccumulator.add_plain`：新增 chain_type="stopped" 处理

### 前端

- `startResumeStream`：用 sessionId + runId 双 key 存 activeConnections，isSessionRunning 正确返回

- `MessageDisplayBlock` 新增 "stopped" kind
- `buildMessageBlocks` 处理 stopped part
- `processStreamPayload` 处理 stopped chain_type

**`dashboard/src/components/chat/ChatMessageList.vue` / `StandaloneChat.vue` / `MessageList.vue`**

**`dashboard/src/components/chat/Chat.vue`**
- 侧边栏多选模式新增"全选"按钮，点击切换全选/取消全选

**`dashboard/src/i18n/locales/zh-CN/features/chat.json`**
- 新增 message.stopped 和 conversation.selectAll

**`dashboard/src/i18n/locales/zh-CN/features/config-metadata.json`**
