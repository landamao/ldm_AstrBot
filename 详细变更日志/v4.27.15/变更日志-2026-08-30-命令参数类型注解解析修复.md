# [2026-08-30] 命令参数解析尊重类型注解修复（对齐上游 PR #9866）

> 本文件为独立变更日志，记录 2026-08-30 一次命令参数解析修复：参数转换目标
> 由「默认值的运行时类型」改为「声明的类型注解」，默认值仅用于参数缺省时填充。
> 对齐上游 AstrBotDevs/AstrBot PR #9866（fix: respect type annotations when
> parsing command parameters），已按本仓库实际文件差异适配。

---

## 问题现象

指令处理器参数带注解时，转换结果与注解不一致：

- `text: str = None` 这类可选参数，用户输入 `123` 会被转成 `int 123` 传入
  处理器，而不是 `str "123"`（如按 QQ 号、学号等数字型字符串做参数时表现明显）；
- 纯注解无默认值的 `flag: bool`，旧逻辑里 `handler_params` 存的是注解 `bool`，
  转换分支未覆盖，会误落到 `callable(target)` 的 `bool("false") = True`，
  永远解析不出 `False`；
- 缺参时直接拿默认值当转换目标，注解信息被默认值覆盖。

## 根因

`command.py` 的 `init_handler_md()` 中，参数处理逻辑为：

```python
if v.default == inspect.Parameter.empty:
    self.handler_params[k] = v.annotation
else:
    self.handler_params[k] = v.default
```

即「有默认值就存默认值」，把默认值（运行时值）同时当作类型信息与缺省填充值。
`validate_and_convert_params()` 随后用 `isinstance(default, X)` 推断转换目标，
导致 `str = None` 参数的转换目标变成 None 的启发式分支（数字字符串转 int），
`str = "fallback"` 的转换目标变成 str，类型信息被默认值劫持。

## 修复内容

### 核心：注解优先，默认值分离

`init_handler_md()` 重写为三态：

| 参数形态 | handler_params 存储 | handler_param_defaults 存储 |
|---|---|---|
| 有注解（如 `text: str`） | 类型注解（转换目标） | 默认值（如有） |
| 无注解 + 非 None 默认值（如 `retries = 1`） | 默认值（保持旧行为，用运行时类型推断） | 默认值 |
| 无注解 + 无默认值或默认值 None | 空标记 `inspect.Parameter.empty` | 无 |

### 新增 `_convert_param()` 统一转换

- 无类型约束（None / 空标记 / Any）：保持旧启发式，数字字符串转 int；
- `str`：原样返回（数字字符串不再被转 int）；
- `bool`：正确解析 `true/false`、`yes/no`、`1/0`，非法值报类型错误；
- `Union` / `Optional`（`str \| None` 等）：解开 Optional 后仅剩一个非 None
  类型时递归转换到该类型，多类型联合保持原值；
- 普通类型：走构造函数转换（int/float/自定义类型）；
- 默认值回退：按默认值的运行时类型推断（bool 先于 int 判断，因 bool 是 int 子类）。

### 缺参与错误提示

- 参数缺失时从 `handler_param_defaults` 取默认值，无默认值才报「必要参数缺失」；
- `print_types()` 错误提示改为「注解标签 + 默认值」渲染（无注解无默认值显示 any），
  与上游一致。
