# 变更日志 — 2026-10-31 — 空唤醒提示词注入开关

## 背景

v4.27.42 起，仅 @ 机器人/@ 全体成员、或只发唤醒前缀这类**空唤醒**消息不再被跳过，`InternalAgentSubStage` 会往 `message_str` 补一条提示词：

```text
<system_reminder>The user woke you up with an @ mention but did not include any content.</system_reminder>
```

配上 [ldmpl-reself-at / 补回艾特自身](https://github.com/landamao/ldmpl-reself-at) 后，空唤醒会同时出现两份「你被 @ 了」的信息：

- 插件的 `on_waiting_llm_request` 在空文本上补出 ` @咪咪(myself) `；
- 框架注入的 `system_reminder` 也留在同一条消息里。

即：`@咪咪(myself) <system_reminder>The user woke you up with an @ mention...</system_reminder>`。

插件已经把「谁 @ 了你」表达清楚，框架这句英文提示纯属重复，故新增开关允许关闭。

## 改动

### 1. 注入开关（`astrbot/core/pipeline/process_stage/method/agent_sub_stages/internal.py`）

新增 `platform_settings.bare_wake_prompt.enable`（默认 `true`，保持现有行为）：

- `initialize` 时读入 `self.bare_wake_prompt_enable`，类属性默认 `True`，即使阶段未初始化（单元测试）也不会走偏。
- `_fill_bare_wake_prompt` 拆成两条路径：
  - 开：写 `event.message_str = _BARE_WAKE_PROMPT` 后照常请求，日志「补提示词后正常请求 LLM」；
  - 关：**不写** `message_str`，`_bare_wake` 标记照旧设置，日志「提示词注入已关闭，交由插件补全」。`_bare_wake` 不随开关变化——群聊上下文 `on_req_llm` 仍据此注入全部缓冲历史，空唤醒依然能接上上下文。
- 关闭时请求不立即放行，而是继续走管线（防抖 → `send_typing` → `on_waiting_llm_request` 钩子），**钩子结束后**再用新增的 `_has_message_content` 复查：
  - 插件补出了内容 → 正常请求 LLM；
  - 仍为空（没装插件/插件没补）→ 打 `skip llm request: bare wake prompt disabled and no plugin filled message_str` 后跳过，等同旧行为，不会把空消息发给模型。
- `has_valid_message` 判定复用同一个 `_has_message_content`，避免两处各写一遍判空。

复查放在钩子之后而不是入口处，是为了让 `on_waiting_llm_request` 的插件有机会先补内容；放在防抖之后，是为了让「空 @ 后在静默窗口内又发来文本」的情况仍按合并结果正常请求。

### 2. 配置项（`astrbot/core/config/default.py`）

- `DEFAULT_CONFIG.platform_settings.bare_wake_prompt = {"enable": True}`：存量配置在启动时由 `check_config_integrity` 自动补上，无需手动改 `cmd_config.json`。
- `CONFIG_METADATA_2`：`platform_group → platform_settings` 增加该对象（供平台配置页/校验使用）。
- `CONFIG_METADATA_3`：`ext_group`（扩展功能）新增「空唤醒提示词」分区，开关名「注入提示词」，hint 说明「装插件时可关闭」以及关闭后的行为。
- WebUI 文案：`ldmbot-dashboard/src/i18n/locales/zh-CN/features/config-metadata.json` 补 `ext_group.bare_wake_prompt` 的 description/hint，并同步构建 `dashboard/dist`（缺 i18n 会在页面上显示 `[MISSING: ...]`）。

配置保存后 `reload_pipeline_scheduler` 会重建各阶段，开关即时生效，无需重启进程。
