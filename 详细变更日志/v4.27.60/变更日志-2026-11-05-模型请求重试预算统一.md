# 变更日志 — 2026-11-05 — 模型请求重试预算统一（重试调成 1 就不再轮番轰炸）

## 背景

用户把「请求最大重试次数」调成 `1`，期望模型请求失败后就地放弃，但实际仍会被连续重试：同一个模型被反复打，接着两个模型轮番上阵，日志里一长串请求。要求修掉这种「调小了还在一直重试」的行为。

## 根因

`request_max_retries` 只管住了**最内层的一层**重试，上下还各压着两层各自记账、互不相干的重试，层层相乘：

### 1. SDK 隐身重试（最隐蔽，完全不受配置控制）

`openai_source.py` 与 `anthropic_source.py` 构造客户端时都没传 `max_retries`，而两个 SDK 的默认值都是 **2**（`openai._constants.DEFAULT_MAX_RETRIES = 2`、`anthropic._constants.DEFAULT_MAX_RETRIES = 2`）。

也就是说：AstrBot 以为「发了一次请求」，SDK 实际在 408/409/429/5xx 上自己又补发 2 次 —— **一次尝试 = 最多 3 个 HTTP 请求**。

实测对比（本地起一个固定返回 500 的服务，调用 `chat.completions.create`）：

```
默认(SDK 隐式重试): HTTP 请求次数 = 3
max_retries=0:     HTTP 请求次数 = 1
```

`request_max_retries=1` 被这条路径直接放大 3 倍。

### 2. `openai_source` 外层错误恢复循环硬编码 10 次

`text_chat` / `text_chat_stream` 里 `max_retries = 10` 是写死的，和配置毫无关系。外层循环负责的错误恢复（429 换 Key、上下文超长裁剪、图片降级、剥离工具）每命中一次就再发一轮请求，最多 10 轮。

### 3. 空输出/仅思考输出重试内置 3/5 次

`tool_loop_agent_runner` 的 `EMPTY_OUTPUT_RETRY_ATTEMPTS = 3`、`EMPTY_CONTENT_RETRY_ATTEMPTS = 5` 也不读配置。用户开了「模型无正文时重新请求」且方式是 `retry_current` 时，一个只吐思考内容不吐正文的模型会被连续打 **5 次**；失败后再切回退模型，又是 5 次 —— 这才是「轮番轰炸」最直接的来源。

### 4. 部分调用点根本没传 `request_max_retries`

`retry_provider_request` 在 `max_attempts=None` 时退回常量 `REQUEST_RETRY_ATTEMPTS = 5`。图片转述（`_ensure_img_caption`、引用图转述）、上下文压缩（`compressor`）、插件调用（`star/context.py`）、会话标题生成、知识库修复等调用点都没传参，于是即使配置是 1，它们仍按 5 次打。

用户配置里 `always_use_image_caption_provider = true`，每张图都要走转述模型 —— 这条路径的 5 次重试是最容易被感知到的。

### 叠加后最坏情况

`5 次空输出重试 × 3 次 SDK 隐式重试 = 15 个请求/模型`，再加一个回退模型 = **一次逻辑请求最多 30 个 HTTP 请求**。配置里的 `1` 完全没体现出来。

## 改动

### 1. 统一预算解析入口（`astrbot/core/provider/sources/request_retry.py`）

新增 `resolve_request_max_retries(max_attempts=None, *, source)`：

- 显式传入的值优先（保持原有调用约定）；
- 未传入时读全局 `provider_settings.request_max_retries`，读不到才退回内置 5；
- 统一 `min_value=1`，非法/布尔/字符串走原有 `coerce_int_config` 告警路径。

`_build_retrying` 改走该入口，于是**所有**忘记传参的调用点（图片转述、压缩、插件调用、标题生成、模型列表拉取……）自动遵循 WebUI 设置，不再各自退回硬编码 5 次。

### 2. 关掉 SDK 隐式重试（`openai_source.py`、`anthropic_source.py`）

`AsyncOpenAI` / `AsyncAzureOpenAI` / `AsyncAnthropic` 全部加 `max_retries=0`，把重试权唯一交给 `retry_provider_request`。

因为 `groq / longcat / openrouter / xai / xiaomi / aihubmix / ssycloud / openai_responses` 都继承 `ProviderOpenAIOfficial`，一处改动全部覆盖。TTS / STT / embedding 源本次未动（它们没有 AstrBot 层的重试策略，保留 SDK 重试更稳）。

### 3. 去掉硬编码的 10 次（`openai_source.py`）

`text_chat` / `text_chat_stream` 的 `max_retries = 10` 改为 `resolve_request_max_retries(request_max_retries, ...)`，失败日志从「重试 N 次仍然失败」改为「共尝试 N 次仍失败」（原文案把总次数说成了重试次数）。

### 4. 空输出重试计入同一预算（`tool_loop_agent_runner.py`）

新增实例字段 `empty_output_retry_attempts` / `empty_content_retry_attempts`，取 `min(内置上限, 预算)`，`_stop_output_retry` 与两条告警日志同步改用新字段：

- 预算 1 → 只发 1 次，不再补发；
- 预算 2 → 最多 2 次；
- 未显式传预算（脚本/单测直接构造 runner）→ 仍用内置 3/5，保持原有行为。

### 5. 配置提示更新（`astrbot/core/config/default.py`）

`provider_settings.request_max_retries` 的 hint 改为说明「含首次请求、全链路统一生效」：填 1 = 失败不补发，填 2 = 首次失败后再试 1 次。

- 新增用例覆盖关键行为：
  - 本地 500 服务 + `text_chat(request_max_retries=1)` → **只发 1 个 HTTP 请求**（若 SDK 重试没关会是 3 个）；
  - `request_max_retries=3` → 恰好 3 个请求；
  - `retry_current` + 仅思考输出 + 预算 1 → 同一模型只请求 1 次并返回错误回复；
  - 预算 2 → 最多 2 次；预算未传 → 保持内置 5 次。

## 部署 / 测试注意

- 需重启 ldm 生效（`Provider.__init__` 里创建客户端，不重启不收 `max_retries=0`）；
- 语义变化：`request_max_retries` 现在是**单次逻辑请求的总尝试次数（含首次）**，全链路统一。以前填 1 实际会发好几次，现在填 1 就是一次；
- 权衡：预算 1 会连带关掉「需要再发一次才能生效」的降级路径（图片被拒后剥图重发、模型不支持工具后剥工具重发、上下文超长后裁剪重发、429 换 Key）。要保留这些降级能力请设 2（也是默认值）——1 次原始请求 + 1 次降级请求；
- 回退模型不在本次重试预算内：主模型失败后切到回退模型仍会各发 1 次（这是「主模型失败回退」功能本身）。要完全不切换，请关闭 `enable_main_model_fallback`；
- 若要彻底不重试同时保留降级，可把 `enable_empty_content_retry` 一起关掉，再按需调 `request_max_retries`。
