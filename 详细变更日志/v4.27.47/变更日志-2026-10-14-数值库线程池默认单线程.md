# [2026-10-14] 数值库线程池默认收敛到单线程（提交内存 2916 MB → 11 MB）

> 本文件为独立变更日志，记录 numpy / faiss 的 OpenMP / OpenBLAS 线程池默认值收敛的根因、落点与可覆盖性。

---

## 动机

内存排查中发现一个与业务无关、却比业务大得多的开销：进程的**峰值私有提交**达到 2831 MB，而常驻工作集只有约 449 MB。归因到 `import faiss` 与 `import numpy` 上：

| 库 | 16 核默认 | `OMP_NUM_THREADS=1` | `=4` |
| --- | --- | --- | --- |
| `import numpy` 提交增量 | 492 MB | **9 MB** | — |
| `import faiss` 提交增量 | 2424 MB | **17 MB** | 498 MB |

根因是这两个库在首次导入时按 CPU 核数创建 OpenMP / OpenBLAS 线程池，每个线程预留一大块私有 arena；16 核下 faiss 的单个 arena 就接近 150 MB。这些内存不计入常驻工作集（RSS），但会：

- 占满系统提交限额、推高页面文件占用；
- 触发 Windows 内存压缩（本机 `MemCompression` 进程已达 473 MB）；
- 让任务管理器的「提交大小」列出现 2.8 GB 这样的数字。

而机器人的实际数值负载极小：向量检索（本机表情包索引 533 条 × 4096 维）、余弦相似度、图片尺寸计算。多线程在这里收益接近于零，反而带来线程同步开销。

## 改动内容

新增 `astrbot/utils/runtime_env.py`：

```python
_THREAD_ENV_VARS = ("OMP_NUM_THREADS", "OPENBLAS_NUM_THREADS", "MKL_NUM_THREADS")

def apply_thread_env_defaults() -> None:
    for name in _THREAD_ENV_VARS:
        os.environ.setdefault(name, "1")
```

用 `setdefault` 而非直接赋值：**用户显式设置的值优先**。

调用点有两处，覆盖两条启动路径，位置都满足「`.env` 已加载」且「早于任何 numpy / faiss 导入」：

1. `main.py` — 紧随 `bootstrap_env(...)` 之后（`.env` 先落地，用户配置才能覆盖默认值；`astrbot.core` 尚未导入，插件与核心都还没机会 import numpy）。
2. `astrbot/cli/commands/cmd_run.py` 的 `run()` — 同样紧随 `bootstrap_env(...)`，与 main.py 路径保持一致。

时序关键点：线程池参数在库**首次初始化时读取一次**，之后再改环境变量不再生效。已实测「进程内设置后导入」同样有效（numpy 9 MB / faiss 8 MB），不依赖 shell 层预设。

## 实测效果

- 单测：`apply_thread_env_defaults()` 后 `import numpy, faiss`，提交增量 **11 MB**（改前 2916 MB）。
- 端到端：模拟真实启动（核心 + WebUI + 插件 + provider 实例化）后导入 numpy 与 faiss，提交增量 14 MB。
- 功能回归：加载真实 `emoji_faiss.index`（ntotal=533，dim=4096）并执行 `idx.search(q, 3)`，正常返回 3 个近邻。

## 兼容性

- **默认值可覆盖**：`.env` 里写 `OMP_NUM_THREADS=8` 即恢复多线程，`setdefault` 不会覆盖。
- **无功能变化**：只是线程数从「CPU 核数」变为 1；数值结果不受影响（浮点归约顺序变化可能带来极小的末位差异，但本项目的相似度检索对此不敏感）。
- **性能取舍**：若某插件做大规模数值计算（本地推理、批量矩阵运算），单线程会变慢——这类用户应按需调大该变量。框架自身无此类负载。

## 测试

- 全量 `pytest tests/` 408 项全过（该改动不影响既有测试，无新增测试——环境变量默认值属启动期行为，由上述探针与功能回归覆盖）。
- 探针脚本验证三个线程变量的 `setdefault` 语义、导入时序与提交内存增量。
- faiss 真实索引检索功能回归。

## 回归点

- **新增数值库导入点时不要早于 `apply_thread_env_defaults()`**。若将来有模块在 `main.py` 的早期导入段（`bootstrap_env` 之前）就 import numpy，该默认值会失效。
- 两条启动路径（`main.py`、CLI `cmd_run.py`）必须同步维护；新增第三条启动路径时记得一并调用。
- 新增环境变量已同步 `main.py --help` 与 `astrbot/utils/env_file.py` 的 `_ENV_EXAMPLE_SECTIONS`（「性能与内存」分节），两处需保持一致。

3. `astrbot/cli/commands/cmd_run.py` — 导入并在 `bootstrap_env()` 后调用
