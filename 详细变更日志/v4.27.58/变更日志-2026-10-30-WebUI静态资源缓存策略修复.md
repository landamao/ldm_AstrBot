# 变更日志 — 2026-10-30 — WebUI 静态资源缓存策略修复（index.html 强缓存一年）

## 背景

`astrbot/dashboard/api/static_files.py` 对**所有**静态文件（包括入口 `index.html`）一刀切返回：

```
Cache-Control: public, max-age=31536000, immutable
```

带内容 hash 的构建产物（`assets/index-xxx.js` 这类）用一年 immutable 长缓存是正确做法；但 **`index.html` 是入口页，文件名固定、内容会随发版变化**，它也被标记 immutable 后浏览器普通刷新根本不向服务器发起请求（immutable 语义即"缓存期内无需再验证"），导致：

- 发版部署新 dist 后，用户浏览器长期停留在旧入口页，引用旧资源；
- 部分场景下用户连 Ctrl+F5 都绕不开，本次上下文管理改版上线时实际撞上（用户强刷多次仍见旧页面）。

同时确认第二个隐患：`_ensure_gzip_file()` 只判断 `.gz` 是否存在、**不比对源文件 mtime**——凡是绕过 `emptyOutDir` 的部署方式（手动覆盖同名文件等）会一直返回旧的 gzip 内容。

## 改动

### 1. 缓存头按文件性质分流（`astrbot/dashboard/api/static_files.py`）

- 原统一常量 `_STATIC_CACHE_HEADERS` 拆分为：
  - `_ASSETS_CACHE_HEADERS`：`public, max-age=31536000, immutable`——仅用于 `assets/` 目录下的构建产物（文件名自带内容 hash，内容变即 URL 变，长缓存安全）；
  - `_ENTRY_CACHE_HEADERS`：`no-cache`——用于 `index.html` 入口与 `assets/` 之外的其他静态文件，每次都带 `etag` / `last-modified` 做条件请求协商，文件未变返回 304（开销极小），有更新立即拿到新版。
- `serve_index()` 固定使用入口缓存头；`serve_static_file()` 按路径前缀 `assets/` 分流。
- `FileResponse` 自带 etag/last-modified，`no-cache` 协商缓存无需额外实现。

### 2. gzip 缓存自动失效（`_ensure_gzip_file`）

- 读取源文件 `st_mtime`，`.gz` 存在但**比源文件旧**时重新压缩覆盖；
- 压缩在 `_GZIP_LOCK` 锁内完成，锁内以同一 mtime 口径 double-check，防并发重复压缩；
- `rm -rf` 重建 dist 的常规部署流程不受影响（gz 随目录清空重建）；手动覆盖同名文件的部署方式从此不再吐旧压缩包。

## 边界与兼容

- **一次性过渡**：浏览器里已存的旧 index.html 带着旧 immutable 头，需**最后一次硬刷新**（Ctrl+F5）换成本次的新响应；此后入口页永远走协商缓存，后续发版普通刷新即可见，不再出现"部署了但看不到"。
- `no-cache` ≠ 不缓存：响应仍会被存储，只是每次使用前必须向服务器验证（304 命中时仅传头部），实测体感无差异。
- `/api/*` 路由在静态通道路由前已拦截 404，不受影响；`version` / `assets/version` 保护逻辑不受影响。
- 纯后端行为变更，前端无需配合。

## 验证

- `py_compile` 通过；模块导入冒烟通过（`static_files.router` 正常挂载）。
- 重启后实测响应头：
  - `GET /` → `cache-control: no-cache`（带 etag / last-modified）；
  - `GET /assets/FullLayout-*.js` → `cache-control: public, max-age=31536000, immutable`。
- 实机回归：本次上下文管理 + 通知中心改版即靠本修复解决了"部署后强刷不可见"的问题。

## 修改文件清单

- `astrbot/dashboard/api/static_files.py`

## 回归点

- **回归一**：发版替换 dist 后，普通刷新（F5）即可加载新页面（index 走 304/200 协商，assets 因 hash 变化拉新文件）。
- **回归二**：手动覆盖某个静态文件（同名不同内容）后，gzip 版本随之更新，不会吐旧 gz。
- **回归三**：二次访问入口页时应看到 304（浏览器带 If-None-Match，服务器比对 etag 命中）。
