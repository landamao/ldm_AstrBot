# 变更日志 — 2026-10-30 — CLI 交互模式跳过横幅动画与插件覆盖安装确认

## 背景

两个独立问题：

1. **CLI 交互模式被横幅动画干扰**：`main.py` 的启动横幅动画有一套跳过判断（`_should_show_startup_banner()`），覆盖了 `--help`、`--reset-password`、`--rollback` 等交互式/短生命周期模式，但唯独漏了 `--restore-backup` / `--恢复备份`。恢复数据备份是完整的交互流程（列出备份包 → 输入序号 → 逐项 y/N 确认），横幅动画把提示和输入行冲出屏幕，输入时动画还在闪烁重绘，体验很差。
2. **插件安装同名冲突直接报死**：无论上传压缩包、GitHub/Git 仓库安装还是直链安装，只要插件目录下已存在同名目录，一律直接抛「安装失败：目录 xxx 已存在」。用户看不到新旧版本差异，也没有任何覆盖入口——只能先卸载再安装，而卸载会连带删配置/数据。

## 改动

### 1. `--restore-backup` 模式跳过横幅动画

`ldmbot/main.py` `_should_show_startup_banner()` 补上一个判断：

```python
if "--restore-backup" in argv or "--恢复备份" in argv:
    return False
```

横幅完全不启动，控制台直接进入交互。既有的 `--help`、`--reset-password`、`--rollback` 豁免与非 TTY / `LDMBOT_NO_BANNER=1` 判断均不受影响。

### 2. 同名插件冲突改为「覆盖确认 + 版本对比」

#### 2.1 核心层（`astrbot/core/star/star_manager.py`）

- 新增专用异常 `PluginAlreadyExistsError`：携带 `dir_name`（插件目录名）、`existing_version`（已安装版本）、`new_version`（待安装版本），与既有的 `PluginVersionUnsupportedError` 同级。
- 新增 `_read_plugin_version_info()`：宽松读取插件目录 metadata.yaml 的 name/version，不校验不抛异常（读不到返回 None，上层显示"未知"）——对比版本信息获取失败不应阻断安装流程。
- 新增 `_handle_existing_target()`：目标目录已存在时的统一处理。
  - `overwrite=False`：读出新旧版本后抛 `PluginAlreadyExistsError`；
  - `overwrite=True`：打日志后走 `_prepare_overwrite_target()`。
- 新增 `_prepare_overwrite_target()`：覆盖前移除旧插件——先按 name/root_dir_name 双路找到已注册实例，`_terminate_plugin()` 终止 + `_unbind_plugin()` 解除注册（**不删配置和数据**），再 `remove_dir()` 删除旧代码目录，保证随后的 load 是干净安装。
- `install_plugin()`（仓库/直链安装）与 `install_plugin_from_file()`（上传压缩包安装）都新增 `overwrite: bool = False` 参数，把原来直接 `raise Exception("安装失败：目录 xxx 已存在。")` 的分支替换为 `_handle_existing_target()` 调用。
- `install_plugin()` 的异常处理为 `PluginAlreadyExistsError` 单开分支：**清理临时下载解压目录后原样上抛**，不进 `failed_plugin_dict`（同名冲突不是安装失败，不应在"失败插件"面板留垃圾记录；`install_plugin_from_file` 路径沿用原有 `skip_failed_tracking` 标志达成同样效果）。

#### 2.2 Dashboard 服务层（`astrbot/dashboard/services/plugin_service.py`）

- `install_plugin()` / `install_plugin_upload()` 读取并透传 `overwrite`；捕获 `PluginAlreadyExistsError` 转 `PluginServiceWarning`：

  ```python
  {
      "warning_type": "plugin_exists",
      "can_ignore": True,
      "plugin_name": exc.dir_name,
      "current_version": exc.existing_version,
      "new_version": exc.new_version,
  }
  ```

  与「ldm 版本不满足」（`astrbot_version_unsupported`）警告同走一条 warning 通道，`_run_service()` 统一返回 `status: "warning"`。

#### 2.3 API 层（`astrbot/dashboard/api/plugins.py` + `schemas.py`）

- `/plugins/install/github`、`/plugins/install/git`、`/plugins/install/url` 三个 JSON 路由从请求体透传 `overwrite`；`PluginInstallRequest` 模型新增 `overwrite: bool | None`。
- `/plugins/install/upload`（multipart 表单）从 form 读取 `overwrite` 字段透传，与 `ignore_version_check` 同款处理。

#### 2.4 WebUI 前端（`ldmbot-dashboard`）

- `useExtensionPage.js`：
  - 新增 `overwriteConfirmDialog`（show / pluginName / currentVersion / newVersion）；
  - `handleInstallResponse()` 新增 `warning_type === "plugin_exists"` 分支：填充版本信息、弹覆盖确认对话框；
  - `newExtension(ignoreVersionCheck, overwrite)` / `performInstallRequest({ ..., overwrite })`：file 路径往 FormData 追加 `overwrite`，URL 路径往 payload 加 `overwrite`；
  - `confirmOverwriteInstall()`（带 `overwrite=true` 重发安装）/ `cancelOverwriteInstall()`。
- `ExtensionPage.vue`：新增覆盖确认对话框，`v-table` 对比「已安装版本 / 待安装版本」（读不到显示"未知"），确认按钮 warning 色，persistent 防误关。
- i18n（`src/i18n/locales/zh-CN/features/extension.json`）：`dialogs.overwriteInstall.*` 文案，标题定为**「插件已安装冲突」**——避免"插件已安装"被误解为"上传的插件已经装好了"；实际含义是：本地已存在同名插件，与本次要装的包发生冲突。

## 边界与兼容

- 覆盖安装只替换插件代码目录，**插件配置（data/config）与数据文件保留**；如需彻底清除仍走「卸载」并勾选删除配置/数据。
- 覆盖有固有风险：旧目录已删、新包依赖安装或加载失败时旧版本不可自动回滚（对话框 hint 已提示）；确认弹窗 persistent，不会误触。
- 版本信息读取失败（新包 metadata 损坏等）不阻断流程：对话框显示"未知"，用户仍可选择覆盖或取消。
- API 向后兼容：`overwrite` 缺省为 False，旧客户端行为与原来一致（同名冲突报错）；新字段对旧客户端无影响。
- 横幅豁免只影响 `--restore-backup`：正常启动、`--rollback` 等既有行为零变化。

## 验证

- 改动的 5 个 Python 文件（main.py、star_manager.py、plugin_service.py、api/plugins.py、schemas.py）`py_compile` 全部通过。
- `vue-tsc --noEmit` 类型检查 + `vite build` 通过，产物输出至 `dashboard/dist`（WebUI 版本文件写回与 `astrbot/__init__.py` 一致）。
- 实测链路：上传 `astrbot_plugin_kktts` 压缩包（本地已装 v1.1.0）→ 弹出覆盖确认对话框，"已安装版本 v1.1.0 / 待安装版本 v1.1.0" 正确显示。

## 回归点

1. **不要把覆盖确认做成静默覆盖**：`overwrite` 缺省必须为 False，任何新安装入口都要走"先警告再确认"链路。
2. `_prepare_overwrite_target()` 刻意不走 `uninstall_plugin()`——卸载会删配置/数据，覆盖语义是"换代码、留数据"。将来若要加"覆盖时清配置"选项，应新增参数而不是复用卸载。
3. `PluginAlreadyExistsError` 在 `install_plugin()` 里有独立的清理+上抛分支，新增 except 时注意顺序（必须在泛化 `except Exception` 之前）。
4. 上传安装失败时服务端临时 zip 不删除（`plugin_upload_<filename>` 固定路径），前端确认覆盖后重新上传会覆盖同一临时文件，属预期行为。
