# 变更日志 — 2026-10-30 — 上下文管理策略重构（三条件触发压缩，移除全部自动截断）

## 背景

旧上下文管理有几个互相纠缠的问题：

1. **自动截断直接丢历史**：轮数超限先硬截断、压缩后仍超限对半截断、压缩失败回退按轮截断——三条路径都会**无声无息地丢掉对话原文**，对用户来说历史突然"被吃掉"了，极不可接受。
2. **配置项语义混乱**：
   - 「轮次超限时一次丢弃轮数」（`dequeue_context_length`）填 0 会被内部钳制成 1（`min(max(1, 0), ...)`），"0=关闭"根本不成立；
   - 「压缩时保留最近对话轮数」（`llm_compress_keep_recent_rounds`）大于 0 时**完全忽略**「压缩时保留最近上下文比例」（`llm_compress_keep_recent_ratio`），比例配置形同虚设；
   - 「历史超限时的处理方式」要在截断/压缩里二选一，选截断就是灾难。
3. **默认不设防**：`max_context_length` 默认 -1（不限制），新装用户一直聊会撞穿模型窗口。

目标语义（与用户逐项确认后确定）：**对话轮数 / 上下文长度（绝对 token） / 模型窗口百分比三个条件独立判断，任一命中即触发一次 LLM 压缩**（保留最近 N 轮原文，更早轮次生成摘要替换）；填 0 或 -1 表示该条件不参与判断；**自动路径不保留任何截断行为**。

## 改动

### 1. 核心三件套（`astrbot/core/agent/context/`）

#### `config.py` — ContextConfig 重构

- `max_context_length: int = 60`：轮数上限，超过即触发压缩，<= 0 关闭该检查；
- `context_max_tokens: int = -1`（**新增**）：绝对 token 预算，超过即触发压缩，<= 0 关闭；
- `context_compress_threshold: float = 0.8`：占模型窗口比例阈值，<= 0 或 >= 1 关闭；
- 删除 `enforce_max_turns`、`truncate_turns`、`llm_compress_keep_recent_ratio`；
- `llm_compress_keep_recent_rounds: int = 5`：压缩保留的最近原文轮数。

#### `manager.py` — 统一判定 + 压缩，无任何截断

- 新增 `check_limits(messages, trusted_token_usage)`：三条件独立判断，返回触发原因（如 `turns 62 > limit 60` / `tokens ... > budget ...` / `tokens ... > 80% of window ...`），轮数判断用 `split_into_rounds`（与压缩器同一套轮次口径）；token 只计一次，绝对值与比例两个条件共用。
- `process()`：`check_limits` 命中 → 调压缩器；**无压缩器或压缩无效果（返回原消息列表/消息数未减少）→ 原样发送 + `logger.warning`**；压缩后仍超限只告警"不截断继续发送"，不再对半截断。
- 删除原第一步的轮数硬截断（原 `truncator.truncate_by_turns` 调用）与压缩后 `truncate_by_halving` 兜底。
- 压缩器选择：有 `llm_compress_provider`（或自定义压缩器）→ 压缩；没有 → 原样发送 + 警告。**不再回退 TruncateByTurnsCompressor**。

#### `compressor.py` — LLMSummaryCompressor 只按轮数保留

- 构造签名：`(provider, keep_recent_rounds=5, instruction_text=None, compression_threshold=0.8, token_counter=None)`；删除 `keep_recent_ratio`。
- `_split_recent_rounds()` 取代 `_split_recent_rounds_by_token_ratio()`：精确保留最近 `keep_recent_rounds` 个整轮，更早轮次进摘要；`<= 0` 时全部进摘要；保留"最后一条用户消息所在整轮永不进摘要"的保护（活跃请求）。
- 新增 `last_error: str | None`：压缩失败原因（调用模型失败/空摘要），供上层写通知；`__call__` 开头重置。
- `TruncateByTurnsCompressor` 类保留（仅 `/compact yes` 手动路径使用）；`should_compress` 方法保留但管理器不再调用（防插件外部引用）。

### 2. 装配层

- `tool_loop_agent_runner.py`：`reset()` 参数删 `enforce_max_turns` / `truncate_turns` / `llm_compress_keep_recent_ratio`，新增 `context_max_tokens` / `max_context_length`；ContextConfig 构造同步；上次请求 token 快照（`_context_usage_snapshot`）复用条件删除 `enforce_max_turns == -1` 前提——压缩会改变消息前缀，指纹不匹配时自然不复用，逻辑等价且更简单。
- `astr_main_agent.py`：`MainAgentBuildConfig` 删 `context_limit_reached_strategy` / `llm_compress_keep_recent_ratio` / `dequeue_context_length`，新增 `context_max_tokens: int = 128000`，`max_context_length` 默认改 60；`_get_compress_provider()` 删除 strategy 前置判断（压缩模型不可用时返回 None，由 ContextManager 走"原样发送"）；`reset` 传参同步。
- `pipeline/.../internal.py`：配置读取同步（`max_context_length` 默认 60、新增 `context_max_tokens` 默认 128000），删除 `dequeue_context_length` 及其"钳制"逻辑；`MainAgentBuildConfig` 构造同步。
- `builtin_commands/commands/conversation.py`（`/compact`）：删除 `dequeue_context_length` 读取（手动截断 `drop_turns` 写死 1）、`LLMSummaryCompressor` 调用删 `keep_recent_ratio`；**`/compact yes` 手动按轮次截断逃生门保留**（显式指令，非自动路径）。

### 3. 配置与面板（`core/config/default.py` + 前端）

- 默认值：`context_compress_threshold` 0.82 → **0.8**；`max_context_length` -1 → **60**；新增 **`context_max_tokens: 128000`**；删除 `context_limit_reached_strategy` / `llm_compress_keep_recent_ratio` / `dequeue_context_length`。
- 面板 metadata `truncate_and_compress` 组重写：三个触发条件（对话轮数上限 / 上下文长度上限 token / 最大上下文百分比阈值）+ 保留最近轮数 + 压缩提示词 + 压缩模型 + 窗口兜底值；组级 hint 写明"三条件任一命中即压缩、不自动截断"；旧 strategy 下拉与两条已删配置的条目移除；3253 行附近的旧类型声明区同步（`dequeue_context_length` → `context_max_tokens`）。
- 前端 `ldmbot-dashboard/src/i18n/locales/zh-CN/features/config-metadata.json` 同步文案。

## 边界与兼容

- **配置迁移自动化**：配置加载器启动时自动移除已删除的旧 key（实测输出 `Config key removed: provider_settings.context_limit_reached_strategy` 等三条）、自动补齐新 key 默认值——存量用户零手工迁移。
- **存量用户行为变化**：新增的 `context_max_tokens=128000` 与 `context_compress_threshold`（原 0.82 保留）立即生效，长对话不会再溢出模型窗口；`max_context_length` 若原本是 -1 则维持"轮数不判断"，想启用改 60。
- **压缩失败不丢数据**：压缩模型不可用/压缩失败/压缩无效果一律原样发送，极小概率超窗导致当次 API 报错，但历史零丢失（该行为的可观测性由同批新增的"重要通知系统"保证，见另一份变更日志）。
- **默认即开启**：新装用户默认 60 轮 / 128k token / 80% 窗口 / 保留 5 轮，不会出现默认关闭聊到溢出。
- `ContextTruncator`（`fix_messages` / `truncate_by_turns` / `truncate_by_halving`）整体保留：手动 `/compact`、消息修复等路径仍在使用。

- 假 provider 逻辑测试全过：

## 回归点

- **回归一**：长对话压缩链路——超过 60 轮或接近窗口时是否触发压缩、摘要是否生成、最近 5 轮原文是否保留、历史是否正确写回；压缩模型不可用时应原样发送且产生重要通知（而非报错或丢历史）。
- **回归二**：工具循环中多步调用的压缩时机（每步请求前都会判定）与 token 快照复用是否正常（上下文未变时复用真实 usage，压缩后指纹失效重新估算）。
- **回归三**：`/compact`（LLM 摘要）与 `/compact yes`（手动截断逃生门）行为不变。
- **回归四**：面板配置页显示新配置项、旧配置项不再出现；旧配置文件升级后自动清理。
