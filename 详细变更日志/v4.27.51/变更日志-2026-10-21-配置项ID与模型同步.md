# [2026-10-21] 配置项 ID 与 model 同步

> 本文件记录“配置项 ID = 来源/模型”这一约定的落地：切换模型不再改现有配置项的 `model`，启动时修复历史失配 ID，并同步所有引用。

---

## 动机

WebUI 添加模型时用 `{provider_source_id}/{model}` 生成配置项 ID，例如 `ldmapi/glm-5.2`、`懒大猫模型/test`。但旧版 `/model` 或 WebUI 编辑只改配置项的 `model` 字段，不改 ID，于是出现：

```json
{
  "id": "懒大猫模型/test",
  "provider_source_id": "懒大猫模型",
  "model": "喜欢懒大猫"
}
```

WebUI 对话模型链只显示配置项 ID，用户看到 `懒大猫模型/test`，会以为主模型是 `test`，实际发给上游的是 `喜欢懒大猫`。ID 和模型失配后，`/model` 按名字切换也容易改错配置项。

## 方案

### 1. 切换模型 = 选中或创建 `来源/模型` 配置项

- 输入模型名/编号后，按以下顺序解析：
  1. 配置项 ID 精确匹配（`/model ldmapi/glm-5.3`）；
  2. 配置项 `model` 精确匹配（`/model glm-5.3`）；
  3. 当前配置项的上游模型列表；
  4. 跨配置项的上游模型列表。
- 第 3/4 步命中的模型如果还没有配置项，按模板（同来源的现有配置项）自动创建 `来源/模型` 配置项，克隆连接配置，`max_context_tokens` 重置为 0 交给自动识别。
- 现有配置项的 `model` 字段不再被 `/model` 修改。

### 2. 启动修复历史失配 ID

`ProviderManager.initialize()` 在加载实例前调用 `_sync_provider_ids()`：

- 只处理 ID 以 `provider_source_id/` 开头的自动命名配置项；
- 期望 ID = `{provider_source_id}/{model}`，不一致且目标 ID 未被占用时改名；
- 同步配置引用：`default_provider_id`、`fallback_chat_models`、`default_image_generation_provider_id`、`llm_compress_provider_id`、TTS/STT `provider_id`、以及任意以 `provider_id` 结尾的配置键；
- 同步会话偏好：`provider_perf_*`、`session_provider_override_*`、`session_model_override`、`session_service_config.model_provider_id`；同时把规则/会话里保存的模型更新为新配置项的 `model`；
- 手填 ID（不以来源前缀开头）不动；目标 ID 已存在时跳过并打警告。

### 3. WebUI 编辑同步改名

`ProviderManager.update_provider(origin_id, new_config)`：

- 用户手填了新 ID 就尊重；
- 没改 ID 且属于自动命名时，按新 `model` 计算期望 ID，改名并同步引用；
- 返回生效后的 ID；配置保存后重载实例，旧 ID 实例在 reload 清理阶段终止。

### 4. 指令层即时自愈

`/model`、`/provider` 在落盘前调用 `_sync_provider_entry_id()`。如果目标配置项 ID 与 `model` 失配，立即走一次 `update_provider` 改名，并在回执里提示：

```text
已同步配置项 ID: 懒大猫模型/test -> 懒大猫模型/喜欢懒大猫
```

因此不必等重启，下一次切换就会修正。

## 代码落点

- `astrbot/core/provider/provider_ids.py`：`expected_provider_id`、`is_auto_generated_provider_id`、`replace_provider_id_in_config`。
- `astrbot/core/provider/manager.py`：`_sync_provider_ids`、`_rename_provider_preferences`、`ensure_provider_entry`、`update_provider` 改名。
- `astrbot/builtin_stars/builtin_commands/commands/provider.py`：解析优先级、自动建项、即时自愈、回执显示完整 ID。

## 验证

- 用本机真实配置只读模拟：仅 `懒大猫模型/test -> 懒大猫模型/喜欢懒大猫`，`default_provider_id` 同步为新 ID，其他配置项无误伤。
- 单元测试覆盖：失配 ID 改名与三类引用同步、手填 ID 不改名、目标 ID 冲突跳过、`update_provider` 改名、`ensure_provider_entry` 生成 ID / 无来源拒绝。

## 边界

- 插件在自己配置里硬编码旧 ID、且键名不以 `provider_id` 结尾的，需要手动调整；核心配置与数据库偏好已覆盖。
- WebChat 前端 localStorage 里保存的旧 `selected_provider` 可能失效，重新选择一次即可。
- 目标 ID 已存在时不会强行合并两个配置项，保留旧 ID 并提示，需要人工处理。
