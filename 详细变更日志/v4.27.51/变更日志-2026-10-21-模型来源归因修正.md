# 变更日志 — 2026-10-21 — `/model` 当前模型来源归因修正

## 现象

自定义规则里只设置了「对话模型」（即 `provider_perf_chat_completion`，规则选中某个 `来源/模型` 配置项），没有用 `/model -save` 单独保存模型字段时，执行 `/model` 列表显示：

```
当前提供商配置项: 「懒大猫模型/喜欢懒大猫（来源 懒大猫模型）」
...
当前模型: 「喜欢懒大猫」（来源: 全局配置）
```

提供商明明由自定义规则选中，来源却标成「全局配置」，与用户对规则作用域的认知不符。

## 根因

`_show_model_list` 只调用 `resolve_session_model(umo, provider_id)` 判断来源。该函数只读取两层**模型**字段：

- `session_service_config.model` + `model_provider_id`（自定义规则）；
- `session_model_override`（会话级）。

规则里没有模型字段（WebUI 规则编辑器只写 `provider_perf_*`）时，它返回 `(None, "none")`，展示层就把来源标成「全局配置」。而实际生效的模型来自规则选中的配置项的 `model` 字段，提供商选择层并没有被纳入判断。

## 修复

新增 `astrbot/core/utils/session_selection.py::resolve_effective_model(umo, provider_id, provider_model)`：

1. 先走 `resolve_session_model`：规则/会话保存了模型且绑定当前配置项，直接返回对应来源，模型取配置项的 `model`（配置项 ID 是唯一事实来源，旧模型名漂移时以配置项为准）；
2. 模型层没有命中时，再看提供商选择层：
   - `provider_perf_chat_completion == 当前配置项 ID` → `rule`；
   - `session_provider_override_chat_completion == 当前配置项 ID` → `session`；
3. 都没有 → `none`（全局配置）。

`/model` 列表改用该函数；`/model -save`、`/model -global` 无目标时的取值和 `/key` 的当前模型显示也统一为「配置项 model 优先」，避免把规则里残留的旧模型名当成当前模型。

## 边界与兼容

- 不改动任何已保存数据，只影响读取与展示。
- 规则只选了提供商时来源显示「自定义规则」；规则完全没涉及模型/提供商时仍显示「全局配置」，因为此时模型确实来自全局配置。
- 规则里的模型绑定在其他配置项（切换过提供商）时，不会被误算到当前配置项，回退到提供商选择层判断。
