# [2026-10-21] 上下文窗口与用量归因按生效模型计算

> 本文件记录会话级模型模式下，上下文窗口与用量统计如何避免继续使用共享 provider 的旧模型值。

---

## 动机

`astr_main_agent` 原先把自动识别的上下文窗口写回 `provider.provider_config["max_context_tokens"]`：

```python
if provider.provider_config.get("max_context_tokens", 0) <= 0:
    provider.provider_config["max_context_tokens"] = ...
```

该配置对象是共享的 provider 实例属性。引入会话级模型后：

- 会话 A 用 `gpt-4o` 首次请求，把窗口写成 128K；
- 会话 B 切到 `gemini-2.5-pro`（1M 窗口），因为字段已大于 0，不再重新识别，仍按 128K 压缩；
- 用量日志和 `provider_stats.provider_model` 也继续记录配置项全局模型，而不是本次实际模型。

## 方案

- `build_main_agent` 按 `effective_model = req.model or provider.get_model()` 逐请求计算窗口：手动配置 > 上游限额 > 内置静态表 > 兜底值；不再写回共享 `provider_config`。
- `ToolLoopAgentRunner.reset()` 新增 `max_context_tokens: int | None = None` 参数，显式接收本次窗口；未传时保持原行为（读 provider 配置）。
- 统计与日志使用实际模型：
  - `stats.model_name` 初始化取 `req.model or provider_config["model"]`；
  - 回退链切换时按候选提供商更新；
  - `provider_stats.provider_model` 与 Agent 用量日志优先取 `stats.model_name`；
  - TTS 统计里的 `chat_model` 同步使用 `stats.model_name`。

## 代码落点

- `astrbot/core/astr_main_agent.py`：计算 `effective_max_context_tokens` 并传给 `reset`。
- `astrbot/core/agent/runners/tool_loop_agent_runner.py`：新增 `reset(max_context_tokens=...)`，`stats.model_name` 取生效模型。
- `astrbot/core/pipeline/process_stage/method/agent_sub_stages/internal.py`：用量日志与 `provider_stats` 使用 `stats.model_name`。
- `astrbot/core/astr_agent_run_util.py`：TTS 统计的 `chat_model` 使用 `stats.model_name`。

## 验证

- `tests/test_upstream_model_limits.py` 6 项通过，四优先级行为不变。
- 新增作用域测试覆盖规则/会话模型解析；全量回归无新增失败。
