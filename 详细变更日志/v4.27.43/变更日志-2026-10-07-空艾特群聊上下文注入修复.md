# [2026-10-07] 空艾特群聊上下文注入修复：`_bare_wake` 标记打通 on_req_llm 入口

> 本文件为独立变更日志，记录 v4.27.42 空艾特去特殊化改造后遗留的群聊上下文注入缺失修复。

---

## 问题现象

v4.27.42 上线后用户实测（群 ハッピーシュガーライフ，NapCat 平台）：连续空 @ 机器人多次，机器人回复正常但完全联系不上群里正在聊的内容，只能尬聊；导出会话记录（conversation JSONL）确认：

- 连续四次空艾特的 user 消息中，只有空唤醒 system_reminder 提示词、用户信息插件与好感度插件注入，**均无群聊上下文块**（`--- BEGIN CONTEXT ---`），模型思考中自述 "cold context (no chat history shown)"；
- 直到用户发出「@bot 你好」那轮，群聊历史块才第一次出现——即上下文全部堆到了「艾特之后有内容的消息」里。

## 根因

群聊上下文机制是「消费式缓冲」：

1. `builtin_stars/astrbot/main.py` 的 `on_message` 仅在消息含文本/图片/Json 组件（`has_context_content`）时调用 `GroupChatContext.handle_message(event)`——把本条消息格式化后记入会话缓冲（`raw_records`），并在事件上设置落位 extra：`_group_context_record_id`（本条记录的 uuid）与 `_group_context_raw_idx`（落位下标）。
2. LLM 请求时 `on_req_llm`（`group_chat_context.py`）依据落位 extra 定位本条消息，注入缓冲中排在其之前的全部记录（历史块挂 `req.leading_user_content_parts`，即用户消息之前），消费清掉已注入部分。

空艾特只有 At 组件，`has_context_content` 判定不过 → 不进缓冲、不带落位 extra → `on_req_llm` 入口判定 `record_id 非 str 且 prompt_idx < 0` 直接 `return` → 注入被跳过。v4.27.42 只解决了「空艾特能走到 LLM 请求」，没有打通这一层。

## 修复内容

### 空唤醒标记（`internal.py`）

`_fill_bare_wake_prompt` 补提示词的同时设置 `event.set_extra("_bare_wake", True)`，作为空唤醒事件的身份标记。

### 注入入口放行（`group_chat_context.py` 的 `on_req_llm`）

- 入口放行条件增加 `_bare_wake`：非空唤醒且无落位 extra 的事件维持原 `return`（如私聊事件）。
- 锁内定位逻辑：`_bare_wake` 时把 `prompt_idx` 设为 `len(raw_list)`，完全复用既有切片——
  - `records_to_inject = raw_list[:prompt_idx]` → 全部缓冲记录；
  - `current_record`（本条自身）→ 空，不进历史块（本条以空唤醒提示词作为主 prompt）；
  - `remaining` → 空，缓冲整体清空（消费完毕）。
- 越界保护 `prompt_idx >= len(raw_list)` 的 return 对空唤醒排除，避免误杀。
- 后续图片延迟转述（`_resolve_lazy_captions`）与历史块格式化共用，无差异。

### 语义等价性

- 带内容艾特：看到「自己之前的全部缓冲记录」，本条文本为主 prompt。
- 空艾特：看到「上次 LLM 请求以来群里的全部对话」（即全部缓冲），空唤醒提示词为主 prompt。
- 两者历史块内容一致（都是当前时刻之前群里的未消费记录）、都前置在用户消息之前、受同一开关（群聊上下文增强）控制；注入后缓冲清空，新消息重新累积，下次唤醒只注入增量。

## 修改文件清单

1. `astrbot/core/pipeline/process_stage/method/agent_sub_stages/internal.py` — `_fill_bare_wake_prompt` 设置 `_bare_wake` extra
2. `astrbot/builtin_stars/astrbot/group_chat_context.py` — `on_req_llm` 入口放行空唤醒并复用切片逻辑注入全部缓冲
3. `tests/test_bare_wake_prompt.py` — 新增 5 个用例
