# 变更日志 — 2026-10-31 — WebUI 首屏 CDN 阻塞修复与语音库按需加载

## 背景

用户反馈 WebUI 刷新后长时间白屏转圈、侧边栏间歇性消失、页面加载特别久，且时好时坏。浏览器控制台证据：`ort.wasm.min.js` 报 `net::ERR_CONNECTION_TIMED_OUT`，无本地资源 404、无业务 API 报错。

根因：`index.html` 自初始提交起就以 `<script defer>` 同步引入两个 jsdelivr CDN 脚本（语音识别 VAD 库：`onnxruntime-web@1.22.0/dist/ort.wasm.min.js` 与 `@ricky0123/vad-web@0.0.29/dist/bundle.min.js`）。**defer 脚本会阻塞 `DOMContentLoaded`**——在 jsdelivr 不可达的网络环境下（国内直连常见），浏览器要挂到连接超时才放行，整页启动被拖住数十秒；期间组件初始化不完整，表现为侧边栏时有时无等怪象。网络恢复即自愈，故现象间歇出现，与页面功能改动无关。

## 改动

- `ldmbot-dashboard/index.html`：移除上述两个 CDN `<script defer>` 标签，首屏零第三方 CDN 依赖。
- `ldmbot-dashboard/src/composables/useVADRecording.ts`：
  - 新增 `loadScript(src)`（Promise 包装动态注入 `<script>`）与 `ensureVadLibs()`：按需串行加载 CDN 库——先 ort 后 vad-web（vad-web 运行时依赖全局 `ort`）；模块级 Promise 缓存避免并发重复注入，**失败时置空缓存允许下次重试**；
  - `initVAD()`：`window.vad` 不存在时先 `ensureVadLibs()`，加载失败仅 `console.error` 并返回（`startRecording` 既有 `vadInstance` 判空逻辑保证不影响页面），加载成功后走原初始化流程。
- 语音运行时的 wasm 资源路径（`baseAssetPath` / `onnxWASMBasePath`）维持 CDN 不变。

## 边界与兼容

- 首屏加载不再发起任何 jsdelivr 请求：CDN 不可达只影响「语音输入」功能本身（点语音时报加载失败），页面其余功能零影响；
- VAD 库加载时机从「页面启动」变为「首次点语音输入」，若用户点语音瞬间脚本尚未加载完成，`ensureVadLibs` 会等待加载结束再初始化，语义与原先 defer（页面启动即预载）在绝大多数场景等价；
- 原 `window.vad` 存在性检查保留为兜底。

## 验证

- `npm run build` 构建通过，并确认 `dist/index.html` 中已无任何 `cdn.jsdelivr.net` 引用；
- 构建产物已同步至主仓库 `dashboard/dist`；
- 用户实测：修复部署后页面加载恢复正常，不再出现长时间转圈与侧边栏消失。

## 修改文件清单

- `ldmbot-dashboard/index.html`（移除 CDN defer 脚本）
- `ldmbot-dashboard/src/composables/useVADRecording.ts`（loadScript / ensureVadLibs 按需加载）
- `ldmbot/dashboard/dist/**`（构建产物同步）

## 回归点

1. **不要把 CDN `<script>` 加回 `index.html`**（无论 defer 还是 async）：defer 阻塞 DOMContentLoaded 的行为正是本次事故根因；语音库的加载职责已完全移交 `useVADRecording.ts`。
2. 语音输入功能需在有网（可访问 jsdelivr）环境回归一次：点语音 → 授权麦克风 → 说话识别；离线环境下应表现为功能不可用但页面正常、控制台有明确报错。
3. 若未来需要彻底离线化语音功能，方向是将 ort wasm + vad 模型文件本地托管（需同时处理 wasm 资产路径配置），而不是恢复首屏同步加载。
4. 排查同类「页面转圈」问题时优先看 Network 面板中第三方域名（CDN/字体）是否超时，而非业务 API。
