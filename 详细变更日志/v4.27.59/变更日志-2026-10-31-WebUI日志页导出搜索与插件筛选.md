# 变更日志 — 2026-10-31 — WebUI 日志页导出/搜索/插件筛选

## 背景

平台日志页此前只能"看"：无法按插件缩小范围、无法搜关键词、出问题想留档只能手动全选复制。参照官方 AstrBot 的日志页能力，用本项目自己的 UI 风格补齐三件事：

- **日志来源标注**：每条日志带来源（core/plugin）与插件名，前端可按插件筛选；
- **关键词搜索**：控制台内即时过滤并高亮命中；
- **日志导出**：按时间范围导出为文本文件，默认对敏感信息脱敏。

## 改动

### 1. 后端：日志来源注入（`astrbot/core/log.py`）

- `_RecordEnricherFilter.filter()` 在打 `plugin_tag` 的同时注入两个新字段：
  - 插件专属 logger（`PLUGIN_LOGGER_PREFIX` 前缀）：`source = "plugin"`、`plugin_name = 插件名`；
  - 其余记录按 `_is_plugin_path(record.pathname)` 判定：`source = "plugin" | "core"`、`plugin_name = None`。
- `LogQueueHandler.emit()` 发布到 log_broker 的 dict 新增 `source` 与 `plugin_name` 两个字段；`getattr` 兜底防未经该过滤器的记录（如子 logger 传播）字段缺失——`plugin_name` 缺失时按 logger 名前缀再兜一次，`source` 缺失时按 `plugin_name`/路径判定。
- SSE 实时流（`format_log_sse` 展开 dict）与 `/logs/history` 历史接口自动透传新字段，无需额外改动。

### 2. 后端：日志导出（`astrbot/dashboard/services/log_service.py`）

新增 `export_logs(redact, start_time, end_time)`，同步阻塞实现、由 API 层 `asyncio.to_thread` 调度：

- **文件收集 `_collect_log_files()`**：按 `AstrBotConfig` 解析文件日志配置（兼容新旧 `log_file` / `log_file_enable` 两种键，与 `LogManager.configure_logger` 一致），主日志文件 + loguru 按大小轮转文件（`{stem}.*{suffix}` / `{name}.*` 两个 glob，去重）按 mtime 排序为旧 → 新；文件日志未开启或文件缺失返回空。
- **行迭代 `_iter_export_lines()`**：
  - 有文件时逐文件读取，`mtime` 早于 `start_time` 的整文件直接跳过；行首 `[YYYY-MM-DD HH:mm:ss(.SSS)]` 时间戳解析（`_LOG_TIME` 正则），落在 `[start_time, end_time]` 外的行丢弃，**无时间戳的续行跟随上一行的保留判定**（traceback 多行不截断）；
  - 无文件时回退 broker 内存缓存 `log_cache`（按 entry `time` 字段过滤），并剥 ANSI 色码。
- **脱敏 `_LogRedactor`**：与官方 `diagnostic_service` 同源的脱敏正则（按纯文本日志场景裁剪）：
  - 递归收集配置文件里命中敏感键名（password/secret/token/api_key/authorization/cookie/credential/私钥类键名等）的字符串值（≤512 字符、不含换行），同时收集其 URL 编码/JSON 转义变体；按长度降序整体替换为 `[REDACTED]`；
  - 常见凭证格式打码：`Bearer/Basic/ApiKey` 认证头、`Cookie/Set-Cookie` 值、URL `user:pass@` 鉴权段、`key: value` / `key=value` 赋值形式（键名命中敏感词）、`sk-`/`ghp_` 等 Token、JWT、PEM 私钥块；对非 ASCII 文本跳过前缀快判优化。
  - 脱敏收集/替换失败不阻塞导出（`except Exception: pass`）。
- **并发与产物**：`threading.Lock` 非阻塞获取，已有导出任务进行中直接报 `LogServiceError("已有导出任务在进行中")`；`start_time > end_time` 报错；输出写 `get_astrbot_temp_path()` 下 `ldmbot-logs-{raw-}{时间戳}.txt`（UTF-8、LF），由 API 层响应结束后清理。

### 3. 后端：导出接口（`astrbot/dashboard/api/logs.py`）

`GET /api/v1/logs/export`，参数 `redact`（默认 true）、`start_time`、`end_time`（Unix 秒，`ge=0`），`require_dashboard_user` 鉴权；`FileResponse`（`text/plain; charset=utf-8`，文件名 `ldmbot-logs-[-raw-]{时间戳}.txt`）+ `BackgroundTask` 响应后删除临时文件；响应头 `Cache-Control: no-store`、`X-Content-Type-Options: nosniff`。

### 4. 前端：控制台搜索与插件筛选（`ConsoleDisplayer.vue`）

- 新增 `showSearch` / `showPluginFilter` props（默认关，**不破坏 ExtensionPage / KnowledgeBase 的既有复用**），新增 `header-actions` 具名插槽（放导出按钮）。
- 搜索：输入 250ms 防抖，匹配时剥 ANSI 后比对，命中关键词 amber 高亮（HTML 转义后包 `<mark>`）。
- 插件筛选：下拉选项从日志缓存条目的 `plugin_name` 派生（去重排序），并与 `pluginApi.list` 的 `display_name` 映射显示名；首位固定「仅核心日志」（哨兵值 `__core__`，排除 `source === 'plugin'` 或有 `plugin_name` 的条目）；缓存为空时显示占位文案。
- 渲染重构：`buildLogElement()` 拆前缀/级别/消息三段 span，fragment 批量渲染；日志条目带 `data-log-id`，缓存裁剪时同步删对应 DOM，避免索引错位。
- 保留既有行为：亮/柔两套配色、指纹去重、`Last-Event-ID` 断线补发、wheel/touch 自动跟随。

### 5. 前端：导出对话框（`LogExportButton.vue`，新文件）

- 快捷范围：近 1 小时 / 12 小时 / 24 小时 / 3 天，或自定义起止时间（本地时间转 Unix 秒，校验开始早于结束）。
- 脱敏开关默认开；关闭时展示红字警告「原始日志可能包含密码、Token 等敏感信息，请勿随意分享」。
- blob 下载：解析 `content-disposition` 取文件名；错误响应体是 Blob，需先 `text()` 再解析 JSON 取 `message`；导出期间按钮禁用并提示「仍在导出…」/大日志量提示。

### 6. 日志页布局与可用性（`ConsolePage.vue` + 样式）

- 删除标题下的 `pageHint` 提示行（及对应 i18n key），header margin 24→8px、padding 12→8px，给日志区让空间。
- 页面改 flex column，日志区 `flex: 1 1 auto; min-height: 0` 自动占满剩余高度，替换原 `calc(100vh - 214px)` 魔法数字。
- 对比度修复：搜索框/插件筛选 placeholder 加深（on-surface 0.72、opacity 1）、已选文字 0.92；全屏按钮原为写死白色（浅色页面里隐形），改为跟随 on-surface 0.72，`:fullscreen` 内反转为白色、搜索/筛选字段切深色底。
- `ConsoleDisplayer` 在 script 块顶层用别名 `useModuleI18n as useConsoleI18n` 取本地 i18n（模块级 ref 无 inject 依赖，顶层调用安全）。

### 7. API 与 i18n

- `src/api/v1.ts`：`logApi.exportArchive(params)` → `GET /api/v1/logs/export`，`responseType: 'blob'`。
- `src/i18n/locales/zh-CN/features/console.json`：新增 `search` / `pluginFilter` / `exportLogs` 三节，删除 `pageHint`。

## 边界与兼容

- `showSearch`/`showPluginFilter` 默认关闭，ExtensionPage、KnowledgeBase 等复用 `ConsoleDisplayer` 的页面不出现新 UI，行为不变。
- SSE/历史接口只是**多带了** `source`/`plugin_name` 字段，旧前端忽略未知字段，无破坏性。
- 导出优先读文件日志（全量历史）；文件日志未开启时只能导出 broker 内存缓存的最近日志，导出对话框内已明示。
- 脱敏是尽力而为：正则覆盖配置密钥与常见凭证格式，不能保证捕获所有敏感内容；raw 导出（`redact=false`）在 UI 层有明确警告。
- 时间过滤按日志行内时间戳，依赖文件日志的行首格式 `[YYYY-MM-DD HH:mm:ss]`；无时间戳行跟随上一行判定。
- 导出接口单任务互斥（进程内线程锁），多实例部署时互斥不跨进程。
- 本项目多数 Vue 文件是纯 JS（无 `lang="ts"`）：`ref<T>()` 泛型会被解析成比较表达式（运行时 ReferenceError），`: type` 注解也会报 TS8010——本批新代码全部无类型标注。

## 回归点

1. `LogQueueHandler.emit()` 的新字段读取必须走 `getattr` 兜底：任何绕过 `_RecordEnricherFilter` 的 logger 传播路径（子 logger 继承等）不能因缺字段抛错，兜底判定逻辑（前缀 → 路径）改动需与 enricher 保持一致。
2. 插件筛选的「仅核心日志」哨兵值是 `__core__`（字符串），排除条件是 `source === 'plugin'` **或** 有 `plugin_name`——两个条件来自不同注入路径，缺一不可。
3. 导出的续行跟随逻辑：`keep` 只在解析出时间戳时更新，多行 traceback 的中间行没有时间戳，必须跟随首行判定，改动行过滤时不要改成"无时间戳即丢弃"。
4. `_LogRedactor` 的密钥收集有 512 字符上限并跳过含换行的值，这是防止把大段配置（如整段私钥字符串值）当"密钥"整体替换；调整上限时注意替换是 `str.replace` 全文扫描，密钥集合过大有明显性能开销（已按长度降序 + 前缀快判优化）。
5. 前端新增 MDI 图标必须是完整字符串字面量出现在源码中，`subset-mdi-font.mjs` 构建期按正则扫描裁剪字体。
6. i18n 仅补了 zh-CN，新增语言包时需同步 `console.json` 的 `search`/`pluginFilter`/`exportLogs` 三节。
7. `ConsoleDisplayer` 的 props 默认关闭是为了复用页面零影响；给其他页面开搜索/筛选前先确认该页日志源是否带 `plugin_name`（不带也能用，只是筛选下拉里没有插件维度）。
