# 变更日志 — 2026-10-31 — 恢复 WebUI 手动安装 pip 库

## 背景

`UpdateService.install_pip_package`（WebUI「插件管理 → 安装 pip 库」入口）此前被短路禁用：方法体直接返回提示「已禁用 WebUI 任意 pip 安装；请通过项目更新流程安装 requirements」，前端点了也不会真正安装。这批改动恢复官方实现，重新开放 WebUI 手动安装 pip 库。

## 改动

`astrbot/dashboard/services/update_service.py` `install_pip_package()`：

- 移除短路禁用分支，恢复官方逻辑：
  1. `demo_mode` 下抛 `UpdateServiceError("演示模式下不允许执行此操作。")`；
  2. 解析 payload 的 `package`（必填，缺失报「缺少参数 package 或不合法」）与 `mirror`（可选，镜像源）；
  3. `await self.pip_install(package, mirror=mirror)` 执行安装，成功返回 `UpdateServiceResult(message="安装成功。")`；
  4. 失败记录 `/api/update_pip` 完整 traceback 后抛 `UpdateServiceError`，前端展示原因。
- 核心更新流程中的 requirements 安装不受影响（走独立路径，本就未禁用）。

## 边界与兼容

- 请求路径与参数结构不变（`/api/update_pip`，`package` + `mirror`），前端无需改动。
- `demo_mode` 保护保留：演示实例仍不能通过 WebUI 装库。
- 镜像源语义跟随 `pip_install` 既有实现（`mirror=None` 时用默认源）。

## 验证

- `update_service.py` `py_compile` 通过。
- 与日志导出改动同批构建验证。

## 修改文件清单

- `astrbot/dashboard/services/update_service.py`（install_pip_package 恢复官方实现）

## 回归点

1. 该方法抛错必须用 `UpdateServiceError`（而非返回失败 result）：API 层按异常映射错误响应，混用会导致前端拿到成功态但实际没装。
2. `pip_install` 是异步方法且承载核心更新 requirements 路径，改动其签名/行为时两处调用方（本方法 + 更新流程）都要回归。
3. 恢复后 WebUI 可装任意 pip 包，属于管理员操作（接口已有 dashboard 鉴权）；如再次需要收紧，优先考虑白名单而不是恢复短路禁用（短路会让报错信息与真实安装状态脱节）。
