# 变更日志 — 2026-11-15 — 生图权限修复：补 wake_prefix、LLM 工具端加管理员限制、去掉 `*` 兜底子指令

## 背景

生图（`/image`）配置为仅管理员可用时存在三处缺口：

1. **兜底权限消息抛 KeyError**：`waking_check/stage.py` 兜底权限消息漏传 `wake_prefix`，非管理员发未匹配的 `/image` 子指令时，格式化提示语直接抛 `KeyError: 'wake_prefix'`，用户看到的不是权限提示而是报错。
2. **LLM 工具端完全没鉴权**：`ldmbot_generate_image` 与 `ldmbot_list_image_generation_models` 不检查管理员，普通用户可以让 Agent 调工具绕过 `/image` 的仅管理员限制。
3. **`@image.command("*")` 兜底子指令抢跑**：未匹配的子指令被 `*` 兜底接住，走不到框架的 `CommandGroupFilter` 标准报错路径，只能靠上面的兜底文案 —— 而那条文案又是坏的。

## 改动

- `astrbot/core/pipeline/waking_check/stage.py`：兜底权限消息补传 `wake_prefix`。
- `astrbot/core/tools/image_generation_tools.py`：新增 `_admin_only_deny()`，复用 `ImageCommands.admin_only()` 的配置判断；`ldmbot_generate_image` 与 `ldmbot_list_image_generation_models` 在非管理员时返回拦截文案，与聊天指令权限逻辑保持一致。
- `astrbot/builtin_stars/builtin_commands/main.py`：删除 `@image.command("*")` 兜底子指令。未匹配子指令与裸 `/image` 交由 `CommandGroupFilter` 抛错、`waking_check` 按框架格式发送 —— 管理员见指令树，非管理员见权限提示。

## 验证

- `tests/test_image_generation_tools.py`、`tests/test_image_command.py`、`tests/test_image_generation_stop.py` 共 **19 个用例全部通过**。

## 行为变化

- 普通用户此前可通过 Agent 绕过管理员限制使用生图，升级后会被拦截（属预期），可在配置中调整 `admin_only`。
