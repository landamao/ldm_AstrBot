# 变更日志 — 2026-11-01 — 非纯文本回复的历史落库修复

## 背景

`astrbot_plugin_kktts` 开启自动转语音的**替换文本**模式后，那一轮对话在历史里整轮消失，下一轮 LLM 完全看不到上一轮说过什么（表现为「转一次语音之后上下文就断片」）。

复现证据：

- `data/logs/ldmbot.log` `16:12:38.383` 出现 `[agent_sub_stages.internal:1257] LLM 响应为空，不保存记录。`——而这一轮明明有回复；
- `data/data_v4.db` 的 `conversations.history` 里依次是 你好1、你好2、你好3、你好4、你好6、你好7，**你好5 整轮缺失**（用户消息与 assistant 回复都没落库）。

## 根因

`LLMResponse.completion_text` 是**派生属性**：只要 `result_chain` 非空，它就等于 `result_chain.get_plain_text()`。

插件在 `on_llm_response` 里把 `resp.result_chain` 换成「只有 `Record`（语音）的链」之后，链里没有任何 `Plain` 组件，`completion_text` 必然读成空字符串。`_save_to_history` 当时用 `not llm_response.completion_text` 判定「空响应」并 `return`，于是整轮被丢弃。

同类隐患不止 TTS：任何把回复换成图片、文件、@ 等非文本组件的插件，都会同样踩到——用户看到回复了，历史里却没有。

## 改动

### 1. 判定改为「链里有没有内容」（`astrbot/core/pipeline/process_stage/method/agent_sub_stages/internal.py`）

`_save_to_history` 在空响应判定前新增：

```python
has_non_text_reply = bool(
    llm_response.result_chain
    and any(
        not isinstance(comp, Plain) for comp in llm_response.result_chain.chain
    )
)
```

丢弃条件补上 `and not has_non_text_reply`：

```text
空 completion_text 且无 tool_calls_result 且未被中断 且链里没有非 Plain 组件 → 才丢弃
```

语义是：**链里存在非 `Plain` 组件就说明本轮确实回复了**，不能按空响应处理。`result_chain` 为空（真的没回复）时行为不变，不会制造空轮次。

### 2. 新增回归测试（`tests/test_history_save_non_text_reply.py`）

四例直击判定边界，全部以 `python tests/test_history_save_non_text_reply.py` 直跑：

- `result_chain` 只有 `Record`（无 `Plain`）→ 本轮落库，assistant 正文取自原文；
- `result_chain` 为空 → 仍不落库（不制造空轮次）；
- 无响应 / `None` → 不落库；
- 正常纯文本回复 → 照常落库，行为无回归。

### 3. 附带：压缩告警不再写进真实库（`tests/test_context_usage_snapshot.py`）

排查本问题时发现另一个独立问题：该测试会故意构造 `token_usage=3_879_963` 触发上下文压缩分支，`compressor` 为 `None` 时 `core/context/manager.py` 会调 `notification_service.notify`，而它走的是**真实** `db_helper`（`data/data_v4.db`）。跑一次测试就在生产库里留一条未读的「上下文压缩失败：未配置可用的压缩模型」通知，下次启动 WebUI 直接弹出来（累计两次就显示 ×2）。

处理：测试文件顶部把 `notification_service.notify` 换成只打日志的空实现。这些 tests 都是以 `python tests/xxx.py` 直跑、cwd 即仓库根，凡是走 `db_helper` / `notification_service` 的路径都会落到真实 `data/`，写新测试时要先 stub 掉。
