# 变更日志 — 2026-11-12 — WebUI 恢复页强提示先备份、逐目录结果、失败后一键还原

## 背景

去掉 `.bak` 之后恢复的兜底只剩「恢复前备份」，但 WebUI 这一侧原本没有任何强制力，失败时也看不出发生了什么：

- 确认页只有一句 `⚠️ 导入将会清空并覆盖现有数据！请确保已备份当前数据。`，用户一路点下去就能在没有备份的情况下覆盖数据 —— 提示了，但等于没提示。
- 失败页只有一行错误摘要，看不到「哪些目录成功了、哪些没成功」，只能凭感觉判断。
- 同一句错误被渲染两遍：`data.error`（后端把 `errors` 用 `"; "` 拼成一行）与 `result.errors`（逐条）同时显示。
- 恢复失败后，前置备份只有「下载」一个出口，想在原地还原得自己跑去备份列表再找一遍。
- 「恢复前先备份」的勾选状态会残留：`open()` 只置 `isOpen`，取消勾选后关掉对话框再打开（走「上传并检查」路径）仍是取消状态 —— 安全开关被静默记住为关闭。

## 改动

### 1. 确认步骤：把「先备份」变成需要主动拒绝的默认项（`BackupDialog.vue`）

- 新增红框卡片「先备份，再恢复」：
  - 红色 tonal 提示：恢复会用备份包覆盖当前数据，一旦覆盖无法找回，**没有任何隐藏副本，也没有 `.bak` 兜底**；
  - 勾选框「恢复前先备份当前数据（强烈建议，默认开启）」，说明会在备份目录生成带 `pre-restore` 标记的 ZIP；
  - 取消勾选后追加红色实心警告 + 必须勾选「我已了解风险，仍然不备份直接恢复」，否则底部确认按钮 `disabled`（新增 `importBlocked` 计算属性）。
- 确认页顶部新增「即将恢复的备份：<文件名>」。此前从备份列表点进来时，页面上完全看不出正在恢复哪个包。
- 恢复范围（端口号 / 账号密码）区块保持不变。

### 2. 完成 / 失败步骤：结果明细（`BackupDialog.vue`）

- 新增 `directoryEntries` 计算属性，把 `directory_results` 渲染成彩色 chip：绿色 `N 个文件`、灰色 `已跳过`、红色 `失败`，成功页与失败页共用。
- 失败页按 `hasPartialRestore`（`imported_tables` 有非零行 / 有 `ok` 目录 / `imported_files` 非空）区分两种说明：
  - 部分成功 → 「失败的目录保持原样（没有被替换），已恢复成功的部分不会自动回滚。」
  - 一个字节都没写 → 「本次恢复没有写入任何数据，现有数据保持完整。」

  取代原来一律显示的「现有数据未改动」。
- 错误展示去重：有结构化 `errors` 时逐条列出，没有才回退到 `importError`，不再重复两遍。
- 成功页展示 `pre_restore_backup.filename` 并提供下载。

### 3. 失败后一键还原（`BackupDialog.vue`）

- 前置备份区块新增主按钮「立即还原这份备份」（`mdi-backup-restore`），与「下载这份备份」并列。
- 点击不是直接开跑，而是复用备份列表的恢复入口 `restoreFromList(filename)`：切到「导入备份」页 → 对该 `pre-restore` 包做预检查 → 停在确认页等用户点「确认导入」。既省掉手动翻列表，又不绕过确认。
- 还原时仍默认「先备份当前数据」，会给当前这个残缺状态再打一份 `pre-restore` 包；用户可在确认页取消勾选。

### 4. 状态复位（`BackupDialog.vue`）

- `open()` 打开对话框时重置 `backupBeforeRestore = true` / `riskAcknowledged = false` / `importResult = null`，避免安全开关记住上一次的取消状态。`resetImport()` 与 `restoreFromList()` 同样复位。

### 5. 接口与文案（`api/v1.ts` / `zh-CN/features/settings.json`）

- `backupApi.import()` 增加第 5 个参数 `backupFirst = true`，请求体带 `backup_first`。
- 新增 `backup.import.preBackup.*`（标题 / 强警告 / 开关 / 说明 / 关闭后警告 / 风险确认 / 已备份提示 / 下载 / 立即还原 / 还原提示）、`partialHint`、`nothingHint`、`restoringFile`、`directories`、`filesCount`、`skipped`、`failedLabel`。

## 说明

- 失败页的「重试」仍是回到文件选择步骤，不会自动重跑上一次的包 —— 避免用户在没搞清失败原因时反复覆盖。
- 「立即还原」依赖后端在失败结果里回传 `pre_restore_backup`；若本次恢复关闭了「先备份」，该区块不会出现，只剩错误说明。
- 前端是纯静态产物，刷新即可生效；后端文案与 `backup_first` 解析需要重启服务。
