# 变更日志 — 2026-10-30 — 日志控制台重复显示与自动滚动失效修复

## 背景

WebUI 日志控制台（`ConsoleDisplayer`，控制台页 / 插件安装弹窗 / 知识库安装区三处复用）用户反馈两个长期存在的 bug：

1. **日志偶尔出现多条一模一样的重复显示，刷新页面后恢复正常**。刷新会清空前端缓存并只从历史接口拉一次，说明后端日志缓存本身没有重复，重复是前端在运行过程中引入的。
2. **自动滚动关不掉**：用户向上滚动回看历史日志后，新日志到达仍会把视图强行拉回底部。

排查确认的根因（前端 `ConsoleDisplayer.vue` + 后端 `log_service.py` 各有份）：

- **重复显示**：
  - `onopen`（SSE 连接成功回调）里 `if (!lastEventId) fetchLogHistory()` 会再全量拉一次历史，与 `mounted` 时的全量拉取、SSE 实时消息三方在时间窗内交错，去重逻辑一旦失手就把同一条日志打印两次；
  - 去重靠 `time === time && data === data && level === level` 三字段全等、对整个缓存做 `some()` 线性扫描，既慢又脆弱（Windows 上 `time.time()` 分辨率较粗，同一时间片内多条日志 time 相同，全等比较对表示差异零容忍）；
  - 断线重连时前端 `new EventSourcePolyfill()` **不带任何断点信息**——后端本已支持按 `Last-Event-ID` 请求头补发断线期间日志（`stream_log_events` 的 `replay_cached_logs`），但该机制从未被接上（实测 node_modules 里 polyfill 源码确认：自动重连把 lastEventId 拼成 **URL 查询参数**，后端读的是 **请求头**，两条通道对不上）；
  - 后端 `stream_log_events` 先 replay 后 `register()` 队列，两步之间产生的日志会丢失；一旦补发被真正启用，补发与实时推送的重叠段又需要去重。
- **自动滚动失效**：用户上滚产生的 scroll 事件被 50ms 节流 + `isProgrammaticScroll`（rAF 一帧 ≈16ms 的窗口）竞态吞掉——日志刷得快时，节流回调落点恰好撞进程序滚动窗口被直接 `return`；且 `scrollToBottomIfNeeded` 的 rAF 回调里还强制 `autoScroll = true`。三重叠加下，高频日志场景用户的滚动意图几乎必然丢失，`autoScroll` 永远停在 true。

## 改动

### 1. 前端 `ConsoleDisplayer.vue`

#### 1.1 去重改为指纹 Set（O(1)，与缓存同步增删）

- 新增 `makeLogKey(log)`：`time` 规范化（number → `toFixed(6)`，其他 → `String`）后拼 `time|level|data` 指纹。同一条日志无论来自历史接口还是 SSE 实时流，指纹一致；
- `processNewLogs()` 重写：指纹命中即跳过；新增日志先收集再统一打印（打印顺序 = 到达顺序，与终端习惯一致）；
- 缓存超上限截断时，被挤出的旧日志**同步从指纹 Set 删除**——既防集合无限增长，也保证被截断的旧日志若日后经补发再进来能正常显示（不会被旧指纹误吞）；
- 打印前复查 `logKeys.has(key)`，排序/截断后被挤出的日志不再误打印。

#### 1.2 SSE 连接与重连

- `onopen` **不再全量重拉历史**（`mounted` 已拉过一次；断线期间的日志改由 Last-Event-ID 补发覆盖，消除三方竞态窗口）；
- `connectSSE()` 构造请求头时，`lastEventId` 存在则附加 `'Last-Event-ID': this.lastEventId`（polyfill 的自定义 headers 会合并进请求，源码已确认）；
- `onerror` 重连定时器里**删除重拉历史逻辑**，只递增重试计数后 `connectSSE()`——断点经请求头交给后端，由后端补发，避免与实时流交错。

#### 1.3 自动滚动重写

- 删除 `isProgrammaticScroll` + rAF 标志与 rAF 内强制 `autoScroll = true`；
- 程序滚动改用时间戳标记：`scrollToBottomIfNeeded()` 记录 `programmaticScrollAt = Date.now()`；`handleTermScroll()` 对 100ms 内的 scroll 事件（程序滚动赋值引发的）直接忽略；
- 新增 `wheel`（`deltaY < 0` 上滚）与 `touchstart` 监听：**程序 `scrollTop` 赋值不会触发这两个事件**，只来自真实用户操作，判定无竞态——滚轮上滚立即 `autoScroll = false`（先于 scroll 事件派发，绝不被吞）；
- scroll 事件职责收窄为**恢复跟随**：节流回调里按位置 `autoScroll = isNearBottom(ele)` 判断，滚回底部自动恢复、离开底部暂停；
- `attachScrollListener()` / `detachScrollListener()` 同步挂载/卸载三个监听（scroll/wheel/touchstart，均 passive）。

### 2. 后端 `astrbot/dashboard/services/log_service.py`

`stream_log_events()` 重写（原 `replay_cached_logs()` 方法删除，仅此一处引用）：

- **先 `register()` 队列再补发**：补发期间产生的新日志积压在队列中不会丢失（旧顺序两步之间必丢日志）；
- 带 `last_event_id` 时遍历缓存快照补发 `time > 断点` 的日志，水位线 `watermark` 逐条推进到补发的最大 ts；
- 实时循环里 `time <= watermark` 的消息直接跳过——这些消息已被补发覆盖，跳过即消除「补发 + 实时」重叠段重复；
- 补发循环内 `float()` 解析加 `(TypeError, ValueError)` 容错，单条脏数据不再断掉整个日志流。

## 边界与兼容

- 不带 `Last-Event-ID` 的全新连接（首次打开页面）行为不变：后端不补发，前端只靠 `mounted` 拉历史。
- `Last-Event-ID` 走的是标准 SSE 语义，浏览器原生 EventSource 重连也会带同一请求头，后端同样正确处理。
- 水位线跳过条件用 `<=` 而非 `<`：`time == watermark` 的队列消息可能已被补发，宁可在「同一微秒戳两条不同日志」的极端情况下舍一条，也不引入重复（与本次修复目标一致；现代 Python 在 Windows 上时间戳为亚微秒精度，概率可忽略）。
- 自动滚动的交互语义变化：移动端 `touchstart` 即暂停跟随（点击日志区也会暂停），滚回底部由 scroll 事件按位置恢复——比旧版「被强行拉回底部」符合预期；桌面端滚轮向下滚回底部同样自动恢复。
- `ConsoleDisplayer` 的三处复用（控制台页、插件安装弹窗、知识库）共用同一组件逻辑，修复对所有实例生效；组件各自持有独立的指纹 Set 与 SSE 连接，互不影响。
- `onopen` 不再重拉历史后，若用户停留在页面期间后端重启（缓存清空），依赖 SSE 重连补发覆盖——后端重启本身会断开 SSE 触发重连流程，行为闭环。

## 回归点

1. **`onopen` 不要再补 `fetchLogHistory()`**：历史拉取只发生在 `mounted`；断线缺口由 `Last-Event-ID` + 后端补发闭环。若再加全量拉取，与实时流交错会复现重复显示。
2. **polyfill 的断点传递是请求头不是 URL 参数**：`connectSSE()` 的 `headers['Last-Event-ID']` 是补发生效的关键；升级 event-source-polyfill 版本时需复查其 headers 合并行为（本次已查 1.x 源码确认 `es.headers` 全量合并进请求）。
3. **后端补发与实时的边界靠水位线**：`stream_log_events` 必须「先 register 后 replay」，跳过条件是 `time <= watermark`；改动顺序或比较符会分别引入丢日志 / 重复日志。
4. **指纹 Set 必须与 `localLogCache` 同步增删**：截断时删指纹、打印前查指纹，缺一步会分别导致 Set 无限增长 / 旧日志被永久误吞 / 被截断日志误打印。
5. **自动滚动的用户意图判定依赖 wheel/touchstart**：这两个事件程序滚动不触发，是整个方案无竞态的前提；若未来程序滚动改用模拟事件（如自动化测试注入 wheel），需另行区分。
6. **handleTermScroll 的 100ms 时间戳窗口**需覆盖程序滚动引发的 scroll 事件派发延迟（实测一帧 ≈16ms，留有余量）；改节流间隔（当前 50ms）时注意窗口仍需大于节流间隔 + 一帧。
