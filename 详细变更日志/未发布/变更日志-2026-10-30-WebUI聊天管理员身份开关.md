# 变更日志 — 2026-10-30 — WebUI 聊天管理员身份开关

## 背景

WebUI 聊天消息进入流水线后，管理员身份由 `WakingCheckStage` 按 `admins_id` 配置判定（发送者 ID 命中 → `event.role = "admin"`）。WebUI 的发送者 ID 就是 dashboard 登录用户名，因此必须把登录用户名写进 `admins_id` 才能使用 admin 权限（admin_only 指令、白名单管理员放行等）。这个耦合不直观：换登录用户名就要改配置，配置里也必须留着一个"看起来像普通 ID"的条目。

需求：在聊天输入框加号菜单里加一个**管理员身份开关**——开启时本次发送的消息直接按管理员处理，关闭则按普通成员；默认开启。这样 WebUI 场景不再依赖 `admins_id`，配置文件里的管理员 ID 默认值也可以改为空。

## 改动

### 1. 后端：显式身份优先于配置判定

#### 1.1 身份透传链（dashboard → webchat 队列）

WebUI 聊天有两条传输路径，最终都汇入 `webchat_queue_mgr` 的 chat_queue，两条都透传 `is_admin`：

- `astrbot/dashboard/services/chat_service.py` `build_chat_stream()`（SSE 路径，POST `/api/v1/chat`）：读取 `post_data.get("is_admin")`，**非 bool 一律归一为 None**（未指定），随 payload 进队列；
- `astrbot/dashboard/services/live_chat_service.py` `handle_chat_message()`（WebSocket 路径，`ct:"chat" t:"send"`）：同样读取并归一，进队列 payload。

#### 1.2 事件标记（`astrbot/core/platform/sources/webchat/webchat_adapter.py`）

`create_event()` 在 payload 里发现 `is_admin` 为显式 bool 时，写入事件 extra：

```python
message_event.set_extra("webchat_explicit_role", "admin" if is_admin else "member")
```

#### 1.3 判定优先级（`astrbot/core/pipeline/waking_check/stage.py`）

设置 sender 身份的逻辑改为：

```python
explicit_role = event.get_extra("webchat_explicit_role")
if explicit_role in ("admin", "member"):
    event.role = explicit_role
else:
    for admin_id in self.ctx.astrbot_config["admins_id"]:
        if str(event.get_sender_id()) == admin_id:
            event.role = "admin"
            break
```

显式声明**完全取代**配置判定（开关关闭 = 即使发送者在 `admins_id` 里也是 member）；未指定时回落原有逻辑，非 WebChat 平台零影响。流水线顺序上 `WakingCheckStage` 先于 `WhitelistCheckStage`（`stage_order.py`），显式 role 会被白名单放行、admin 指令过滤等后续阶段正确使用。

#### 1.4 默认配置（`astrbot/core/config/default.py`）

- `admins_id` 默认值 `["ldm"]` → `[]`：WebUI 开关已覆盖 dashboard 场景，全新安装无需再预置登录用户名；
- 配置面板 `admins_id` 项新增 hint：「按发送者 ID 判定管理员身份。WebUI 聊天可通过输入框加号菜单中的「管理员身份」开关临时控制，无需在此配置。」

#### 1.5 API 声明（`astrbot/dashboard/schemas.py`）

`OpenApiChatRequest` 显式声明 `is_admin: bool | None = None`（含 OpenAPI 文档描述）。`_model_dict()` 用 `exclude_unset=True`，客户端不传该字段时不会出现在 post_data → 判定走 None → 回落 `admins_id`，向后兼容。

### 2. WebUI 前端（`ldmbot-dashboard`）

- `src/components/chat/ChatInput.vue`：加号菜单新增「管理员身份」开关项（位于流式响应开关上方），图标 `mdi-shield-account` / `mdi-shield-account-outline` 随状态切换，文案走 `adminIdentity.enabled/disabled`；Props 新增 `isAdmin`（必填），Emits 新增 `toggleAdmin`。
- `src/components/chat/Chat.vue`：新增 `isAdminEnabled = ref(true)` 与 `toggleAdmin()`；两处 `<ChatInput>` 传 `:is-admin` / `@toggle-admin`；**三条发送路径全部携带**——`sendCurrentMessage()`（普通发送）、`saveMessageEdit()` → `continueEditedMessage`（编辑后续写）、`handleRegenerateMessage()` → `regenerateMessage`（重新生成）。
- `src/components/chat/StandaloneChat.vue`：独立聊天页同样接入（状态、模板传参、toggle、发送 payload）。
- `src/composables/useMessages.ts`：`SendMessageStreamOptions` / `ContinueEditedMessageOptions` 新增 `isAdmin?: boolean`；`sendMessageStream()` 透传给 `startSseStream()` / `startWebSocketStream()`（位置参数追加在 enableFallback 之后）；两种请求体均带 `is_admin`（undefined 时 `JSON.stringify` 自动省略该字段）。
- i18n：`src/i18n/locales/zh-CN/features/chat.json` 新增 `adminIdentity: { enabled: "管理员身份已开启", disabled: "管理员身份已关闭" }`。
- 类型：`src/api/generated/openapi-v1/types.gen.ts` `ChatRequest` 新增 `is_admin?: boolean`。

## 边界与兼容

- `admins_id` 默认值改动**只影响全新安装/重置配置**；既有配置文件里的值不会被动，配置了管理员 ID 的老逻辑对非 WebUI 消息（QQ 等平台）依然生效。
- Open API（API Key 调用 `/api/v1/chat`）路径的 payload 不含 `is_admin`，仍走 `admins_id` 判定；原有的 admin username 保护（`username is reserved for an AstrBot administrator`、`chat:admin` scope）不受影响。
- 未指定 `is_admin` 的旧前端/第三方调用完全向后兼容（回落 `admins_id`）。
- 开关是**逐消息生效**，与 streaming/reasoning/fallback 开关一致不持久化，刷新页面回到默认开启。
- WebUI 消息本就走 JWT 登录鉴权，登录用户声明管理员身份不引入新的未授权面；Open API 匿名末端用户不经过该开关。
- `is_admin` 只影响 `event.role`，不改变消息落库的 sender 记录。

## 回归点

1. **新增 WebChat 消息入口**（如 Open API 的 WebSocket bridge 等）若要支持本开关，必须在 queue payload 里传 bool 的 `is_admin`——不传即回落 `admins_id` 判定；归一规则（非 bool → None）与 chat_service/live_chat_service 保持一致。
2. `waking_check` 里 `webchat_explicit_role` 判定与 `admins_id` 判定是**互斥分支**：显式为 "member" 时即使发送者在 `admins_id` 里也不得提升为 admin，改动时不要合并两条逻辑。
3. extra key 固定为 `webchat_explicit_role`（值为字符串 `"admin"`/`"member"`，不是 bool），其他平台适配器若要复用该机制，写入同名 extra 即可，无需改流水线。
4. 前端新增菜单图标必须是**完整字符串字面量**出现在 .vue/.ts 源码中，`subset-mdi-font.mjs` 构建期靠正则 `mdi-[a-z][a-z0-9-]*` 扫描裁剪字体；动态拼接图标名会缺失字形。
5. `rm -rf dist` 后重建，preserveDistVersion 会写出 **v 前缀**版本号——发版/部署前核对 `dist/version` 与 `dist/assets/version` 应为无 v 的 `4.27.58`。
6. i18n 目前仅 zh-CN 有 `adminIdentity` 节，新增语言包时需同步补齐。
