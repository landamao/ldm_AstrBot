# 变更日志 — 2026-11-19 — 新增 `on_platform_connected`：适配器真正连上平台才触发

## 背景

`@filter.on_platform_loaded` 在适配器**实例加载完成**时就触发，此时 `PlatformManager`
只是把 `inst.run()` 挂成了任务，平台侧可能根本没连上：OneBot 反向 WebSocket 没建起来、
账号没登录、token 填错，都会让钩子照常跑一遍。

插件因此拿不到「什么时候真的可以调 API」这个信号。典型写法只能等第一条消息：

```python
@filter.event_message_type(filter.EventMessageType.GROUP_MESSAGE)
async def 接收消息(self, event: AiocqhttpMessageEvent):
    bots[event.get_self_id()] = event.bot   # 第一条消息之前 bots 是空的
```

想在启动时就设置群昵称、拉取好友/群列表、预热缓存，都没有可靠的时机。

## 改动

### 1. 新事件类型与注册器

- `astrbot/core/star/star_handler.py`：`EventType` 新增 `OnPlatformConnectedEvent`
  （生命周期类钩子，不受 `plugins_name` 白名单过滤）；补对应 overload。
- `astrbot/core/star/register/star_handler.py`：新增
  `register_on_platform_connected(platform_name=None, priority=0)`，
  `platform_name` 落到 `extras_configs`，派发时据此跳过其它适配器。
- `astrbot/core/star/register/__init__.py`、`astrbot/api/event/filter/__init__.py`：
  导出为 `filter.on_platform_connected`。

### 2. 派发与连接状态

- 新增 `astrbot/core/platform/connection_hooks.py`：`dispatch_platform_connected()`
  按优先级依次执行钩子，单个钩子抛错只记日志，不影响其它钩子和适配器连接流程。
- `astrbot/core/platform/platform.py`：
  - `Platform.notify_connected(platform_self_id)`：适配器连上后调用，派发钩子。
  - `Platform.is_connected`：基类默认以 `status == RUNNING` 为准，可被适配器覆盖。
  - `Platform.connected_self_id`：平台侧机器人账号，基类返回 `None`。
  - `get_stats()` 输出增加 `connected` 字段，面板/接口可直接看到真实连接态。
- `astrbot/dashboard/services/plugin_service.py`：插件详情页把新事件类型显示为
  「适配器连上平台后」，不再直接暴露 `OnPlatformConnectedEvent` 枚举名。

### 3. aiocqhttp（OneBot v11）

- `on_websocket_connection`（等价 OneBot 的 `lifecycle.connect` 元事件）改为 async，
  收到后 `await self.notify_connected(event.self_id)`；断开重连会再次触发。
- 覆盖 `is_connected` / `connected_self_id`：直接读 `bot._wsr_api_clients` /
  `bot._wsr_event_clients`，断线时库自身清理连接表，不存在缓存过期。
- 钩子触发时 API 连接已登记（`_add_wsr_api_client` 在读事件之前执行），
  所以钩子里可以立刻 `platform.get_client().call_action(...)`。

## 用法

```python
from astrbot.api.event import filter

class 我的插件(Star):
    @filter.on_platform_connected(platform_name="aiocqhttp")
    async def OneBot连上了(self, platform, self_id):
        bot = platform.get_client()                  # aiocqhttp 的 CQHttp
        friends = await bot.call_action("get_friend_list")
        self.logger.info(f"QQ {self_id} 上线，好友 {len(friends)} 个")

    async def initialize(self):
        # 插件加载时适配器可能早就连上了，钩子不会补发，这里主动查一次
        inst = self.context.get_platform_inst("你的平台ID")
        if inst and inst.is_connected:
            ...
```

Hook 参数：

| 参数 | 类型 | 说明 |
|---|---|---|
| `platform` | `Platform` | 适配器实例，`meta()` 取 id/name，`get_client()` 取原始客户端 |
| `self_id` | `str \| None` | 平台侧机器人账号（OneBot 为机器人 QQ 号） |

## 验证

`tests/test_platform_connected_hook.py`，6 条用例全过，`ruff check` 无告警：

| 用例 | 断言 |
|---|---|
| 注册器 | `platform_name` 写入 extras，事件类型为 `OnPlatformConnectedEvent` |
| 派发 | 抛错钩子（priority=10）先跑且未阻断，其余两个各收一次 |
| 过滤 | `platform_name="telegram"` 只命中通用钩子 |
| 基类状态 | `status=RUNNING` 时 `is_connected` / `stats["connected"]` 为真 |
| OneBot 状态 | 写入 `_wsr_api_clients` 后 `is_connected` 真、`connected_self_id` 为 QQ 号；清空后恢复 |
| 真实链路 | `bot._bus.emit("meta_event.lifecycle.connect", event)` 触发钩子，拿到 self_id |

## 行为变化

- 纯新增，不传 `platform_name` 与原有钩子互不影响；`get_stats()` 多一个 `connected` 键。
- `on_platform_loaded` 语义不变（仍是「适配器实例加载完成」），不要拿它当连接信号。
- 目前只有 aiocqhttp 接入了连接检测；其它适配器可用基类默认值，或自行在建立连接后
  调用 `notify_connected()`。
