# 变更日志 — 2026-11-18 — 指令组新增 `self_handle`：纯组名交给组函数处理

## 背景

指令组的纯组名消息（如只发 `/ccb`、不带任何子指令）此前由框架无条件接管：`CommandGroupFilter.filter()` 直接 `raise ValueError("子指令名不存在。…")`，`waking_check` 捕获后回一段固定的指令树。

两个限制：

1. **插件无法自定义**。组 handler 被 `is_group_cmd_handler` 判掉、永远不进 `activated_handlers`，组函数体是死代码，写 `yield` 也没有机会执行。
2. **`*` 兜底子指令也接不到纯组名**。`filter()` 的 `equals` 分支在 fallback 判断之前就抛错，`CommandFilter` 的兜底分支里也有 `if self.parent_group.equals(message_str): return False` 双重拦截。

想给 `/ccb` 空参时发自己的用法说明，只能放弃指令组、拆成普通 `@filter.command` + `GreedyStr` 自己解析。

## 改动

新增 `self_handle` 参数，默认 `False` 保持旧行为，显式传 `True` 才把纯组名交给组函数：

```python
@filter.command_group("ccb", self_handle=True)
async def ccbg(self, event):
    """ccb指令"""
    yield event.plain_result("用法：/ccb <内容>")

@ccbg.command("*")
async def ccb(self, event, text: str = None):
    """cc对方"""
```

- `astrbot/core/star/filter/command_group.py`：`CommandGroupFilter.__init__` 新增 `self_handle=False` 属性；`filter()` 的 `equals` 分支在 `self_handle` 为 True 时直接放行，不再抛错。
- `astrbot/core/star/register/star_handler.py`：`register_command_group()` 新增 `self_handle: bool = False` 参数，根指令组与子指令组两条分支都会传给 `CommandGroupFilter`。
- `astrbot/core/pipeline/waking_check/stage.py`：过滤循环内新增 `self_handle_group` 判定 —— 当 `CommandGroupFilter.self_handle` 为 True 且当前消息恰好等于组名（`equals`）时，允许该组 handler 进入 `activated_handlers`。带子指令时 `equals` 为 False，组函数不会被执行，互不干扰。

## 验证

`tests/test_cmdgroup_self_handle.py`，9 条断言全过：

| 消息 | 期望 |
|---|---|
| `/aa`（self_handle + 子指令 + 兜底）| 激活组函数 `aa` |
| `/aa off` | 只激活子指令 `aa_off` |
| `/aa uuu` | 只激活 `*` 兜底 |
| `/bb`（默认组）| 仍抛「子指令名不存在」 |
| `/cc`（self_handle 且无子指令）| 激活组函数 `cc` |
| `/cc uuu` | 抛「子指令名不存在」 |
| `/dd` + `/dd sub`（子指令组也开 self_handle）| 分别激活根组 / 子组自身 |

既有 `tests/test_cmdgroup_integration.py`（7 条断言）与 `tests/test_command_group_no_name.py` 行为不变，全部通过；`ruff check` 四个文件全部通过。

## 行为变化

- 不传 `self_handle` 的指令组完全不受影响，纯组名仍发指令树。
- 传 `self_handle=True` 后，纯组名不再发指令树，改为执行组函数；未知子指令（如 `/ccb xxx`）仍走原报错路径。
- 组函数只接收 `event`（没有参数解析），需要参数时请继续用子指令。
