# [2026-09-01] WebChat 重试用户消息重复修复：重试路径复用保留的用户消息记录

> 本文件为独立变更日志，记录 2026-09-01 一次 WebChat（ChatUI）重试链路缺陷修复：
> 点重试后用户消息在会话里重复出现，重试 N 次用户消息就多 N 条。修复方式为
> 重试路径复用被保留的用户消息记录，不再新插。

---

## 问题现象

- WebUI ChatUI 中对 bot 回复点「重试」，每重试一次，右侧的用户消息就重复出现一条；
- 实测重试 3 次，同一条内容为 `test` 的用户消息共出现 4 条（原始 1 条 + 新插 3 条），
  时间戳完全相同，bot 仍只回复一次；
- 截图佐证：4 条相同用户消息均为 19:54，下方仅一条「测试成功」回复。

## 根因

重试链路（08-31 重构版）的设计意图是「复用上一条用户消息重新发送」：

1. 前端 `regenerateMessage`（useMessages.ts）找到被重试 bot 前面最近的一条用户消息，
   把其已落库的真实 id 通过请求体 `_truncate_from_message_id` 传给后端；
2. 后端模块级 `truncate_turn_from_user_message`（chat_service.py，SSE/WS 共用）
   执行重试清理：删除该用户消息之后的所有 platform 记录（旧 bot 回复、报错、
   插件消息等）+ 关联 threads + conversation history 截断到该轮次之前；
   **用户消息本身不删，只换新 checkpoint**（重新请求视为全新一轮）。

缺陷出在第 3 步：清理函数正确保留了用户消息，但两条发送通路在清理之后
**又无条件新插一条用户记录**：

- SSE 通路 `chat_service.py` 的 `send_message_stream`：
  `_skip_user_history` 为 False（重试路径不设置该标志）→ `platform_history_mgr.insert`
  再插一条；

```python
saved_user_record = None

message_parts_for_storage = strip_message_parts_path_fields(message_parts)
if not skip_user_history:  # 重试时也为 False → 无条件新插
    saved_user_record = await self.platform_history_mgr.insert(...)
```

- WS 通路 `live_chat_service.py` 的 `t=send` 处理：truncate 之后同样无条件
  `platform_history_mgr.insert` 新插。

「保留（truncate 换 checkpoint）+ 新插（insert）」叠加，导致每次重试
用户消息净增 1 条。数据库层面每条记录 checkpoint 不同、id 递增，
前端按顺序全部渲染，即截图中时间相同的一排重复消息。

## 修复内容

重试清理成功时，两条通路都改为**取回被保留的用户消息记录复用**，不再新插；
正常发消息路径完全不受影响。

### 后端 `astrbot/dashboard/services/chat_service.py`（SSE 通路）

- `_truncate_from_message_id` 清理成功（`new_checkpoint_from_truncate` 非空）时，
  用 `db.get_platform_message_history_by_id` 取回被保留的用户消息记录，
  赋给 `saved_user_record`；取不到（理论兜底）抛 `ChatServiceError`；
- 用户消息插入条件由 `if not skip_user_history:` 收紧为
  `if not skip_user_history and saved_user_record is None:`；
- `user_message_saved` SSE 事件照发：复用记录的 id 本就是同一条，前端
  `userRecord` 原位更新 id / created_at / llm_checkpoint_id，行为无感知差异。

### 后端 `astrbot/dashboard/services/live_chat_service.py`（WS 通路）

- truncate 块前初始化 `reused_user_record = None`；
- 清理成功时同样取回保留记录赋给 `reused_user_record`；取不到时回发
  `User message not found` error 帧并终止（与既有错误处理对齐）；
- 用户消息落库处改为三元复用：`reused_user_record` 非空则直接用作
  `saved_user_record`，否则按原逻辑 `platform_history_mgr.insert` 新插；
- `user_message_saved` WS 帧照发，语义同上。

## 修改文件清单

1. `astrbot/dashboard/services/chat_service.py`（SSE 通路 send_message_stream）
2. `astrbot/dashboard/services/live_chat_service.py`（WS 通路 t=send 处理）

纯后端改动，无需重新构建前端。

## 部署 / 测试注意

- `bash ~/同步源码.sh` 同步到运行目录后手动重启 ldm 生效；
- 回归验证点：
  1. 正常发消息：用户消息只出现一次（正常路径未动）；
  2. 失败消息点重试：用户消息不重复，旧 bot 回复被清掉、新回复正常流式输出；
  3. 连续重试多次：用户消息始终只有一条；
  4. 编辑消息后重发、生图会话重试（`retry_message_id` 链路）：行为不变
     （生图重试本就是删 bot 复用 user 的独立链路，无此问题）；
- 本次修复只防止以后重复；修复前已产生的重复历史消息仍在库中，
  删除对应会话即可，不做自动清理。
