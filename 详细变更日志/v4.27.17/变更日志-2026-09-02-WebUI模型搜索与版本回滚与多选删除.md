# 变更日志：WebUI 模型选择搜索、版本回滚管理、加载态区分、ChatUI 多选删除（2026-09-02）

## 概述

本轮 WebUI 四项功能改动：

1. 配置/插件配置的模型选择弹窗加搜索过滤
2. 设置→维护新增「版本回滚」管理（弹窗操作：回滚 + 回滚目录清理）
3. 插件管理/插件页面/MCP 区分「加载中」与「真的没有」
4. ChatUI 新增多选删除消息（选择单元 = 轮）

## 一、模型选择弹窗搜索过滤

**背景**：配置文件页、插件配置里的模型选择弹窗（ProviderSelector）没有搜索，模型提供商多时只能滚动找。调查确认全项目共 3 处模型选择 UI：ProviderSelector.vue（配置/插件配置 7 种 `_special` 场景共用）、ChatModelChainSelector.vue（模型链）、ProviderModelMenu.vue（ChatUI 顶部菜单）——后两处原本已有搜索，只有 ProviderSelector 缺。

**改动**：

- `dashboard/src/components/shared/ProviderSelector.vue`
  - 选择弹窗顶部新增搜索框，按提供商 ID / 类型 / 模型名模糊过滤（与 ChatModelChainSelector 同一套匹配规则）
  - 有搜索词时显示「（N 个匹配）」计数；无匹配时显示「没有匹配的提供商」空态（与「暂无可用的提供商」空态区分）
  - 每次打开弹窗自动清空搜索词
- `dashboard/src/i18n/locales/zh-CN/core/shared.json`
  - `providerSelector` 块新增 `searchPlaceholder` / `searchResultCount` / `noSearchResults` 三个词条

**顺手修正**：ChatUI 顶部模型菜单（ProviderModelMenu.vue）中 4 处硬编码英文改为 i18n 中文词条（`Search models` → 搜索模型或 ID、`Loading models...` → 正在加载模型...、`No available models` → 暂无可用模型、`Default model`/`Model` → 默认模型/模型），词条加在 `features/provider.json` 的 `models` 块。

## 二、设置→维护：版本回滚管理

**背景**：更新器每次更新前已自动把旧版本备份到 `data/ldmbot_rollback/`（zip，含 astrbot/ + dist/ + main.py，`update_rollback.py` 机制），但只能命令行 `--rollback` 操作，WebUI 完全没有入口。

**后端改动**：

- `astrbot/dashboard/services/update_service.py`（service 层三方法，复用 `update_rollback.py` 现成的 `list_backups()` / `rollback()` / `get_rollback_dir()`）
  - `list_rollback_backups()`：列出备份（版本号、文件名、大小、备份时间，最新在前）+ 回滚目录路径
  - `rollback_to_version()`：回滚到指定版本（version 空 = 最近一次备份）。校验 desktop_managed / 更新互斥 / demo 模式；回滚成功后自动 `_schedule_restart()` 全量重启
  - `clear_rollback_backups()`：清理备份。带 version 只删该版本 zip；version 空 = 清全部 zip（逐个删，保留目录与说明.txt）
- `astrbot/dashboard/api/updates.py`（新增 3 组共 6 个端点，双路由模式与现有端点一致）
  - `GET /api/v1/updates/rollback-backups`（legacy `GET /api/update/rollback-backups`）— require_system_scope
  - `POST /api/v1/updates/rollback`（legacy `POST /api/update/rollback`）— 回滚，body `{version}`
  - `POST /api/v1/updates/rollback-backups/clear`（legacy `POST /api/update/rollback-backups/clear`）— 清理，body `{version}`

**前端改动**：

- `dashboard/src/components/shared/RollbackDialog.vue`（新文件）
  - 与 BackupDialog 同构的 persistent 弹窗：备份表格（版本/大小/时间/操作）+ 每行「回滚」「删除」按钮（tonal 填充色）+ 底部「清理全部备份」+ 底部显示备份目录路径 + 空态提示
  - 加载中显示进度条，加载完才判空态（与需求三同一原则）
  - 回滚/删除/清理均走全局确认弹窗二次确认；成功失败都弹 toast
  - 回滚确认后关闭弹窗并显示 WaitingForRestart 等待重启界面（直接 `wfr.check()`，不重复触发重启——后端已安排）
  - ⚠️ 踩坑记录：组件用 `useModuleI18n('features/settings')`，词条必须写 `tm('system.rollback.xxx')`（词条在 settings.json 的 `system.rollback` 下）。首版写成 `tm('rollback.xxx')` 导致弹窗全部显示 `[MISSING: features.settings.rollback...]`（初判误为浏览器缓存，实际是词条路径少一段）
- `dashboard/src/views/Settings.vue`
  - 维护区块新增「版本回滚」卡片（settings-item 同构风格，标题/副标题/一个「回滚管理」按钮），点击打开 RollbackDialog
- `dashboard/src/api/v1.ts`
  - `updatesApi` 新增 `rollbackBackups()` / `rollbackToVersion(version)` / `clearRollbackBackups(version)`
- `dashboard/src/i18n/locales/zh-CN/features/settings.json`
  - `system.rollback` 块：标题/副标题/按钮/表格列头/操作按钮/提示/弹窗标题/备份目录标签/三个确认文案/七个消息词条

**语义说明**：回滚整包恢复旧版本源码与 WebUI；备份保留（可在此弹窗删除）；新版本运行正常时建议清理备份释放空间。

## 三、区分「加载中」和「真的没有」

**问题现象**：进入插件页面 Tab，一开始就闪现「暂无插件页面」，过一会数据回来才显示内容——空态判断没有排除「数据还没回来」的情况。四处同类 UI 中只有 Skills 是对的（loading 时显示进度条，加载完才判空态），照该模式修另外三处：

- `dashboard/src/views/extension/InstalledPluginsTab.vue`（插件管理）
  - 解构补取 `loading_`；空态行改为 `v-else-if`，新增首分支：`loading_ && 列表为空` 时显示 v-progress-linear 进度条
- `dashboard/src/views/extension/PluginPagesTab.vue`（插件页面）
  - 同构修改：加载中进度条 + 空态改 `v-else-if`
- `dashboard/src/components/extension/McpServersSection.vue`（MCP 服务器）
  - 新增首分支：`loadingGettingServers && mcpServers 为空` 时显示 v-progress-circular + 「正在加载 MCP 服务器...」；空态改 `v-else-if`
  - 30 秒轮询刷新时已有数据，不判空态分支，无影响
- `dashboard/src/i18n/locales/zh-CN/features/tool-use.json`
  - `mcpServers.loading` = 「正在加载 MCP 服务器...」

## 四、ChatUI 多选删除消息（选择单元 = 轮）

**需求语义**：删除一条用户消息会连带该轮 bot 回复一起删（轮次语义），所以选择单元就是**轮**——点任何一条消息（含 bot 回复），选中它所在的整轮。

### 后端

- `astrbot/dashboard/services/chat_service.py`
  - 新增 `delete_messages(username, session_id, message_ids)`：
    - 校验会话归属（creator 一致）与消息全部属于该会话，越界报 `Message not found in this session`
    - 轮次展开：传入的用户消息 id 按轮展开为该轮全部记录（用户消息 + 其后 bot 回复/报错/插件消息）；只传 bot 消息则直接删（不展开轮次）
    - 删除关联 threads（`delete_webchat_threads_by_parent_message_ids`）+ thread 会话（复用 `delete_threads_by_ids`，含 agent stop、队列清理）
    - LLM 上下文同步：有整轮被删时，按各轮 checkpoint 用 `find_turn_range` 从 conversation history 中移除对应轮（含 `_checkpoint` 段），大模型不再记得被删内容
    - 返回 `{deleted: 实删记录数, removed_turns: 整轮数}`；日志中文记录删除条数/轮数/分支数
- `astrbot/dashboard/api/chat.py`
  - 新增 `POST /api/v1/chat/sessions/{session_id}/messages/delete`（chat scope），body `{message_ids: [...]}`

### 前端

- `dashboard/src/components/chat/ChatMessageList.vue`
  - 新 props：`enableDelete` / `selectionMode` / `selectedIds: Set<string>` / `deleting`；新 emits：`enterSelectionMode` / `toggleSelected(turnKey)` / `exitSelectionMode` / `deleteSelected(turnKeys)`
  - **轮次归并**：`turnKeyById` 计算属性把每条消息映射到所属轮（key = 该轮用户消息 id；首条用户消息之前的孤儿 bot 消息 key = 自身 id）。勾选状态、高亮、可选判断全部基于轮 key——点气泡即勾选/取消整轮
  - 选择模式下：消息旁显示勾选圈（bot 在头像旁、用户消息在气泡左，`order: -1` 调整），选中轮整轮红色描边高亮（error 色）；本地占位消息（`local-` 前缀）所在轮不可选
  - 消息 meta 工具栏新增「多选删除」入口按钮（`enableDelete` 时显示）
  - 底部操作条 Teleport 到 body + dialog-transition 动画：「已选 N 轮」+ 取消 + 红色删除按钮（空选禁用、请求中 loading）
  - 确认弹窗用新增的 `askForConfirmationHtml`，数字标红：`<span class="confirm-dialog-highlight">N</span>`（error 色 + 加粗）
- `dashboard/src/components/chat/Chat.vue`
  - 多选状态管理（选中轮 key 集合）+ `deleteSelectedMessages`：调 `chatApi.deleteMessages`（turnKey 即各轮用户消息 id，后端按轮展开），成功 toast「已删除 N 轮消息」+ `loadSessionMessages(sessionId, false)` 刷新
- `dashboard/src/api/v1.ts`
  - `chatApi.deleteMessages(sessionId, messageIds)`
- `dashboard/src/components/ConfirmDialog.vue` + `dashboard/src/utils/confirmDialog.ts`
  - 全局确认弹窗扩展 `htmlMessage` 选项（v-html 渲染，优先于纯文本 message），保持原有纯文本路径完全不变
  - 新增 `askForConfirmationHtml()`：无全局弹窗时剥掉 HTML 标签回退 `window.confirm`
  - 高亮样式 `.confirm-dialog-highlight` 用非 scoped style（v-html 内容不受 scoped 作用域约束）
- `dashboard/src/i18n/locales/zh-CN/features/chat.json`
  - `selection` 块：入口提示/已选 N 轮/删除(N)/确认文案（N 轮消息、整轮连带删除、无法撤销）/成功失败词条
