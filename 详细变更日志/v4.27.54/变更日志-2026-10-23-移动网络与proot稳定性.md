# 变更日志 — 2026-10-23 — 移动网络与 Android proot 稳定性

## 背景

两个环境问题：

1. 移动网络/公共 DNS 被拦截时，glibc 偶发返回 `EAI_AGAIN`（Temporary failure in name resolution）。aiohttp 每次重连都会重新解析，失败一次整条连接就断，表现为 QQ 官方机器人一直卡在 “Websocket session starting” 循环里，并且 botpy 会为每次失败打印整段 traceback。
2. Android proot 环境下 SELinux 或 App 的假 `/proc` 可能让 `/proc/stat` 缺少 `btime`。`psutil.boot_time()` 因此抛 `RuntimeError`，导致重启前清理子进程、状态插件等全部失败，重启流程被阻断。

## 改动

### 1. `runtime_bootstrap.py`：DNS 重试 + 缓存

- 模块级保存原始 `socket.getaddrinfo`，替换为 `_getaddrinfo_with_retry`：
  - 仅对 `socket.gaierror` 且 `errno == EAI_AGAIN` 重试，最多 3 次，间隔 0.4s / 0.8s / 1.2s；
  - 其他 DNS 错误（如 `EAI_NONAME`）立即抛出，不做无意义重试；
  - 成功结果按 `(host, port, family, type, proto, flags)` 缓存 60 秒。
- 缓存淘汰：超过 512 条直接清空；超过 256 条时删除超过 TTL 的项。
- `install_dns_retry_patch()` 幂等，安装成功/已安装返回 `True`，安装异常记录错误并返回 `False`。
- asyncio 默认解析器在线程池里调用 `socket.getaddrinfo`，因此该补丁同时覆盖 aiohttp、httpx 等基于 asyncio 的请求。

### 2. `runtime_bootstrap.py`：psutil boot_time 兜底

- `install_psutil_boot_time_fallback()`：
  - 仅在能导入 `psutil._pslinux`（Linux）时生效，其他平台直接返回 `False`；
  - 包装 `_pslinux.boot_time` 与 `psutil.boot_time`，原函数失败时读取 `/proc/uptime`，用 `time.time() - uptime` 反推；
  - `/proc/uptime` 也读不到时按 `uptime=0` 返回当前时间，保证调用方不再抛异常。
- 该补丁是兜底逻辑，失败只记录错误，不影响主流程。

### 3. `initialize_runtime_bootstrap()`

顺序执行：CA bundle 补丁 → DNS 重试补丁 → psutil boot_time 兜底。返回值改为 `ca_ok and dns_ok`；boot_time 补丁失败不计入返回值（非 Linux 平台本来就会跳过）。

### 4. `qqofficial_platform_adapter.py`

- 新增 `_dns_error_is_temporary()` / `_is_transient_network_error()`：沿 `__cause__` / `__context__` 链判断异常是否属于可重试的网络错误（`ClientConnectorDNSError` 且临时、`gaierror` 且 `EAI_AGAIN`、`ClientConnectorError`、`ClientOSError`、`TimeoutError`、`ConnectionError`）。
- `ManagedBotWebSocket.on_error`：临时网络错误时只打一行 warning，并执行与 botpy 父类相同的 `self._connection.add(self._session)` 重连入队；非临时错误仍走父类逻辑。
- `run()` 改为 `_run_with_retry()`：`client.start()` 抛临时网络错误时按 5s 起、每次翻倍、上限 60s 的间隔重试；`asyncio.CancelledError` 与 `is_shutting_down` 直接退出，非网络错误原样抛出。

### 5. `process_restart.py`

- `_terminate_child_processes()` 增加 `(RuntimeError, OSError)` 捕获，记录 warning 后返回，不再让读取进程信息的失败阻断重启。

## 边界与风险

- DNS 缓存 60 秒，动态 DNS 场景下切换 IP 最长延迟 1 分钟；这是为减少移动网络解析失败做的取舍。
- `_is_transient_network_error` 把 `ClientConnectorCertificateError`（`ClientConnectorError` 子类）也视为可重试，证书配置错误时会持续退避重试而不是立即退出；对常驻机器人而言可接受，但排查时需注意日志中的证书错误。
- `time.sleep` 在 DNS 重试中最多阻塞 2.4 秒；正常路径由 asyncio 线程池调用，不阻塞事件循环。
- 补丁均为启动时安装，运行期不可关闭；非 Android/移动网络环境行为与之前一致。
