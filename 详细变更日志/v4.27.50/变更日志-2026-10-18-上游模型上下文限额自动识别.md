# [2026-10-18] 上游模型上下文限额自动识别

> 本文件为独立变更日志，记录「最大上下文」自动从模型服务方读取的功能：注册表、四优先级解析、两源采集与 WebUI 统一口径。

---

## 动机

提供商的「最大上下文 tokens」此前只有两个来源：用户手工填写，或内置静态表（`LLM_METADATAS`），两者都没有时一律按 128000 兜底。后果是：实际 200K / 1M 的模型被按 128K 提前压缩上下文或误报接近上限；内置表覆盖不了的长尾模型与兼容网关上的自定义模型全部吃兜底值；每接一个新模型都可能要手工查文档填数字。

而很多模型服务方其实在自己的模型列表接口里就带着限额信息——OpenAI 兼容网关（如 SiliconFlow）在 `/v1/models` 的条目上附加 `context_length` / `max_output_len` 等扩展字段，Gemini 的 `models.list` 返回 `inputTokenLimit` / `outputTokenLimit`。这些信息此前被直接丢弃。

## 设计

### 注册表

新模块 `astrbot/core/provider/upstream_model_limits.py`：进程内注册表，键为 `(provider_config["id"], model_id)`，值为 `{"context": int, "output": int}`（未知字段记 0，表示上游未给出；全部缺失则不登记）。`threading.Lock` 保护；同键覆盖、拉取列表前可按来源整体清理，防止上游下架的模型留下陈旧限额。

### 采集（两个源）

- **OpenAI 兼容源**（`openai_source.py`）：`_extract_upstream_limit` 从模型条目本身与 pydantic `model_extra` 里逐一探测已知扩展字段名——上下文类 `context_length` / `context_size` / `max_context_length` / `context_window`，输出类 `max_output_tokens` / `max_output_len` / `max_tokens_limit`。`/v1/models` 标准响应只有 id 等基础字段，探测不到时返回 None、不登记，行为与旧版一致。
- **Gemini 源**（`gemini_source.py`）：`get_models()` 遍历模型时顺带收 `input_token_limit` / `output_token_limit`。

两源均在 `get_models()` 成功路径上调用 `record_model_limits(provider_config["id"], ...)`；每次拉列表前 `clear_limits_for_source` 清残留。

**SDK 坑（实测踩到）**：google-genai 2.11.0 的 HTTP 响应解析路径 `_Model_from_mldev` 只把旧字段名 `supportedGenerationMethods` 映射为 `supported_actions`，不认新名 `supportedActions`（pydantic `model_validate_json` 路径才认后者）。给 Gemini 源写测试桩响应用旧字段名，否则 `supported_actions=None` 导致模型被过滤成空列表。

### 解析（四优先级）

手动配置 > 上游限额 > 内置静态表 > 兜底值（128000）。手工填写的 `max_context_tokens` 永远最优先；上游识别只在留空（≤0）时补位。

### 接入点

- **运行时**：`astr_main_agent.py` 的 `build_main_agent`——原逻辑「留空则查 LLM_METADATAS」扩为「留空则先查上游注册表、再查静态表」。
- **WebUI**（`config_service.py` + 新模块 `model_metadata_builder.py`）：模型元数据拼装统一走 builder，四处（`get_config` / `list_provider_source_models` / `list_provider_models` / `get_provider`）口径一致，模型列表里能看到识别到的上游限额来源。

## 验证

- 新增 `tests/test_upstream_model_limits.py` 6 项：扩展字段探测（model_extra 命中）、Gemini 桩响应采集（`supportedGenerationMethods` 旧字段名）、拉列表前残留清理、四优先级顺序（手动压过上游、上游压过静态表）、跨提供商同模型 ID 键隔离。
- 全量测试 434 通过（1 失败为 v4.27.49 遗留预存失败，与本功能无关）；`ruff check` 全仓通过。
- 本机 WebUI 实测：拉取模型列表后，上游带限额字段的模型显示识别到的上下文窗口；手工填写的值不被覆盖。

## 兼容性

- 上游未给出限额字段的接口行为完全不变（不登记，回落原优先级链）。
- 手动配置过 `max_context_tokens` 的提供商不受任何影响（优先级最高）。
- 配置结构无新增字段；注册表仅存内存，重启后随下次拉取模型列表重建。
