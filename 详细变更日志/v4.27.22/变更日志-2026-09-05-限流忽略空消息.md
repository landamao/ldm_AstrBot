# 新增：限流忽略空消息（`platform_settings.rate_limit.ignore_empty_message`）

- 日期：2026-09-05
- 背景：NapCat（QQ）等平台会把"用户正在输入"等状态作为**内容为空的消息事件**短时间大量推送。这些空消息此前与正常消息一样参与限流计数，导致限流（默认 60 秒 30 条）很快被状态消息刷满，正常消息被 stall 拖住（日志中可见空消息事件后紧跟"会话被限流，将暂停 N 秒"）。

## 改动

### `astrbot/core/pipeline/rate_limit_check/stage.py`

- 新增配置项 `ignore_empty_message`（默认 **True**），在 `initialize` 读取（`.get(..., True)` 兼容旧用户配置缺键）。
- `process()` 入口处：开启配置且消息为空时直接放行——**不计数、不 stall**。
- 新增 `_is_empty_message` 判定：消息链为空，或所有组件都是 `Plain` 且 `text` 为**空字符串**时视为空消息。判定口径（经用户确认）：
  - 用户发送的**空格等有字符的文本是真实消息，正常计数**（不做 strip）；
  - 含 `At`/`Image` 等非文本组件的消息不算空消息，正常计数。

### `astrbot/core/config/default.py`

- `DEFAULT_CONFIG`：`platform_settings.rate_limit` 新增 `"ignore_empty_message": True`。
- `CONFIG_METADATA_2`（校验）：rate_limit.items 新增 `"ignore_empty_message": {"type": "bool"}`。
- `CONFIG_METADATA_3`（WebUI 表单）：新增「空消息不计入限流」开关，hint 说明判定口径与适配场景。

## 测试

`tests/test_rate_limit_empty_message.py`（脚本式，`python tests/test_rate_limit_empty_message.py`），5 用例：

1. 空消息链不计数、正常消息计数；
2. 空字符串文本不计数，**空格文本计数**（真实内容）；
3. 仅 `At` 组件的消息计数；
4. 计数已满时空消息到达不 stall 也不计数（本次 bug 场景，`asyncio.wait_for` 超时断言）；
5. 关闭配置恢复旧行为：空消息计数、队列满时触发 stall（对照）。

ruff（改动文件范围）通过。

## 补充：WebUI 标签文案（源码语言文件 + 重新构建）

CONFIG_METADATA_3 的 description/hint 会被 `ConfigMetadataI18n` 转成 i18n key，由**前端内嵌的语言字典**解析（`dashboard/src/i18n/locales/zh-CN/features/config-metadata.json`）。新字段没进字典时，配置页会把裸 key `platform_settings.rate_limit.ignore_e...` 直接当标签显示。

修复：在该语言文件 `platform_group.rate_limit.platform_settings.rate_limit` 下补上 `ignore_empty_message` 的 description + hint（与 `strategy` 同级），然后 `corepack pnpm build` 重新构建 dashboard。注意构建会清空 dist，`dist/assets/version` 与 `dist/version`（兼容性检查读 `assets/version`，当前 `v4.27.21`）需先备份、构建后写回。构建后入口 JS 哈希变化（`index-DDiFuWv0.js`），浏览器缓存自动失效，强刷即可；后端无需重启（静态文件实时读盘）。
