# [2026-10-14] 禁更环境变量状态可视化（启动警告日志 + 关于弹窗黄字提示）

> 本文件为独立变更日志，记录 LDMBOT_DISABLE_UPDATE 状态显性化的动机、实现链路与兼容性考量。

---

## 动机

`LDMBOT_DISABLE_UPDATE`（v4.27.45 引入）启用后本次启动拒绝一切主程序更新（源码与 WebUI）及回滚，但此前它**静默生效**：

- 启动日志里没有任何「当前处于禁更状态」的提示（该变量的四段警告文案只在拦截动作发生时才出现）；
- WebUI 界面上更新入口照常可点，点了才报错；
- 排障时容易走弯路：WebUI 更新按钮点了没反应、回滚报「已禁用」，翻半天日志才想起是环境变量挡的。

需要一个「不点更新也能确认状态」的途径。定案两处出口：WebUI 就绪时打一次警告日志（看日志的人）+ 关于弹窗常驻黄字提示（看界面的人）。均只在启用时出现，未启用时不产生任何噪音。

## 改动内容

### 后端（2 个文件）

1. `astrbot/dashboard/server.py`（`run()` 内，WebUI 就绪横幅之后）：

   ```python
   # 同理，禁更环境变量也在 WebUI 就绪后补打一次，方便确认其处于生效状态
   if is_update_disabled():
       logger.warning(禁用提示)
   ```

   位置紧跟既有的 `warn_deprecated_reset_env_vars("dashboard_ready")`——沿用同一先例：配置加载期的警告容易被启动过程的大量日志刷屏淹没，WebUI 就绪后再补打一次。复用 `update_guard.py` 导出的统一判定 `is_update_disabled()` 与统一文案 `禁用提示`，与 `/upldm` 聊天指令、`update_service` 更新闸门、`update_rollback` 回滚闸门被拒时的报错完全同源。

   注：`update_guard.py` 模块 docstring 说明 `update_rollback.py` 因纯标准库约束无法 import 该模块而内联了同一判定——本次新增的两处都走 import，不涉及那处内联，三处同步义务未增加。

2. `astrbot/core/utils/about_info.py`（`get_about_info()` 的 `ldm` 段末尾）：

   ```python
   "update_disabled": is_update_disabled(),
   ```

   `about_info` 同时供 WebUI 关于弹窗（`/api/v1/stats/about`）与内置指令 `/about` 共用；本次只在 WebUI 弹窗消费该字段，指令侧输出暂不追加（指令用户可直接看环境变量，且改指令输出要同步其快照测试）。

### 前端（3 个文件，ldmbot-dashboard 源码仓）

1. `src/api/v1.ts`：`AboutData.ldm` 补 `update_disabled?: boolean` 字段。
2. `src/components/shared/AboutDialog.vue`：信息区（目录列表）与按钮区之间插入条件节点——

   - `v-if="info.ldm?.update_disabled"`，未启用时完全不渲染（无占位、无 DOM、无闪烁）；
   - 黄字用 `color: rgb(var(--v-theme-warning))`，与全库既有 warning 主题用法一致（App.vue、ProviderModelMenu.vue、CommandTable.vue 同款写法）；
   - 图标 `mdi-alert-outline` + `text-body-2` 字号，视觉上是「注意」而非「错误」，与 error 级区分。

3. `src/i18n/locales/zh-CN/features/about.json`：`dialog.updateDisabledNotice` 新条目：「注意：你已启用禁止更新环境变量（LDMBOT_DISABLE_UPDATE），本次启动拒绝一切主程序更新与回滚操作。」

### 测试

`tests/test_update_disabled_env.py` 新增 `test_about_info_reports_update_disabled`：设 `LDMBOT_DISABLE_UPDATE=1` 时 `get_about_info()["ldm"]["update_disabled"] is True`，删除后 `is False`。该文件自带 `autouse` fixture 先清掉本机环境变量，防泄漏影响判定。

## 设计取舍

- **为什么放在关于弹窗而不是设置页**：禁更是环境变量决定的状态，不是 WebUI 可改的配置——放设置页会暗示「可以在这里关掉」，实际上必须移除环境变量重启。关于弹窗是纯只读状态页，语义匹配。
- **为什么弹窗提示不做成独立 API 而搭 `stats/about` 顺风车**：关于弹窗打开时本来就请求该接口，加一个布尔字段零额外请求；状态与关于页其他运行信息（版本、启动命令）同源同刻，不会出现两个接口读到的状态不一致。
- **为什么日志放 WebUI 就绪后而不是 run() 开头**：见上文「动机」段引用的先例——启动早期日志会被横幅动画与大量初始化日志淹没。
- **`/about` 路由页（纯项目介绍页，标题+Star/Issue 按钮）不加提示**：该页无任何数据加载与运行状态，加提示要为它引入一次 API 请求；禁更状态的消费场景是「运维确认」，关于弹窗已覆盖。

## 兼容性

- `update_disabled` 为**新增**字段：旧版 WebUI 调新后端会忽略未知字段；新版 WebUI 调旧后端读到 `undefined`，`v-if` 判假同样不显示提示。双向都不会报错。
- 判定实时读进程环境变量（`is_update_disabled` 每次调用现取 `os.getenv`），环境变量在进程外无法被修改，效果等同启动时固化——无需缓存失效逻辑。
- 禁更拦截逻辑本身一行未动，本变更纯粹是「让状态可见」。

## 实测效果

- 启用 `LDMBOT_DISABLE_UPDATE=1` 启动：WebUI 就绪横幅后出现一条 `WARNING`，内容为统一禁用提示文案；关于弹窗出现黄字提示。
- 未启用启动：无该日志，弹窗无提示节点。
- dist 重建后产物 grep 确认：`update_disabled`（FullLayout chunk）与黄字文案（index chunk）均已编入。

## 回归点

- `AboutDialog.vue` 后续新增展示字段时，黄字提示块保持在「信息区之后、按钮区之前」的位置，它是状态警示而不是普通信息行。
- 以后若把禁更判定改为缓存值（如启动时算一次存起来），记得 `about_info` 与 `server.py` 两处一起换，保持口径一致。
