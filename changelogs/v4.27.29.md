# [4.27.29] — 2026-09-14 — /compact 参数解析崩溃修复与 /plugin 指令显示名匹配

本版本包含 1 项问题修复与 1 项体验增强：修复 `/compact` 指令带任何参数必崩的问题，`/plugin` 管理指令全面支持按显示名定位插件。

## 🛠️ 问题修复（1项）

### 1. /compact 带数字参数必崩（TypeError）

此前发送 `/compact 4`（以及任何带参数的形式）会直接报错且无任何回复，后台日志出现 `TypeError: '>' not supported between instances of 'tuple' and 'int'`。

- 根因：参数解析函数的返回值是 `(值, 错误提示)` 二元组，指令侧误当单个数字使用，导致所有非 `yes` 参数（数字、乱码、空串）都在解析处崩溃。
- 修复后按约定解包使用：无法解析为数字时返回「参数无法识别」用法提示；`0`/负数轮数（如 `/compact 0`）此前会静默忽略参数执行，与帮助文案「保留最近N轮」语义矛盾，现同样归入用法提示。
- `/compact`、`/compact yes`、`/compact <N>` 的正常行为不受影响。

### 2. LLM 摘要压缩前新增「正在压缩」提示

走 LLM 摘要的压缩耗时较长（需等待压缩模型返回，可达数十秒），期间会话里全程无反馈，容易以为指令没生效而重复发送。

- 现在 LLM 摘要路径在调用压缩模型前，先即时发送「正在压缩上下文（LLM 摘要（保留最近 N 轮）），请稍候…」，N 为实际生效的保留轮数（显式参数或配置默认）。
- 完成后照旧回复压缩结果，两条消息都有；按轮次截断路径（`/compact yes`）是本地操作无耗时，不追加提示。

## ✨ 体验增强（1项）

### /plugin 指令支持显示名匹配：按显示名定位插件，模糊命中给候选不执行

插件的真实插件名（如 `astrbot_plugin_stealer`）与显示名（如 `表情包小偷`）不一致时，此前直接输显示名会报「插件名不存在」，必须先 `/plugin ls` 查内部名再复制；名字输错也只有一句报错，不知道相近候选。

现在 `/plugin` 的 on / off / restart / update / help 五个子指令全面支持显示名匹配：

- 插件名精确命中 → 直接执行（原行为，优先级最高）。
- 显示名精确且唯一命中 → 直接执行，内部自动落到真实插件名。
- 模糊命中（插件名与显示名做不区分大小写的包含匹配）→ 不执行，返回候选提示与完整可复制指令，确认后再用；唯一命中提示「你可能要……的插件是」，多个命中返回编号候选列表。
- 候选统一「显示名（插件名）」格式，无显示名的插件用插件名补位，括号内的值即需要复制的插件名。
- `/plugin` 指令组帮助末尾新增说明：`<插件名>` 也可填插件显示名（需完全一致），模糊命中时会给出候选列表。
