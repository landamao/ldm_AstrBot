# [4.27.62] — 2026-11-12 — 备份恢复改为「先备份 + 原子替换」、恢复结果逐目录可判定、WebUI 动效开关

本版重做了**备份恢复的兜底模型**：不再依赖 `.bak` 副本，改为「恢复前先整包备份 + 恢复时原子改名替换」，顺带修掉 Windows 上恢复失败会把现有目录**掏空到只剩被占用文件**的严重 bug；恢复结果**逐目录可判定**（哪个目录失败、为什么、界面上一眼可见），目录被占用时按目录类型说人话并给出**真实可复制的恢复命令**；WebUI 确认页把「先备份」变成默认开启、需主动拒绝的强提示，失败后可直接**一键还原**刚生成的前置备份。另新增终端 `--backup` 与 WebUI 全局 Q 弹动效开关。

## 🚀 新功能

### 1. 终端 `--backup`：不开服务直接打包当前数据

- `main.py` 新增 `--backup` / `--备份 [输出目录]`：不启动服务，直接把当前 `data/` 打成 ZIP，格式与 WebUI 导出的备份完全一致，可直接用 `--restore-backup` 或 WebUI 恢复。
- 全新环境先 `db_helper.initialize()` 建表再打包，已有数据库一律不动；CLI 没有 `kb_manager`，走 `include_knowledge_base` 整目录打包，知识库不会漏。
- `--backup` 与 `--restore-backup` 都进启动横幅跳过列表，不会再打出无关的服务启动提示。

### 2. 恢复前自动整包备份（WebUI 与终端共用）

- 新增 `create_pre_restore_backup()`：按**当前进程真实的 db / config 路径**导出一份 `*_pre-restore.zip`，WebUI 恢复与终端 `--restore-backup` 都走同一份实现。
- `BackupService.import_backup()` 新增 `backup_first`（默认 `True`）：前置备份**失败就直接中止，一个字节都不动**，不再出现「备份没做成但数据已被覆盖」。
- 备份结果通过 `pre_restore_backup` 回传前端，界面可直接下载或用它还原。

### 3. WebUI 恢复失败后可「立即还原这份备份」

- 失败页在前置备份存在时提供「下载」与「立即还原」两个出口，不必再跑去备份列表里翻找刚才那份 `pre-restore` 包。
- 若本次恢复关闭了「先备份」，该区块不出现，只保留错误说明 —— 不会给一个不存在的还原入口。

### 4. WebUI 全局 Q 弹动效开关

- 新增 `GET/PUT /ui-preferences/motion`（含同名 legacy 路由 `/api/ui-preferences/motion`），落库键 `dashboard_motion_effects`；**默认开启**，只有明确关闭时才写库，reset / clear 即删除记录恢复默认。
- `normalize_motion` 兼容裸 bool、字符串 `"false"`、数字 `0` 等写法，前端传什么都不会把开关置成奇怪状态。

## 🛠️ 重构与修复

### 5. 恢复不再产生 `.bak`：目录替换改为原子改名

旧实现用 `shutil.move(target → target.bak)`，在 **Windows 上会掏空现有目录**：`os.rename` 被占用文件拦下后 `shutil.move` 会退化成 `copytree` + `rmtree(src)`，拷贝能成功（被占用的文件可读），随后 `rmtree` 在锁文件上抛 `WinError 32` —— 此时目录里除锁文件外的内容**已经被删掉了**。实测四个文件只有 `native.pyd` 被占用，失败后 `plugins/` 里只剩 `native.pyd`。

- 目录替换改为纯原子改名：先解压到同级 staging（`data/.<name>.importing`）→ `os.rename` 把现有目录移成 `.old-<时间戳>` → 再 `os.rename` staging 就位 → 成功后立刻 `rmtree` 中转。第三步入位失败且已改名则回滚原名；回滚也失败时错误里直接给出旧数据的完整路径，**不假装成功**。代码中留注释禁止改回 `shutil.move`。
- 配置文件改用「同目录写 `.restoring.tmp` + `os.replace` + `fsync`」：要么旧内容、要么完整新内容，不再 `copy2` 出 `.bak`。
- 恢复与导出互斥：两者共用同一份 `.importing` 暂存目录，且恢复期导出会拍出半旧半新的脏快照，改为已有 import / export 任务就拒绝。
- `export_all` / `get_backup_directories` 增加 `include_knowledge_base` 开关，新增 `get_restorable_directories()` 让导入端识别全部目录类型；旧备份行为不变。
- 新增两个回归用例：恢复后 `data/` 下不得出现 `.bak` / `.old-*` / `.importing` / `.restoring.tmp`；monkeypatch `os.rename` 抛 `WinError 5` 时断言 `success=False`、目录内文件全在且内容未变（**旧实现在这条上会失败**）。

### 6. 恢复结果逐目录可判定，失败等级纠正

- `ImportResult` 新增 `directory_results`（`status: ok|failed|skipped`、`files`、`error`）与 `set_directory_result()`，`to_dict()` 一并透出；恢复结束能逐目录看到「恢复了多少文件 / 哪个失败 / 为什么」。
- **失败等级纠正**：目录替换、解压、配置文件导入、知识库导入从 `add_warning` 改为 `add_error`（`success=False`）。此前插件目录一个都没恢复，任务照样 `completed`、WebUI 显示绿勾「导入完成」；知识库尤其必须显式 —— 它在导入前已被 `_clear_kb_data()` 清空，失败就意味着数据缺失。
- 单个附件、单个文档块、KB 媒体文件失败仍只记 warning（不阻断整体恢复），但不再只写日志、界面上完全看不见。
- 失败时也回传结果明细：`_set_task_result(..., result=payload, error=...)`，`get_progress()` 在 `failed` 下同样返回 `result`（此前只有 `completed` 带）。

### 7. 错误带全量堆栈，界面只说人话

- `add_error()` / `add_warning()` 新增 `exc_info`，所有 catch 分支统一传异常；`pre_check` 的 `BadZipFile` / `JSONDecodeError` 也补上堆栈。原则是**日志要全、界面要短**，Traceback 只进 `data/logs/ldmbot.log`。
- 目录替换失败时不再把 `OSError` 原文里的中转路径糊到界面上（此前会显示 `... -> '...\data\.plugin_data.old-20261112_034619'`，用户第一反应是「这个 `.old` 是什么」）。
- 目录级失败文案由「现有数据未改动」改为「该目录保持原样（未替换）」，避免用户以为整个恢复毫无效果。

### 8. 目录被占用时说人话，并给可执行的命令

- `_is_directory_lock_error` 认 Windows `winerror 5/32` 与 POSIX `EBUSY`（普通 `EACCES` 不误判）；`_detect_directory_holders` 用 `psutil` 反查是哪个插件占着目录；`_locked_directory_hint` 按 `plugins` / `plugin_data` / `knowledge_base` 给不同建议。
- 新增 `suggest_terminal_restore`：只在**服务进程内恢复**时才提示「停掉服务去终端恢复」；终端恢复本身改为提示「可能还有另一个 ldm 进程占用」。
- 恢复命令改取 `about_info.build_restore_command()` 的**真实解释器路径**（复用 `sys.executable + sys.argv`，透传 `--data-dir/--webui-dir`，带空格路径自动加引号），不再是写死的 `python main.py` —— 照抄到 venv 会跑到另一份 Python 上。

### 9. WebUI 恢复页强提示、逐目录结果、状态复位

- 确认页新增红框卡片「先备份，再恢复」：勾选框**默认开启**，取消勾选后追加红色实心警告 + 必须再勾「我已了解风险，仍然不备份直接恢复」，否则确认按钮 `disabled`。
- 完成 / 失败页展示逐目录明细（`filesCount` / `skipped` / `failedLabel`），修掉同一句错误被渲染两遍（`data.error` 与 `result.errors` 同时显示）的问题；全部失败与部分失败分别给不同说明。
- `open()` 打开对话框时复位 `backupBeforeRestore = true` / `riskAcknowledged = false` / `importResult = null`，安全开关**不会记住上一次的取消状态**。

## 📌 升级说明

- 本次为后端 + 前端混合改动：更新后需**重启**；WebUI 普通刷新即可。
- **行为变化（重要）**：
  - 恢复**不再生成 `.bak` 副本**，兜底完全依赖「恢复前备份」。WebUI 默认开启且需显式取消，终端 `--restore-backup` 默认 `Y`。**没有备份就直接恢复，覆盖后无法找回。**
  - 历史遗留的 `*.bak`（`data/` 下的 `plugins.bak` / `plugin_data.bak`、`config` 下的 `.bak`）**不会自动清理** —— 属于用户数据，需要时请人工确认后再删。
  - 恢复失败现在会**如实报失败**（此前插件目录没恢复也可能显示绿勾）。看到失败不等于数据被破坏：失败的目录保持原样，已成功的部分不会自动回滚。
  - 恢复仍建议**停服务进行**：在线替换 `plugins` / `plugin_data` 即使成功，也会让正在运行的插件拿着旧路径。
- 无数据库迁移、无配置迁移；动效开关属新增记录，删掉即恢复默认。
- 详细变更见「详细变更日志/v4.27.62/」。
