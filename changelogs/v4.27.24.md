# [4.27.24] — 2026-09-06 — 新增 .env 环境变量文件支持、插件报错不中断事件配置

本版本包含 2 项重要新增，围绕部署配置灵活性与插件容错性。重点推荐关注「.env 环境变量文件支持」：以后所有 LDMBOT_* 环境变量都有一个集中、可见、可直接编辑的落点。各变更的完整细节见项目「详细变更日志/v4.27.24/」目录。

## ✨ 新增

### .env 环境变量文件支持：环境变量集中管理，缺失时自动生成示例

#### 背景

此前所有 LDMBOT_* 环境变量只能写进系统环境变量或作为启动命令前缀（如 `LDMBOT_DASHBOARD_PORT=8080 python main.py`），对 Windows 计划任务、服务、桌面快捷方式等启动方式很不友好；也没有一个集中位置能查看全部可用变量，每次都要翻 `main.py --help` 手抄。

#### 核心改善

启动时（main.py 与 CLI `run` 均生效）自动加载项目根目录的 `.env` 文件；文件不存在时自动生成一份带完整说明的示例模板——所有变量集中一处、注释即说明，按需取消注释即可启用。

- 示例模板覆盖全部 42 个环境变量（含 https_proxy/http_proxy），按分节排列，中文说明按显示宽度对齐；模板全部处于注释状态，去掉行首「# 」即生效；
- 优先级清晰：命令行参数 > 系统环境变量 > .env 文件；真实环境变量始终优先（.env 只作默认值），已有部署升级后行为完全不变；
- 已存在的 .env 永不覆盖、不改写；写入失败（只读目录等场景）仅打印警告，不影响启动；
- `main.py --help` 的「环境变量」一节补充了文件位置、自动生成行为、启用方式与优先级说明。

#### 使用方式

文件位置：项目根目录（与 main.py 同目录）。首次启动后打开 `.env`，去掉所需变量行首的「# 」并填入值，重启后生效。

### 插件报错不中断事件配置（plugin_error_continue）

#### 背景

此前插件处理函数（指令/事件监听）抛异常时会直接终止整个事件：同一事件后续还未执行的插件 handler 全部跳过，结果装饰、发送等后续流程也全部中断。多个插件同时监听同一事件时，一个插件的 bug 会放大成「整条链路失效」。

#### 核心改善

新增配置开关「插件报错不中断事件」，默认关闭、保持现有行为；开启后插件报错只记录日志并触发错误事件钩子，随后直接继续执行后续插件——不发错误文案、不终止事件，报错的插件如同不存在。

- 开启后：插件报错仅记录日志，继续执行后续插件 handler 与事件流程，单个插件的故障不再波及其他插件；
- 不发错误回复文案：文案一旦发出会被视为「本事件已有回复」，导致唤醒消息的 LLM 请求被跳过；继续模式下事件结果保持为空，报错插件的会话照常进入 LLM 处理；
- 配置运行时读取，WebUI 修改后即时生效，无需重启；
- 存量部署无需手动迁移：启动时自动补默认值（关闭）。

#### 配置位置

WebUI → 配置文件 → 插件配置 →「插件报错不中断事件」。
