# [4.27.38] — 2026-09-26 — 无正文重试、主模型失败回退开关

本版本解决两类模型链痛点：模型偶发「只回思考不回正文」导致艾特 AI 消息落空；以及想单独锁定某个模型使用时必须反复改回退链配置。顺带把 LLM 请求失败的错误文案统一为中文化。

## ⭐ 重点新增（2项）

### 1. 模型无正文时重新请求 + 重试方式

LLM 响应只有思考字段、无正文也无工具调用时（日志表现为「（仅有 reasoning，无正文）」），原先被当作合法结果接受，聊天里表现为艾特 AI 后毫无反应。

现在「配置-AI」里新增开关（默认开启）：命中上述情况就继续重试，直到拿到正文或工具调用（最多尝试 5 次，防失控）。并配套「重试方式」：

- **请求回退模型**：当前模型无正文输出即判定为失败，继续请求回退模型列表（若有且已开启回退）。
- **重试当前模型**（默认）：有思考输出说明当前模型可正常工作，继续重试当前模型直到吐出正文或工具调用，失败则回退（若已开启回退）。

两个配置项位于「开启主模型失败回退」下方。关闭开关则回到旧行为。重试判定在 agent 层统一实现，各模型源通用；工具调用响应不会被误判。

### 2. 开启主模型失败回退

「配置-AI」的「对话模型链」正下方新增开关（默认开启）。关闭后主模型失败就直接抛错、不尝试任何回退模型——想固定用某个模型完成任务时，不必再破坏配好的回退链。回退链配置保持原样，随时可重新打开。与 WebChat 消息级的回退开关叠加生效（任一关闭即不回退）。

## ✨ 体验优化（1项）

### 1. LLM 请求失败错误中文化

用户可见的错误框架文案统一为中文：「所有对话模型均请求失败：…」「AI 执行过程中出现错误。错误类型/错误信息…」等，覆盖内置执行器、第三方执行器（Dify/Coze/DeerFlow）与切换回退的排查日志。第三方 SDK 的原始错误信息作为技术细节保留，WebChat 折叠错误块内可展开查看。
