# [4.27.15] — 2026-08-30 — ChatUI 断线续流、生图会话重试菜单与停止按钮、工具轮次落库修复、命令参数类型注解解析、stop/打断行为重做

本次更新包含 4 项新增、3 项体验优化、2 项修复。全部为 ldmbot 本地改动。

### 新增

- **ChatUI 断线续流**（参照官方 PR #9259）
  - LLM 聊天：将 `back_queue` 消费与 SSE 推送解耦——新增 ChatRunState 后台消费任务独立消费队列、累积、落库并扇出给所有订阅者，订阅者随时离开或重连都不影响消费；离开页面再回来不丢 AI 回复
  - 断线续流入口 `GET /api/v1/chat/runs/{runId}/stream`：找到活跃 run 后先发已累积的完整快照，再推送增量事件；前端带 5 次指数退避重试
  - 生图会话：后端标记生成中状态，会话返回 `is_running`；前端插入「生成中...」占位并 5 秒轮询，生成完成自动替换图片，无需手动刷新
  - 修复切换会话闪屏：点回当前正在进行的会话不重新加载消息列表

- **WebChat 重试权威化**（后端下发 `can_regenerate` 标志）
  - 后端逐条消息计算并下发 `can_regenerate`，前端优先认该标志；插件/指令消息不再误显重试按钮（此前会报 "Linked checkpoint not found"）
  - llm_error 报错消息始终可重试：以同 checkpoint 的用户消息为源重新发起请求，删除旧报错记录，不截断历史；报错后再次点击不再报 "Invalid key: message_id"
  - SSE 与 WebSocket 两条通路的 `message_saved` 事件同步携带标志，本地流式消息落库后无需刷新页面即可正确显示/隐藏重试按钮
  - 重试模型兜底顶部当前选择：直接点重试按钮时不再回退到配置主模型

- **命令参数解析尊重类型注解**（对齐上游 PR #9866）
  - 参数转换目标由「默认值的运行时类型」改为「声明的类型注解」，默认值仅用于参数缺省时填充
  - `text: str = None` 这类参数收到 `123` 时传入 `str` 而非 `int`；纯注解 `flag: bool` 能正确解析 `true/false`、`yes/no`、`1/0`
  - 新增 `_convert_param()` 统一转换：str 原样返回、bool 多写法解析、Optional/Union 解包递归、普通类型构造转换；无注解无默认值参数行为不变
  - 缺参时按默认值填充，无默认值才报「必要参数缺失」；错误提示改为「注解标签 + 默认值」渲染

- **WebUI 版本文件防泄漏**
  - `/version`、`/assets/version` 不再通过静态通道对外提供（一律 404），未登录用户读不到版本号；版本信息改走 `/api` 获取

### 体验优化

- **生图会话重试菜单**（对齐聊天会话）
  - 重试按钮改为与聊天会话一致的弹出菜单：**重试**（删除最后一条 bot 消息，按原提示词 + 当前选中的生图模型重新生成）/ **使用其他模型**（列出全部已启用的生图提供商，选中后用该模型重新生成）
  - 「使用其他模型」仅本次生成使用所选模型，不改写默认选中的生图模型
  - 生成期间发送按钮切换为停止按钮，点击即中止生成；中止后占位消息显示「已停止生成」
  - 聊天会话重试菜单行为不变

- **工具图片处理重做**（跟随「始终使用默认图片转述模型」全局配置）
  - 工具生成的图片与用户发来的图片走同一套模态/转述配置逻辑：模型支持图片输入且未开启「始终转述」时回注原图供模型审查；否则不回注，先用「默认图片转述模型」生成描述写进工具结果，图片由 LLM 手动调用发送工具发出（框架不代发）
  - 不支持视觉的渠道（如 ldmapi 的 glm 渠道）不再收到 base64 大图，消除 `Model do not support image input` 400 报错与无谓的提供商回退；上下文不再被工具图片撑爆
  - 模态判定统一为 `provider/modalities.py:provider_supports_modality`（收图路径与工具图片路径共用）；图片压缩配置解析与实现统一下沉 `utils/media_utils.py`，删除两处重复实现

- **工具管理文案中文化**
  - 函数工具的权限设置与启用/停用操作的报错、回执全部改为中文（如「工具「xxx」不存在」「工具「xxx」权限已更新为 管理员」），并补充成功日志

### 修复

- **工具轮次整轮不落库**（影响 QQ 等非 WebChat 平台）
  - 落库调用被错误缩进在 checkpoint 判断内，而该 extra 仅 WebChat 适配器会设置，导致工具发送消息结束的轮次（如生图轮）整轮静默丢弃——历史凭空缺轮、bot 不记得刚做的事、上下文 token 骤降
  - 修复后落库调用对所有平台无条件执行；事故期间已丢失的历史轮次无法追回，修复后新轮次正常落库
  - 工具轮次落库修复涉及 6 个文件需一起生效（internal.py / tool_loop_agent_runner.py / modalities.py / astr_main_agent.py / image_tools.py / media_utils.py）

- **stop/打断行为重做**
  - 停止/打断都只做强行停止，已生成内容仍投递给用户（此前 /stop 强制停止会丢弃缓冲内容）
  - 删除「将打断提示写入对话上下文」开关及配套文案配置项，打断提示文案固定为「已打断当前回复，开始处理新消息。」；打断功能开关本身仍可配置
  - 已发送内容仍存上下文并附带英文标记，让模型知道回复被截断
