# [4.27.45] — 2026-10-10 — 终止传播归因修复与更新回滚加固

本版本三条主线：一是事件终止传播的日志归因从「事后时序猜测」改为「停止时留痕、真实归因」，并让已死事件不再执行任何钩子处理器；二是修复 main.py 光标兜底信号处理器吞掉 SIGTERM、导致 systemd 停机卡满 90 秒的问题；三是更新与回滚链路加固——新增 `LDMBOT_DISABLE_UPDATE` 环境变量一键禁用全部主程序更新与回滚，回滚备份从「只含 main.py」补全为 12 个根目录文件，WebUI 回滚管理新增「立即备份」，并把「备份/回滚只含程序代码、不涉及运行数据」的提示铺满 CLI 与 WebUI 全部入口。

## 🛠️ 问题修复（3项）

### 1. 终止传播日志错误归因：从时序猜测改为停止时留痕

旧机制在处理器执行后的检查点上把终止归给「刚执行完的那个插件」，事件被 `/reset`、`/stop` 等指令经 stop_all 外部终止、或插件 yield 后的挂起窗口内被打断时，无辜插件背锅，且首个（可能错误的）归因独占日志与 WebChat 终止卡片。现在首次 `stop_event()` 时把调用栈（仅 code 对象 + 行号）留在事件上，输出日志时由内向外匹配注册处理器真实归因；判断不出来源时输出固定文案「事件被终止传播，未找到调用点」，不回退时序猜测。日志与卡片均附带消息概要，便于定位是哪次对话。

行为变化（插件开发者注意）：事件已死后不再执行任何钩子处理器（含 on_after_message_sent）——依赖钩子做全量出站审计的插件会受影响。

### 2. SIGTERM 被光标兜底处理器吞掉，systemd 停机卡满 90 秒

main.py 为修「终端光标永久消失」注册的 SIGTERM 处理器只恢复光标、不终止进程，systemd stop 时进程要卡满 TimeoutStopSec（默认 90s）才被强杀，期间看似「停不下来」。现在处理器恢复光标后把信号交还默认终止（SIG_DFL + 重发），WSL 实测信号后 16ms 退出、退出码 143、光标恢复字节正常写出。

### 3. 回滚备份缺根目录文件，回滚后「旧源码 + 新依赖清单」混杂

更新包会覆盖 main.py、requirements.txt、pyproject.toml 等根目录文件，而回滚备份此前只打包 main.py 一个——回滚后旧源码配新依赖清单，行为错乱且难以排查。现在备份与恢复覆盖 12 个根目录文件（main.py、runtime_bootstrap.py、requirements.txt、pyproject.toml、uv.lock、.env.example、.gitignore、LICENSE、NOTICE、README.md、CHANGELOG.md、从官方迁移教程.txt），旧备份缺哪个文件就保持现状并提示。

## 🚀 新功能（2项）

### 1. LDMBOT_DISABLE_UPDATE 环境变量：一键禁用主程序更新

置为 true/1/t 后，本次启动拒绝一切主程序更新操作：核心源码更新、WebUI 更新、上传更新包、`/upldm` 指令、WebUI 更新按钮、`--rollback` 命令行回滚与 WebUI 回滚，无强制继续途径；插件更新不在管辖范围。适合部署在由外部流程（如 git pull + systemd）统一管理代码的机器上，避免误触更新把代码状态搞乱。

### 2. WebUI 回滚管理新增「立即备份」

回滚管理对话框新增「立即备份」按钮，随时把当前版本源码与 WebUI 打包进回滚目录（只读打包、不影响运行），不必等到更新前才被动生成备份；核心更新进行中会拒绝，同版本已有备份将被覆盖（先弹确认）。

## ✨ 体验优化（1项）

### 1. 「备份/回滚只含程序代码，不含运行数据」提示铺满全部入口

「回滚会不会把数据也滚回去」是高频误解。现在 CLI 的 --rollback 帮助、交互式回滚列表、回滚执行时，与 WebUI 的回滚设置项、回滚对话框顶部、回滚确认弹窗，都明确标注：data/ 目录（数据库、配置、会话记录、知识库等）不进备份、回滚不碰。
