# [4.27.46] — 2026-10-14 — 插件 API 完善：发送回执、裸字符串产出与指令查询

本版本五条主线都面向插件开发体验：一是 `event.send()` 开始返回发送结果（`MessageSendResult`），插件终于能拿到平台侧消息 ID，撤回、引用、表情回应等后续操作有了抓手；二是 handler 产出裸字符串自动按纯文本发送，`yield "文本"` 不再静默无效；三是新增 `Context.get_all_commands()`，插件可查询全部已注册与已启用的指令；四是 `@filter` 全家桶的 `priority` 参数从 `**kwargs` 隐式透传改为显式签名参数，IDE 补全与类型检查终于看得见；五是 StarTools 的 docstring 与运行时报错中文化。此外本轮做了一次 ruff 全仓整理，并修掉了三个测试文件随本机配置漂移的预存失败。

## 🚀 新功能（2项）

### 1. event.send() 返回发送结果（MessageSendResult）

`await event.send(chain)` 此前返回 `None`，而协议端其实一直有响应——OneBot 的 `send_group_msg` / `send_private_msg` 响应里本就带 `message_id`，只是适配器把它丢掉了。现在返回统一的 `MessageSendResult`：`message_id` 为平台侧消息 ID（统一转字符串，跨平台写法一致），`raw` 原样保留平台原生响应（OneBot 下即响应 dict），纯透传的能力一点没丢。

aiocqhttp 完整透传，消息链被拆分为多次发送时（合并转发、文件与普通消息混排）返回最后一次发送的响应；WebChat 返回本地生成的 `message_id`（无平台侧响应，这是能拿到的最大信息量）；其余 15 个平台适配器本次未动，`send()` 仍返回 `None`，行为与之前完全一致。基类 `send()` 只记日志与累计已发送文本，始终返回 `None`，是否透传由适配器决定。

**纯增量改动**：框架内全部 `send()` 调用点都忽略返回值，老插件不受任何影响。

### 2. Context.get_all_commands()：插件查询已注册指令

插件此前只能通过 `context.get_all_stars()` 看到插件列表，拿不到指令层面信息：某个指令名是否已被占用、哪些指令处于启用状态、某条指令被指令管理重命名成了什么，都没有正规入口。现在 `context.get_all_commands(only_enabled=False)` 平铺返回全部指令描述符（含指令组与子指令），字段含生效名（`effective_command`，重命名后）、别名、描述、所属插件、权限要求与启停状态。

复用指令管理的 `CommandDescriptor`，不新造数据结构，并同步导出至 `astrbot.api.star` 供插件做类型标注。方法为同步函数：指令管理的启停/重命名/别名变更都会实时应用到运行时注册表，插件加载时也有兜底同步，因此纯读注册表即为权威状态，插件在任何时机都能直接调用。已禁用插件注册的指令在两种模式下都不返回。

## ✨ 体验优化（3项）

### 1. handler 产出裸字符串自动按纯文本发送

插件指令里回一句纯文本，此前必须写全 `yield event.plain_result("文本")`；直接 `yield "文本"` 会走 `call_handler` 的 else 分支被原样上抛、ProcessStage 忽略——**静默无效**，不报错也不发送，很容易踩。现在裸字符串视作纯文本结果，等价于 `event.plain_result(ret)`，`yield` 与 `return` 两条路径对称支持。

注意 handler 仍须是 `async def`（同步生成器本就不被支持，现状未变）。LLM 工具链路不受影响：工具 `return str` 进下一次请求 prompt 的既有语义走独立执行链路，不被本改动触及。空串与纯空白走 respond 阶段既有的空白链过滤，不会发出空消息。

### 2. @filter 注册器 priority 参数显式化

`@filter` 全家桶的签名此前全是 `**kwargs`，`priority` 完全靠「约定俗成往 kwargs 里塞」才能用——IDE 补全看不见、类型检查器报未知参数。现在 21 个注册器（指令族、过滤器族、全部 `on_*` 钩子族）签名加 `priority: int = 0` 并显式透传，docstring 补上说明：数值越大越先执行，默认为 0。

**纯增量**：原 `priority=N` 的 kwargs 写法继续有效，同名实参现在绑定到显式参数，行为一致；不传时默认 0，与之前缺省行为一致。`register_llm_tool` 与 `register_agent` 有意不加——它们的执行顺序不由 handler 注册表决定。

### 3. StarTools 文档与运行时报错中文化

`StarTools` 类与 10 个方法的英文 docstring 全部译为中文（正文中文、全角标点，保留 Google 风格的 `Args`/`Returns`/`Raises` 节名），7 类运行时错误消息一并中文化，如 `StarTools not initialized` → `StarTools 未初始化`、`Platform not found: x` → `找不到平台: x`。这与「注入 LLM 的提示词一律英文」的约定不冲突：StarTools 的 docstring 是给插件开发者看的 API 文档，不进提示词。
