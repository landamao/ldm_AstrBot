# [4.27.56] — 2026-10-30 — 新增事件收尾钩子 OnEventCompletedEvent

本版补上事件生命周期的最后一环。此前框架没有任何「事件处理完成」的钩子，而 `call_event_hook()` 的入口预检会让已终止的事件跳过全部后续钩子（含 `on_after_message_sent`），插件没有任何时机做收尾清理——典型症状是「处理中」的贴表情永远挂在消息上。现在 pipeline 结束时会统一派发 `on_event_completed`，**正常结束、被终止传播、pipeline 抛异常**三条路径都会执行；同时 `call_event_hook()` 新增 `allow_stopped` 参数，让收尾类钩子绕过终止预检。

## 🚀 新功能（1项）

### 1. 事件收尾钩子 on_event_completed

- 新增事件类型 `EventType.OnEventCompletedEvent` 与装饰器 `@filter.on_event_completed()`，在 `PipelineScheduler.execute()` 的 `finally` 中派发，覆盖正常结束、终止传播、pipeline 异常三条路径。
- `call_event_hook()` 新增关键字参数 `allow_stopped`：为 True 时跳过入口与逐处理器的终止预检、不做终止归因，也不会因某个处理器终止事件而中断后续派发；默认 False，既有钩子行为完全不变。
- 没有插件注册该钩子时完全不派发（派发前先查一次处理器表），不带来任何额外开销——避免每条消息多一次会话插件配置查询。
- 钩子内抛错只记日志，不影响 `cleanup_temporary_local_files()` 与 `active_event_registry.unregister()`；派发期间被取消时清理同样照常执行。
- 收尾钩子跑在回复阶段之后，此时 `event.get_result()` 已被清空，判断「有没有真正发出消息」请用 `event._has_send_oper`。

## 📌 升级说明

- 更新后重启生效；无新增/移除配置项，对既有插件零行为变更（未注册该钩子时不派发）。
- 插件侧用法：`@filter.on_event_completed()` → 先 `event.is_stopped()` 区分终止与正常结束，再按需清理（如撤回贴出去的表情）。旧版框架没有该装饰器，插件可用 `getattr(filter, "on_event_completed", None)` 做降级兼容。
- 配套插件「消息回应」v1.2 已用上该钩子：事件最终没发出任何回复时自动撤回贴出的表情。
- 详细变更见「详细变更日志/v4.27.56/」。
