# [4.27.61] — 2026-11-12 — 插件覆盖安装复用同一份包、插件页面两种打开方式、打包脚本不再误带 .env

本版包含三组改动：**插件覆盖安装复用同一份包**（确认框显示的版本就是实际装上的包，链接安装的完整下载从 3 次降到 1 次、上传安装从 2 次降到 1 次）；**WebUI 插件页面两种打开方式**（新标签页 / 仪表盘内嵌，共用一份偏好并持久化）；**更换插件源支持自定义 GitHub 仓库**（含分支名带斜杠的地址）；顺带修掉**源码打包脚本误带本机 `.env`** 的泄露隐患。

## 🚀 新功能

### 1. 插件页面「新标签页 / 页面内」两种打开方式

插件自带的 Web 页面不再只能跳新标签页：

- 每张插件页面卡片右上角置顶一个新标签页图标，下方并列「新标签页 / 页面内」两个按钮；头部提供默认打开方式的分段开关，切换即写入 localStorage（键 `astrbot.pluginPageOpenMode`，默认新标签页，未知值自动回落）。
- 「页面内」走新增的 `PluginPageEmbedded` 路由（挂在 `FullLayout` 下）：**侧边栏与顶部栏保留**，顶部多一条「返回 / 在新标签页打开」工具栏；内嵌模式不接管 `document.title` 与 favicon，不会把仪表盘标签页改名。
- 插件页面列表、插件卡片、插件详情页三处入口**共用同一份偏好**，在一处切换，其它入口立即跟随。
- `PluginPagePage.vue` 从近 700 行瘦身为薄包装，页面主体拆到 `plugin-page/PluginPageView.vue`，两种打开方式共用同一份渲染逻辑。
- tooltip 改为受控显隐（点击即收），避免路由跳转后 `mouseleave` 丢失导致提示框卡在屏幕上；卡片 hover 上浮 + 粉影、分段按钮 `scale` 恢复 Q 弹动画。

### 2. 更换插件源支持自定义 GitHub 仓库

- 更换插件源对话框新增「自定义仓库地址」输入，作为虚拟候选参与选中（不进入市场候选列表增删）；400ms 防抖调用 `/plugins/validate/repo` 做远端元数据预校验，结果只作提示、不阻止确认；插件本身没有可用仓库时直接展开输入框。
- 后端 `PluginSourceBindRequest` 新增 `repo`：`install_method` 为 `github` / `repo` 时用自定义地址覆盖插件原有仓库，必须解析成 GitHub HTTP(S) archive 仓库，否则提示「请输入有效的 GitHub 仓库链接。」；未填时仍用插件自带地址。
- 仓库地址解析放宽：分支名允许 `/`（`/tree/fix/xxx`）与 URL 编码 `%2F`，解析后还原为原始分支名，raw 文件与 archive 下载链接都能正确拼接。

## 🛠️ 重构与修复

### 3. 插件覆盖安装复用同一份包

覆盖安装是「先看版本 → 用户确认 → 再真装」两次请求，此前两次各自取包：

- 链接 / 直链 / git 安装为了读版本先完整下载一次、抛冲突后删掉，确认后再下载一次 —— 一次覆盖安装**完整下载 3 次，其中 2 次纯浪费**；上传安装则要在确认后**把同一个 zip 重传一遍**。
- 更要紧的是正确性：第二次按 URL 重新取包时远端 HEAD 可能已变，出现「确认框写 4.1.0、实际装上 4.2.0」，用户在不知情下批准了另一个包。

修复方式是**把确认时看到的那份字节本身留下来**：

- 新增 `astrbot/core/star/plugin_install_cache.py`：以包的 sha256 为 token 做内容寻址缓存（`temp/plugin-install-cache/<sha256>.zip`，目录 0700，24 小时 TTL、最多每 10 分钟清理一次）。`resolve_archive` 取包时**重算哈希**，文件被替换或损坏即丢弃并回退重新获取，因此「确认 → 安装」之间不存在换包窗口。
- `PluginUpdator` 冲突时先把待装包按来源（直链 / git clone / archive）抓到暂存目录，用 `inspect_plugin_archive` **直接读 zip 内 `metadata.yaml`** 拿版本（不解压整包），再存入缓存并把 token 挂到 `PluginAlreadyExistsError`；确认后 `install(cache_token=...)` 命中即本地解压，**不再联网**。取包或写缓存失败不阻断确认，退回旧行为。
- `star_manager` 成功与非冲突异常释放缓存，**冲突分支保留**（确认后还要用）；上传安装解压时保留压缩包，由 `release_archive` 统一回收。
- dashboard 三个安装入口全部透传 `cache_token`，上传接口 `file` 变**可选**（确认时只发 token）；token 失效**显式报错**而不静默换包。前端确认框带 `cacheToken`，取消 / 成功 / 关闭弹窗都清 token，避免「取消后再装」误用旧包。
- **效果**：链接安装完整下载 3 次 → 1 次；上传安装上传 2 次 → 1 次；且确认框显示的版本与实际安装的包必然一致。

### 4. 源码打包脚本误带本机 `.env` 修复

`打包源码.bat` 与 `复制源码.bat` 的复制列表写的是 `.env` 而非模板 `.env.example`：眼下会把本机的 `LDMBOT_DISABLE_UPDATE` / `DASHBOARD_PORT` / `NO_BANNER` / `SET_TITLE` 当作出厂默认值发给别人；更危险的是 `.env` 正是填 API Key、面板口令的地方，**一旦填了密钥，每次打包都会静默把密钥打进包里**。两处统一改为 `.env.example`；`runtime_bootstrap.py` 不依赖 `.env` 存在，`首次启动`不受影响。

## 📌 升级说明

- 本次为后端 + 前端混合改动：更新后需**重启**；WebUI 普通刷新即可。
- **行为变化**：
  - 插件覆盖确认的第二次请求只带 `cache_token`，不再重传压缩包/重新下载。若停在确认框太久（缓存 24 小时过期）或临时目录被清理，会明确提示「安装包缓存已失效」，按提示重新安装即可，不会静默装成另一个版本。
  - 插件页面默认仍是**新标签页**打开，老习惯不变；想留在仪表盘内请在插件页面头部或卡片上切到「页面内」。
  - 更换插件源现在允许自定义 GitHub 仓库地址，但只接受 GitHub HTTP(S) 仓库（不支持任意 Git 服务器）。
- 无数据库迁移、无配置迁移；清理临时目录只会让缓存失效，不影响已安装插件。
- 详细变更见「详细变更日志/v4.27.61/」。
