# [4.27.32] — 2026-09-18 — 上下文指令跨会话管理、压缩用量回执优化与文件下载修复

本版本让管理员无需切换聊天窗口，就能查看其他会话的 Agent 状态与用量，或压缩目标会话的上下文；同时优化压缩回执的数据来源与字段含义，并修复文件组件下载远程文件时的缺失导入问题。

## ⭐ 重点新增（1项）

### 1. `/status` 与 `/compact` 支持跨会话操作，群号、QQ号和名称均可定位

#### 背景

此前两个指令只能操作发出指令的当前会话。管理员检查某个群的上下文占用、查看运行状态或整理对话历史时，需要先切到目标会话，远程管理不够方便。

#### 核心改善

- `/status` 新增可选会话参数，用于查看目标会话的 Agent 运行状态、上下文占用及用量统计。
- `/compact` 新增可选会话参数，使用目标会话的配置、当前对话和压缩模型处理其历史，而不是误用指令发出位置的配置。
- 会话定位与 `/persona` 共用一套规则：支持完整会话 ID、会话 ID 段、群号、QQ号、昵称、群名，以及 WebChat 线程的 `!` 分段；名称采用精确匹配，不做模糊猜测。
- 简写命中多个会话时，列出候选及可用别称，要求进一步指定；无法定位时明确提示未找到会话。只剩别称、已无对话记录的条目不会被名称匹配重新选中。
- 跨会话操作需要机器人管理员权限；权限拒绝后不读取目标对话历史、用量统计或执行压缩。简写定位阶段仍会查询会话标识与别称。
- 正常状态回执与压缩完成回执显示完整会话 ID，便于确认操作对象；跨会话目标没有当前对话时给出对应提示。

#### 使用方式

以下号码和名称仅为格式示例，实际使用时请替换为已有会话：

- `/status 123456`：按群号或 QQ号查看状态。
- `/status 测试群`：按群名或昵称查看状态。
- `/status webchat!user1!thread-9`：按 WebChat 线程标识定位。
- `/compact 测试群 3`：压缩目标会话，并保留最近 3 轮原文。
- `/compact 测试群 yes 3`：同上；未找到可用摘要模型时，允许按原有机制回退到轮次截断。

不传会话参数时仍操作当前会话。`yes`、保留轮数、会话参数的顺序不限；同类参数重复或无法识别时会返回使用方法。完整会话 ID 指的是「平台ID:消息类型:会话号」，不是对话 UUID。

#### 数字参数注意事项

`/compact` 的数字可能表示会话号，也可能表示保留轮数：数字精确命中已知会话时按会话处理，未命中时按轮数处理。参数中已经指定昵称、群名或完整 ID 等非数字目标时，其余数字只作为轮数。

因此，仅输入一个不存在的数字会话号，不一定得到「未找到会话」提示，也可能被理解为当前会话的保留轮数。跨会话压缩时优先使用明确的名称或完整会话 ID；同号多平台时使用完整 ID 消除歧义。

## ✨ 体验优化（1项）

### 1. `/compact` 回执优先使用模型用量，区分摘要输出与完整上下文估算

#### 背景

原回执统一显示本地估算占用，未利用已有请求统计和摘要模型返回的用量。同时，摘要请求的输出 token 数并不等于压缩后完整历史的占用，两种口径需要明确区分。

#### 核心改善

- LLM 摘要模式下，「压缩前占用」优先使用该对话最近一条正数上下文统计，标注「模型返回」；缺失或读取失败时使用本地估算，标注「估算」。
- 摘要模型返回正数输出用量时显示「摘要输出」，不再将它包装成压缩后完整历史的占用。
- 未取得正数摘要输出用量时，显示「压缩后占用」并明确标注「估算」；它与「摘要输出」不会同时出现。
- 回执保留压缩方式、目标会话 ID 与前后轮数，按字段分行展示。轮次截断模式显示压缩后估算，不显示 LLM 摘要模式专属的压缩前字段。

#### 数据口径与限制

「压缩前占用」的模型数据来自历史请求快照，并非本次压缩前重新向模型测量。重置、删除历史或连续压缩后，该记录可能不再等于当前历史的实际占用。

「摘要输出」是摘要请求的 API 输出用量，不能与压缩前占用直接计算完整上下文的压缩率。缺少模型数据时仍可能展示估算，但不会把估算标成模型返回。

## 🛠️ 问题修复（1项）

### 1. 修复文件组件下载远程文件时因缺失导入而报错

#### 问题现象

文件组件下载远程文件时会读取文件自动下载大小限制，但旧代码调用了未导入的函数，执行到该路径时会出现 `NameError`，导致文件下载无法继续。

#### 核心改善

补齐下载限制函数的导入，使文件下载能够按已有配置取得大小限制并调用下载逻辑。本次不改变限制数值、配置方式或下载策略。
