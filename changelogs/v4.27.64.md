# [4.27.64] — 2026-11-25 — 群聊上下文群黑白名单、适配器连上平台钩子、指令组 self_handle、QQ 语音解码崩溃修复

本版是三处框架能力扩展加一处高频崩溃修复：**群聊上下文增强支持群黑白名单**（不必再为个别群关掉整个功能）；插件新增 **`on_platform_connected` 钩子**，在适配器真正连上平台时才触发，可以放心调 API；指令组新增 **`self_handle`**，纯组名可以交给组函数自己处理，不再被框架锁死成一段指令树。修复项是 **QQ NT 语音因尾部 `FF FF` 结束标记导致 SILK 解码必然崩溃**，顺带堵住了单条语音失败连带打挂整条消息的路径。

## 🚀 新功能

### 1. 群聊上下文增强支持群黑白名单

- 新增配置 `provider_ltm_settings.group_icl_group_list`，默认空表示不限制群，**行为与升级前完全一致**。
- 规则与「自动理解图片」的群黑白名单一致：写群号为白名单、`/` 开头为黑名单、`all` / `*` 为全部；群号与会话 ID（UMO）任一命中即通过。
- 未通过的群不记录消息、不注入历史，也**不消费**已积累的缓冲 —— 临时移出白名单再改回来，之前的上下文还在。
- 顺带修掉 `all + /群号` 组合下白名单通配符绕过黑名单的老问题，图片转述同步受益。
- WebUI 配置项「群聊黑白名单」位于「最大消息数量」下方，说明中写明黑名单群不启用上下文增强、自动理解图片也一并不生效。

### 2. 新增 `on_platform_connected`：适配器真正连上平台才触发

- `@filter.on_platform_loaded` 只保证**适配器实例加载完成**，此时 OneBot 反向 WS 可能还没建连、账号还没登录。新钩子在连接真正建立后触发，参数为 `platform` 与 `self_id`。
- 支持 `platform_name=` 限定具体适配器；单个钩子抛错只记日志，不影响其它钩子与连接流程；断开重连会再次触发。
- 触发时 API 连接已登记，钩子里可以直接 `platform.get_client().call_action(...)`（如拉好友/群列表、设置群昵称、预热缓存）。
- `Platform` 新增 `is_connected` / `connected_self_id`，`get_stats()` 输出多一个 `connected` 字段；目前 aiocqhttp 已完整接入，其它适配器可用基类默认值或自行调用 `notify_connected()`。

### 3. 指令组新增 `self_handle`：纯组名交给组函数处理

- 此前只发组名（如 `/ccb`）会被 `CommandGroupFilter` 无条件拦下并回一段固定指令树，组 handler 被排除在激活列表外，函数体是死代码。
- 新增 `@filter.command_group("x", self_handle=True)`：显式开启后纯组名激活组 handler 本身；默认 `False` 保持旧行为。带子指令时 `equals` 为 `False`，不会与子指令重复执行。
- 典型用法：`/ccb` 空参时由组函数自己发用法说明，`/ccb xxx` 仍按原子指令或 `*` 兜底处理。

## 🛠️ 修复

### 4. 修复 QQ 语音尾部结束标记导致的 SILK 解码崩溃

- QQ NT 语音在帧流末尾带 `FF FF` 结束标记，`pysilk` 把它当成帧长 `-1`，`BytesIO.read(-1)` 读走整段剩余数据，SDK 返回 `-11`（`DEC_PAYLOAD_TOO_LARGE`，实为长度字段为负），**整条语音必然解不出来**。
- 解码前按帧清洗：只放行 `0 < len <= 1024` 且数据完整的帧；一帧都解不出时在前 64 字节内滑动重同步；整体解码失败退化为逐帧解码，坏帧填 20ms 静音，单帧损坏不再连坐整段音频。
- 定位方式由「只剥开头 `0x02`」改为查找 `#!SILK_V3` 魔数，头部有多余字节也能恢复。
- 预处理阶段主消息与引用链两处语音处理合并为统一 `try/except`：单条语音失败只跳过该条，不再把同一条消息里的文本、图片一起打挂。

## 📌 升级说明

- 更新后需**重启**生效；WebUI 普通刷新即可。
- 无数据库迁移；群黑白名单为新增配置项，留空即沿用旧行为。
- 若旧配置里写过 `all + /群号`，此前黑名单实际失效，修复后该群会被真正排除 —— 属预期行为，请复查配置。
- `on_platform_connected` 为纯新增事件，未使用的插件不受影响；`self_handle` 默认关闭，既有指令组行为不变。
- 详细变更见「详细变更日志/v4.27.64/」。
