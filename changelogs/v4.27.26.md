# [4.27.26] — 2026-09-10 — 提示词注入规范化与插件指令文案统一

本版本聚焦两项内部质量改善：对话上下文中所有非用户内容统一用 `<system_reminder>` 包裹并去除行为引导，避免框架文案劫持人格；插件管理聊天指令与 WebUI 后端日志的插件名引用格式统一为「」括住，关键操作回执新增版本信息。各变更的完整细节见项目「详细变更日志/v4.27.26/」目录。

## ✨ 新增

### 提示词注入规范化：system_reminder 包裹 + 去除行为引导

#### 背景

审查发现两类问题：

1. **注入不可区分**：大量「非用户内容」直接以 user 文本或 `[SYSTEM NOTICE]` 形式混进上下文，模型无法区分「用户说的」和「系统补的」，人格扮演容易被带偏。最典型的是空 @ 唤醒：一整段中文直接当作 user prompt，且写满了行为引导。
2. **引导污染人格**：注入文案里大量操作/输出/思考/语气引导（「友好地询问」「符合人设」「只输出回复内容」「Prioritize…」「Continue the conversation…」「Stop calling tools…」等），与用户配置的人格 prompt 冲突，导致角色扮演机械化、口吻被框架劫持。

#### 核心改善

确立两条设计原则并全链路落地：

1. 非 user 内容一律用 `<system_reminder>` 标签包裹，与用户发言可区分；
2. 系统注入只陈述事实（「发生了什么」），不引导操作/输出/思考/语气——怎么回由人格与主 system prompt 决定。

覆盖范围：

- **空 @ 唤醒**：整段中文行为引导 → `@昵称` + `<system_reminder>用户艾特了你，但并未输入任何内容</system_reminder>`；昵称优先取 At 组件 name，缺失回退 get_self_id()
- **打断/停止提示**：去掉 `Continue the conversation based on the content already sent above.`，只保留事实句并包裹 system_reminder
- **Agent 循环注入**（8 组模板）：`USER_INTERRUPTION_MESSAGE` / `FOLLOW_UP_NOTICE_TEMPLATE` / `MAX_STEPS_REACHED_PROMPT` / `REPEATED_TOOL_NOTICE` 三级 / `TOOL_RESULT_OVERFLOW_NOTICE` / `SKILLS_LIKE_REQUERY` 等全部去引导、改 system_reminder 包裹
- **Cron/后台任务唤醒**：删除整段 `# IMPORTANT RULES`（Do NOT greet、Explain WHY、MUST use send_message 等），改为 system_reminder + 唤醒来源 + 任务 JSON
- **对话内内容块**：KB 检索结果、WebChat 侧栏选段、引用消息、图片转述、附件路径、工作区路径、Computer Use 未启用提示——全部改 system_reminder + 纯事实
- **系统级能力说明**：沙箱模式、本地模式（OS + Shell 类型）、网搜引用格式、工具调用规范——去引导只留机制事实
- **Skills 加载说明**：去掉 When to trigger / Never silently skip / Announce which skill 等行为规则，只保留技能清单 + 路径 + 读取方式

#### 使用方式

此项为内部改善，无需用户配置。改完后人格扮演更自然，系统注入不再与人格 prompt 冲突。安全模式、人格定义、标题生成等独立小模型调用刻意未改。

## 🎨 体验优化

### 插件指令回复与插件管理日志文案统一

#### 背景

聊天侧 `/plugin` 指令组的回复文案中，插件名引用格式混乱（空格与「」混用），且 `/plugin get`、`/plugin update` 的成功回复不带版本信息；WebUI 插件管理后端日志同样存在插件名格式不统一的问题。

#### 核心改善

**聊天指令（/plugin）**：

- 插件名一律用「」括住：启用「xxx」已启用、禁用「xxx」已禁用、重启「xxx」已重启、重启失败文案同步统一
- `/plugin get` 安装成功新增版本：`安装插件「xxx」成功，版本 1.2.3。`（版本从安装后注册表读取；元数据缺失时显示「未知」或省略版本段）
- `/plugin update` 更新成功新增旧→新版本：`插件「xxx」更新成功，版本 1.2.3 → 1.3.0`（旧版本在更新前捕获，新版本在 reload 完成后重新读取）

**WebUI 插件管理后端**：

- 19 处日志/返回消息的插件名（或仓库地址、上传文件名）统一加「」括住，涵盖安装、卸载、更新、重载、批量更新、GitHub 加速等场景

#### 使用方式

聊天侧实测：`/plugin on|off|restart <插件名>` 查看回复是否为「」格式；`/plugin get <仓库>`、`/plugin update <插件名>` 查看版本显示。WebUI 日志在插件管理操作时查看。
