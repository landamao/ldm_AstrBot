# [4.27.60] — 2026-11-10 — 异常接入重要通知、壁纸流式取图、重试预算统一、空唤醒水位切片

本版包含八组改动：**异常统一进通知中心**（插件 handler / 事件钩子 / 模型调用 / 管道未捕获 / 插件载入全部接入，带群号与调用栈，通知可删可清空已读）；**壁纸远程取图流式代理**（服务端代取 + 令牌复用，背景/预览/下载终于同一张，手机默认同图、电脑默认直连）；**模型请求重试预算统一**（关掉 SDK 隐式重试、去掉硬编码 10 次与空输出 5 次，配置填 1 就真的只请求一次）；**群聊空唤醒水位切片**（唤醒后新到的消息不再被当成历史重复注入）；**空唤醒提示词注入开关**（装补艾特插件时可关掉框架那句英文提示）；**非纯文本回复历史落库修复**（TTS 换语音后整轮不再失忆）；**WebUI 自定义 Logo 换图不刷新修复 + 壁纸透明度滑块恢复（默认 80%）**；**FAISS 文档库生成列迁移幂等修复**（启动不再刷 duplicate column 告警）。

## 🚀 新功能

### 1. 插件 / 钩子 / 模型 / 管道异常接入重要通知

此前的通知中心只有「上下文压缩失败」一个来源，而真正需要被看见的插件报错只躺在日志里。本版把五类异常全部接进来：

- **插件 handler 抛错** → `plugin_error:{插件}`；**事件钩子抛错**（`on_llm_request` / `on_decorating_result` 等，此前被 `except BaseException` 静默吞掉）→ `plugin_hook_error:{插件}`；**内部 Agent / LLM 与第三方 runner 失败** → `agent_error:{runner}:{模型}`；**管道未捕获异常** → `pipeline_uncaught:{异常类型}`；**插件载入失败** → `plugin_load_error:{插件}`。
- 详情统一含时间、平台、群号、发送者、会话标识（umo）、插件与处理函数、异常类型与信息、调用栈，超长中间截断（详情 4000 字 / 调用栈 2800 字）。
- 同 key 未读通知聚合：`count + 1` 并刷新标题与详情（此前只刷详情，插件换了报错位置标题仍停在旧内容）。
- 管道异常用 `create_task` 写库不阻塞调度，任务句柄集中收集、shutdown 时 `gather`，避免退出时通知丢失；写库失败只记日志，绝不影响业务主流程。
- `help` 指令里的通知详情由整段调用栈压成**单行 160 字摘要**，完整内容引导到 WebUI 查看。
- 通知中心 UI：长详情默认折叠 6 行 + 展开/收起 + 复制，操作按钮与「标记已读」并到同一行 footer，面板加宽至 560px、字号整体上调。

### 2. 通知删除

- `POST /notifications/delete`：传 `ids` 删指定条目（不论已读），传 `clear_read=true` 只清已读、保留未读，返回实际删除条数。
- 前端每条通知加删除按钮，面板头部提供「清空已读」。

### 3. 壁纸远程取图：流式代理 + 令牌

随机壁纸 API 每次请求换图，浏览器又因 canvas 污染无法跨域取字节，导致「设置页看到的 / 页面背景 / 点下载得到的」是三张不同的图。新增 `GET /api/v1/ui-preferences/wallpaper/proxy?url=&t=`：

- 带令牌 `t`：命中缓存直接返回字节（`immutable`，URL 含唯一令牌故可长缓存）；未命中则**边收边转发**（`StreamingResponse`），浏览器边下边画，不再等整张图下完；读完把字节钉在令牌上。
- 令牌缓存 LRU：最多 8 张 / 48MB / 6 小时。
- 不带 `t`：一次性收完再返回，兼容旧调用。
- 健壮性：仅允许 http(s)、单张 32MB 上限（超限只透传不进缓存）、UA 伪装、**按文件头嗅探真实类型**（很多图源返回 `octet-stream` 甚至 `text/html`）、共享 `httpx.AsyncClient` 复用连接与 TLS、尊重环境变量代理。

### 4. 壁纸「直连 / 服务端」二选一

- 背景、设置页预览、下载**共用同一份解析后地址（同令牌）**，天然同一张；「换一张」= 换令牌。
- 新增偏好 `wallpaperUseProxy`（localStorage，按浏览器保存）；**默认按设备**：手机走服务端（保证同图）、电脑走直连（更快）。
- 直连模式预览区不重复拉图（随机图源 `no-store`，再拉必是另一张），一次浏览只发一次请求；该模式的「换一张」靠 `_n=令牌` 一次性参数生效。
- 保存壁纸时把旧令牌认领到新版本号，避免「保存完背景立刻换图」。
- 不做 IndexedDB 持久缓存：随机壁纸的玩法就是刷新换一张。

### 5. 空唤醒提示词注入开关

新增 `platform_settings.bare_wake_prompt.enable`（默认 `true`）。配合「补回艾特自身」插件时，框架注入的 `system_reminder` 与插件的 `@你自己` 重复，可关闭：

- 关时不写 `message_str`，`_bare_wake` 标记保持不变（群聊上下文仍全量注入，空唤醒能接上历史）；
- 请求不立即放行，继续走管线到 `on_waiting_llm_request` 钩子，**钩子结束后**复查：插件补出内容则正常请求，仍为空才跳过，不会把空消息发给模型。
- 配置保存后重建管线即时生效，无需重启。

## 🛠️ 重构与修复

### 6. 群聊空唤醒水位切片

- 根因：v4.27.43 的空唤醒兜底用「LLM 请求时刻」的缓冲快照当历史，而插件在 `on_llm_request` 里等待（消息补获默认等 6 秒）会把窗口撑开，**唤醒之后新到的消息被当历史注入**，同一张图一轮出现两次、整轮 token 翻倍。
- 修复：`GroupChatContext` 新增与 `raw_records` 平行的单调序号 `_record_seq`（裁剪不影响比较，下标方案会错位），`Main.on_message` 在**消息阶段**打水位 `_group_context_wake_seq`。
- `on_req_llm` 切点重排为四条优先级：落位 record_id > 空唤醒水位 `bisect_right` > 无水位全量（旧兜底）> 旧 `prompt_idx` 兜底；**水位之后的记录不再 `clear()`**，留在缓冲给下一轮。

### 7. 非纯文本回复的历史落库修复

- 根因：`completion_text` 是派生属性（等于 `result_chain.get_plain_text()`）。插件把结果链换成只含语音 `Record` 的链后，`completion_text` 必然为空，`_save_to_history` 据此判定「空响应」并丢弃整轮 —— 表现为「转一次语音之后上下文断片」。
- 修复：空响应判定补 `has_non_text_reply`（链里存在任何非 `Plain` 组件即视为本轮有回复），图片 / 文件 / @ 等被插件替换的回复同享此修复；`result_chain` 真为空时行为不变，不制造空轮次。
- 附带修掉一个测试污染：`test_context_usage_snapshot.py` 会走真实 `db_helper` 往生产库写「上下文压缩失败」通知，已 stub 掉。

### 8. 模型请求重试预算统一（填 1 就真的只请求一次）

- 根因是四层重试各记各的账：① OpenAI / Anthropic SDK 默认 `max_retries=2`（一次尝试最多 3 个 HTTP 请求，完全不受配置控制）；② `text_chat` / `text_chat_stream` 外层恢复循环硬编码 10 次；③ 空输出重试内置 3 次、仅思考输出 5 次且不读配置；④ 图片转述 / 上下文压缩 / 插件调用 / 标题生成等调用点没传参，退回常量 5。最坏叠加 **5 × 3 × 2 个模型 = 30 个请求**。
- 修复：新增 `resolve_request_max_retries`（显式值优先，否则读全局配置，读不到才退 5）并让 `_build_retrying` 统一走入口；三个 SDK 客户端全部 `max_retries=0`，重试权唯一交给 `retry_provider_request`（继承 OpenAI 源的 groq/longcat/openrouter/xai/xiaomi/aihubmix/ssycloud/openai_responses 一并覆盖）；去掉硬编码 10；空输出 / 仅思考重试取 `min(内置上限, 预算)`。
- 语义变化：`request_max_retries` 现在是**单次逻辑请求的总尝试次数（含首次）**，全链路统一。失败日志由「重试 N 次仍然失败」改为「共尝试 N 次仍失败」。

### 9. WebUI 自定义 Logo 换图不刷新 + 壁纸透明度恢复

- Logo 不刷新根因：`<img src>` 按完整 URL 缓存，远端换图但 URL 没变 → 永远命中旧缓存；清空再填同一个链接缓存键也一样。修复：新增 `buildLogoSrc` / `buildWallpaperSrc` 破缓存地址 —— 本站上传只附 `?v=`，普通外链附 `?v=&t=`（页面会话令牌，刷新页面即换），**带普通 query 的外链照常 `&` 续接**（QQ 头像直链这类首版被误判为签名链接，已修正），只有含 `X-Amz-Signature` / `OSSAccessKeyId` / `Signature` 等签名参数的地址原样返回。
- 设置页每次保存写 `version: Date.now()`，favicon 与全部 Logo 展示点统一走新地址。
- 壁纸透明度滑块恢复（0-100，默认 80，100 = 完全不透明），后端 `normalize_wallpaper` 恢复 `opacity` 规范化，旧配置里的 `opacity` 字段重新被读取。
- `logoHasChanges` / `wallpaperHasChanges` 忽略 `version` 比较，避免「未保存改动」提示常亮。

### 10. FAISS 文档库生成列迁移幂等

- 根因：`PRAGMA table_info` **不返回生成列**，`kb_doc_id` / `user_id` 是 `GENERATED ALWAYS AS (json_extract(...))` 虚拟列，判断恒为「缺失」，每次启动都 ALTER 并报 `duplicate column name`。
- 修复：改用 `PRAGMA table_xinfo`；新增列由 `STORED` 改 `VIRTUAL`（各版本 SQLite 都支持 ALTER 添加，同样可建索引）；逐列 `try/except` 忽略多实例并发的重复列报错；异常日志措辞改为「初始化 documents 生成列/索引失败」。

### 11. 附带

`AstrBotMessage.raw_message` 类型标注由 `object` 改为 `Any`（纯标注，无运行时变化）。

## 📌 升级说明

- 更新后需**重启**生效（通知埋点、壁纸服务、重试预算、`normalize_*` 均为后端改动）；前端普通刷新即可。
- **行为变化**：
  - `request_max_retries` 现在是含首次的总尝试次数，填 1 就真的只发一次。**预算 1 会连带关掉需要「再发一次」的降级路径**（图片被拒剥图重发、不支持工具剥工具重发、上下文超长裁剪重发、429 换 Key），要保留这些能力请用 2（也是默认值）。
  - 壁纸在电脑端默认改走浏览器直连（更快），此时「下载当前壁纸」可能与背景不是同一张 —— 需要严格一致请在设置页切到「服务端（同图）」；手机端默认已是同图模式。
  - 通知中心会开始出现插件异常通知，同 key 聚合累加次数，不会无限新增。
- 无数据库迁移、无配置迁移；`bare_wake_prompt.enable` 与壁纸 `opacity` 由启动时配置完整性检查与默认值自动补齐，存量用户零手工处理。
- 详细变更见「详细变更日志/v4.27.60/」。
