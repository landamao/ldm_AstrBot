# [4.27.30] — 2026-09-14 — data 目录自定义路径全面跟随：插件导入、CLI 与日志路径修正

本版本为 1 项重要修复：`LDMBOT_DATA_DIR` / `--data-dir` 自定义 data 目录从「部分跟随」升级为「全面跟随」，彻底解决自定义目录下插件加载失败、CLI 与主程序数据目录不同步、日志标签误判三类问题。

## 🛠️ 问题修复（1项）

### 1. 自定义 data 目录下插件静默加载失败 / CLI 路径不同步 / 日志标签误判（3 类症状同根因）

设置 `LDMBOT_DATA_DIR`（或启动参数 `--data-dir`）把 data 目录指向自定义位置后，此前存在三类不一致：

**症状一：插件加载报 ModuleNotFoundError，或静默加载了默认目录的同名插件**

- 插件物理目录已正确解析到自定义目录，但模块导入仍按逻辑包名 `data.plugins.*` 到源码树默认 `data/plugins` 里找——自定义目录下的插件报「模块不存在」；若两边恰好都有同名插件，会不加提示地加载默认目录那份，自定义目录里的改动完全不生效。
- 修复：启动时向 Python 导入系统注入命名空间包映射，把逻辑包名 `data` / `data.plugins` 指向实际 data 目录与插件目录。逻辑模块名不变，已持久化的插件模块路径（数据库、共享偏好）继续有效，无需任何数据迁移；真实存在的包不会被覆盖，路径一致时幂等复用。
- 三处调用点兜底：主程序启动即注入、插件加载前兜底注入、CLI 启动路径同步注入。

**症状二：`astrbot plug` / `conf` / `init` 等 CLI 命令仍读写当前目录下的 `data/`**

- CLI 命令各自把 data 目录写死为「项目根/data」，与主程序实际使用的自定义目录不同步：在 CLI 里装的插件、改的配置可能落到另一个目录。
- 修复：CLI 新增统一的数据目录解析入口，按「`LDMBOT_DATA_DIR` → `LDMBOT_ROOT/data` → 当前目录/data」的优先级解析，与主程序行为一致；`plug`（插件管理）、`conf`（配置）、`init`（初始化）、`run`（运行）四个命令全部接入。未显式配置时默认 `LDMBOT_ROOT` 为项目根，默认目录行为不变。
- `run` 命令不再无条件覆盖已设置的 `LDMBOT_DATA_DIR` / `LDMBOT_ROOT` 环境变量，并在启动日志中输出实际使用的 data 目录。

**症状三：自定义目录下的插件日志标签显示 `[Core]` 而非 `[Plug]`**

- 日志组件按路径里是否包含字面量 `data/plugins` 判断插件文件，自定义目录名（如 `data_xxx/plugins`）永远匹配不上，插件日志全部被打成核心日志。
- 修复：改为与实际插件目录（及内置插件目录）做真实路径前缀对照，兼容 Windows 路径大小写；对照失败时退回原有宽松匹配兜底。自定义目录下的插件日志现在正确显示 `[Plug]` 标签。

### 关联修复

- WebUI 产物解压默认路径：从「当前工作目录下的 data」改为跟随实际 data 目录解析，消除依赖启动位置导致的解压位置漂移。
- 桌面版（frozen）应用重启时，除 `--webui-dir` 外一并保留 `--data-dir` 启动参数（环境变量本可被子进程继承，CLI 参数此前会丢失）。

## 📌 升级说明

- 默认 data 目录（未设置任何自定义路径）的行为完全不变。
- 仅当使用 `LDMBOT_DATA_DIR` / `--data-dir` / `LDMBOT_ROOT` 指向非源码树 `data/` 时，路径解析发生变化：插件导入、CLI 读写、日志标签全面跟随自定义目录。
- 无配置项变更、无存量数据迁移；已持久化的插件模块路径继续有效。
- 需重启 ldm 生效（导入映射在启动期完成）。
- CLI（`astrbot plug` / `conf` / `init`）在自定义 data 目录下使用时，需与主程序使用相同的环境变量 / `.env`，否则仍按当前目录下 `data` 解析。
