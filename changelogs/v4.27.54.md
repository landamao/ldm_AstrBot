# [4.27.54] — 2026-10-23 — 移动网络与 Android proot 稳定性修复（DNS 重试、QQ 官方重连、重启兜底）

本版针对移动网络 DNS 抖动和 Android proot 环境下的启动/重启失败做稳定性加固，正常环境行为不变。

## 🐛 修复（3项）

### 1. DNS 偶发 `EAI_AGAIN` 导致连接卡死或刷屏

- `runtime_bootstrap.py` 启动时全局接管 `socket.getaddrinfo`：遇到 `EAI_AGAIN`（Temporary failure in name resolution）短重试 3 次（0.4s / 0.8s / 1.2s），成功结果缓存 60 秒；域名不存在等永久错误原样抛出。
- 缓存超过 512 条时清空、超过 256 条时清理过期项，避免长期运行内存无限增长。
- 只改变 DNS 解析失败的重试与缓存策略，不影响连接超时等其他网络行为。

### 2. QQ 官方机器人初始连接失败不再直接停摆

- `qqofficial_platform_adapter.py` 的 `run()` 改为带退避的重试循环：初始登录、获取 WebSocket 地址遇到 DNS 抖动、连接失败或超时时，按 5 秒起、翻倍至最长 60 秒的间隔重试；主动停止（`is_shutting_down`）或非网络错误仍然抛出。
- `ManagedBotWebSocket.on_error` 对临时网络错误只输出一行 warning，并保持原有“重新入队 session”的重连逻辑，不再打印整段 traceback。
- 鉴权失败等永久错误的行为保持不变。

### 3. Android proot 下重启与状态读取失败

- `process_restart.py` 读取进程信息时捕获 `RuntimeError` / `OSError`（proot 的 `/proc/stat` 可能缺少 `btime`），记录 warning 后跳过子进程清理，不再阻断后续 `os.execv` 重启。
- `runtime_bootstrap.py` 新增 `install_psutil_boot_time_fallback()`：`psutil.boot_time()` 读取失败时用 `/proc/uptime` 反推启动时间；非 Linux 平台自动跳过。

## 📌 升级说明

- 更新后重启生效。
- DNS 重试次数（3 次）与缓存时长（60 秒）为内置策略，无需额外配置。
- 仅影响网络抖动和 Android proot 场景，正常桌面/服务器环境行为不变。
