# [4.27.49] — 2026-10-17 — 模型列表报错修复、中文 API Key 透传、回退告警归因修正

本版本是三笔修复：获取模型列表失败时看到的 `not all arguments converted during string formatting` 是日志占位符笔误炸掉真实错误；含中文的 API Key 保存正常却在发请求时以一条隐晦的编码错误崩溃，现已全程透传；多级回退连续失败时切换告警把每一次失败都挂到主模型名下，现已逐条正确归因。

## 🐛 修复（2项）

### 1. 获取模型列表失败时的报错恢复为真实原因

获取模型列表失败时，此前 WebUI 与日志里看到的是 `not all arguments converted during string formatting`——openai/anthropic/gemini 三个 provider 源的 `get_models()` 异常分支误用了 loguru 风格 `{}` 占位符，而 `astrbot` 的 logger 是标准库 logging（`%s` 风格），logging 自身先抛了格式化错误，把连接拒绝、401 等真实原因整个顶掉。三处占位符已改为 `%s`，报错恢复为「获取模型列表失败：{真实原因}」。详见[详细日志](../详细变更日志/v4.27.49/变更日志-2026-10-17-模型列表失败日志格式化崩溃修复.md)。

### 2. 主模型回退切换告警逐条正确归因

多级回退（主模型 + 多个回退对话模型）连续失败时，切换告警此前永远写「主模型请求失败」——日志取的是已被切换覆盖的当前 provider，第一次切换后原模型 ID 就丢了。现改为从上一候选直接取失败方 ID 并按位次标注角色（主模型 / 回退对话模型），每次失败各归其位。详见[详细日志](../详细变更日志/v4.27.49/变更日志-2026-10-17-回退切换告警归因修正.md)。

## ✨ 新增（1项）

### 1. 中文 API Key 透传支持

含中文（任意非 ASCII 字符）的 API Key 此前保存正常但发请求必炸 `UnicodeEncodeError: 'ascii' codec can't encode...`——httpx 要求头值为 ASCII。现非 ASCII 密钥自动按 UTF-8 编码成 bytes 进 HTTP 头原样上线，openai（含 9 个继承子类）、anthropic、gemini、生图四通道全程可用，`/provider` 指令切换 key 亦同步支持；ASCII 密钥路径一行未动。详见[详细日志](../详细变更日志/v4.27.49/变更日志-2026-10-17-中文APIKey透传支持.md)。
