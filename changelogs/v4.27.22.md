# [4.27.22] — 2026-09-05 — 修复对话失忆、静默无回复与更新误删源码，新增限流忽略空消息

本版本聚焦稳定性修复，一次性解决 3 个会影响对话体验的顽固问题：长对话被误压缩导致「失忆」、达到步数上限后静默无回复并残留坏消息、「更新ldm」误删本地 WebUI 源码；同时新增「限流忽略空消息」开关，避免平台状态消息刷满限流拖住正常回复。

## 🛠️ 问题修复

### 长对话低占用却误触发压缩（「失忆」）

多轮工具调用 + 带上下文缓存（prompt cache）的模型（如 DeepSeek）场景下，界面显示占用仅约 7% 却提前触发压缩，把 9.7 万真实上下文压成 1.9 万，导致聊过的硬信息「搜不到、答不出、甚至乱编」。根因是压缩判断误用了包含缓存命中与输出的计费值（token_usage.total），该值巨大且被完全信任、替代了对真实消息的逐条估算。

现改为「上下文占用快照」机制：压缩前用快照的 prompt_tokens 加新增尾部消息估算，且仅当同一 provider、工具集未变、当前消息是快照的严格前缀扩展时才信任快照；任一条件不符一律退回逐条估算。真实占用远低于阈值线，不再被误压。

### 达到步数上限后静默无回复并残留坏消息

Agent 达到步数上限（max_step）后，框架移除全部工具并强制收尾；若此时模型仍「幻觉」输出工具调用，之前会静默不产生任何最终回复（用户只看到卡住的「调用工具」状态），并把一条协议非法的残缺消息持久化进对话历史，之后每一轮都报 400 错误。

现三重防护：拦截幻觉工具调用并按普通回复正常收尾（纯幻觉无文本时补一句「工具调用次数已达上限，未能生成最终回复」保证有可见回复）；组装结果前按工具调用 id 配对补齐缺失结果；落库前丢弃悬空的工具调用消息，并顺带清理已中毒的存量会话。

### 「更新ldm」不再清空本地 dashboard 源码

此前「更新ldm」会把本地 `dashboard/` 整目录当普通目录清空再覆盖，而更新包只含构建产物（dist），导致本地 WebUI 源码（src、工程文件等）一次性全丢。现 dashboard 与 data、.venv、.git 等一样列为受保护项，更新时整目录跳过；dist 的替换仍只作用于实际生效的 WebUI 目录。WebUI 更新按钮、上传压缩包、命令行 update 三个入口一并生效。

## ⭐ 重点新增

### 限流忽略空消息

新增配置 `platform_settings.rate_limit.ignore_empty_message`（默认开启）。NapCat（QQ）等平台会把「正在输入」等状态作为内容为空的消息事件短时间大量推送；此前这类空消息与正常消息一样参与限流计数，很快刷满限流拖住正常回复。开启后空消息直接放行——不计数、不 stall；空格等有字符的文本与含 At/图片等组件的消息仍按正常消息计数。WebUI 配置页新增「空消息不计入限流」开关。

## 📌 升级说明

- 本版本含前端构建产物（配置页新开关），更新后请手动重启 ldm；如浏览器仍显示旧界面，请执行 Ctrl+F5 强制刷新。
- 「空消息不计入限流」默认开启，如需恢复旧行为可在配置页关闭。
