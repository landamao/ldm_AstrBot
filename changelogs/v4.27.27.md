# [4.27.27] — 2026-09-12 — 人格批量管理与导入增强、.env 示例模板解析修复

本版本包含两项改动：WebUI 人格管理页新增多选批量操作，人格导入支持同名冲突处理与结果汇总；修复 .env 示例模板取消注释后说明文字被解析进变量值的问题。

## ✨ 新增

### WebUI 人格管理：多选批量操作

人格页面新增「多选」模式，支持批量导出与批量删除。

- 点击「多选」进入选择模式，人格卡片显示勾选框，实时显示已选数量。
- 支持全选 / 取消全选（作用于当前文件夹内的人格）。
- **导出选中**：将选中人格打包导出为一个 JSON 文件，包含系统提示词、预设对话、工具与 Skills 选择、自定义报错回复，文件名带时间戳。导出前需确认。
- **删除选中**：批量删除选中人格，删除前二次确认并提示不可撤销；部分删除失败时会明确提示失败数量。

### WebUI 人格导入：同名冲突处理与结果汇总

人格导入功能完善同名冲突场景的处理，并给出完整结果反馈。

- 导入前自动检测与现有人格的名称冲突：单个冲突时弹窗询问「覆盖该人格 / 重命名导入」；多个冲突时询问「全部覆盖 / 全部跳过」。
- 选择覆盖时按文件内容更新系统提示词、预设对话、工具与 Skills、自定义报错回复；文件中缺失的字段保持原样不误清空。
- 选择重命名导入时自动追加 `_imported` 后缀（重名时继续加序号），确保不覆盖任何现有人格。
- 兼容单对象、数组、标准导出格式（含 `personas` 数组）三种文件形态。
- 导入完成后汇总提示新增 / 覆盖 / 跳过 / 失败数量。
- 导出与导入均已包含自定义报错回复字段，跨实例迁移人格配置不再丢失该设置。

## 🛠️ 问题修复

### .env 示例模板：说明文字不再被解析进变量值

#### 问题现象

.env 示例模板此前将说明文字直接写在变量行尾（`# 变量=值  说明文字`）。用户去掉行首 `# ` 启用变量后，说明文字不属于注释，会被 dotenv 一并解析为变量值的一部分，导致实际生效值被污染（如密码变量带上整段说明）。

#### 修复方案

示例模板的说明文字现在以行内注释形式书写（`# 变量=值  # 说明文字`），取消行首注释启用变量后，说明仍是合法的行内注释，被 dotenv 正确忽略。变量值保持纯净。

#### 说明

- 已生成的旧 .env 文件不会被自动改写，如曾填过实际值可检查行尾是否带入了说明文字；重新启用某个变量时建议参照新模板格式。
