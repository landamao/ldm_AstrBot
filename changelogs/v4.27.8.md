# [4.27.8] — 2026-08-25 — /reset 清群聊上下文、流式输出日志优化、WebChat 流式开关体验改进

本次更新包含 2 项修复、2 项体验优化、1 项版本信息获取日志修复。

### 修复

- **/reset 指令未清除群聊上下文增强的历史消息**
  - 问题：使用 /reset 指令后，LLM 对话历史已清空，但群聊上下文增强的内存历史（raw_records）和数据库消息历史（platform_message_history）仍然保留，导致 AI 仍能看到之前的群聊上下文
  - 根因：/reset 只调用了 `conversation_manager.update_conversation()` 清空 LLM 对话历史，未处理群聊上下文增强的两层数据
  - 修复：/reset 时设置 `_clean_group_context_session` 标记（after_message_sent 钩子清内存 raw_records），同时调用 `delete_all` 清除数据库 platform_message_history 记录

- **流式输出时日志显示「发送消息 (空)」**
  - 问题：WebChat 流式输出完成后，日志中出现一条 `发送消息 - xxx/xxx: (空)`，因为流式输出结束后基类收到空消息链
  - 根因：`send()` 方法对空消息链也打日志，流式输出路径最终传入空链
  - 修复：空消息链跳过日志；流式输出完成后，如果 `send()` 未打过日志（如 WebChat），则统一打一条 `发送消息 - 流式输出` 日志

- **框架版本信息获取重复打印日志 + GitHub API 成功无日志**
  - 问题一：用户从镜像服务器切换到 GitHub 时，前端同时发起 checkUpdate 和 getReleases 两个请求，后端并发调用 `fetch_release_info` 导致重复拉取并打印多条「获取到 N 个版本」日志
  - 根因一：两个并发请求同时进入 `fetch_release_info`，缓存来不及被第一个请求填充，第二个也走了网络拉取
  - 修复一：给 `fetch_release_info` 加 `asyncio.Lock`，串行化并发请求；拿到锁后先查缓存，命中则直接返回
  - 问题二：GitHub REST API 主路径成功获取版本列表后没有打印成功日志，而镜像、Atom 回退、git ls-remote 回退都有
  - 修复二：GitHub REST API 成功后补打 `GitHub API 获取到 N 个版本` 日志

### 体验优化

- **WebChat 的 /flow 指令改为提示去页面设置**
  - 问题：WebChat 平台的流式输出由前端 `enableStreaming` 直接控制，/flow 指令写入的会话级覆盖对 WebChat 不生效，但指令不会给出任何提示
  - 优化：/flow 指令检测到 WebChat 平台时，回复提示「WebChat 的流式输出开关可在当前页面的设置里实时切换，无需使用指令」

- **WebUI Chat 侧边栏设置菜单新增流式输出开关**
  - 问题：流式输出开关仅在输入框 +号菜单中，用户通常去设置菜单找开关却找不到
  - 优化：在 Chat 页面侧边栏底部的设置菜单中新增流式输出开关项，与深色/浅色模式、面板透明度并列，点击即可切换

### 说明

- 更新后请**手动重启**一次服务
- 若面板显示异常，可用顶栏「强制刷新面板」或浏览器 Ctrl+F5
- 建议验证：群聊中使用 /reset 后确认 AI 不再引用之前的上下文；WebChat 流式输出开关在设置菜单和输入框 +号菜单均可切换
